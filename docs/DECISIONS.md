# 결정과 프로토타입 가정

## 현재 사용자 지시

- HTML 기반, Three.js로 3차원 지도 표현. 최종 함선은 2D 그림의 윤곽에 두께를 주는 방식을 검토 중이며 아직 구현하지 않음.
- 기본 플레이 화면은 태양계 기반 모항성계이며, v0.4부터 같은 뷰어에 임의 항성계 데이터를 주입할 수 있음.
- 행성은 천천히 공전. 선택하지 않은 궤도는 희미하게, 선택한 천체의 궤도는 선명하게 표시.
- 행성·위성·소행성대와 입체적인 위치 관계를 관찰할 수 있어야 함.
- 새 지시가 초기 인계서보다 이번 작업 범위를 좁힘. 탐사·건설까지 한 번에 구현하지 않음.

## 구현 방식

1. 프레임워크·번들러 없는 정적 ES 모듈. 실행·수정이 간단하고 게임 상태와 렌더링 책임을 파일로 분리할 수 있음.
2. Three.js 0.170.0과 OrbitControls를 저장소에 포함. 런타임 CDN 모듈 의존성을 없애고 버전 고정. 폰트는 실패해도 동작하는 선택적 외부 자원.
3. 모바일 가로 화면을 기준으로 최소 HUD와 천체 옆 정보 탭을 배치. 과거 상시 목록·관측 패널은 v0.4 지시에 따라 교체. 세로 화면도 기본 조작은 가능하나 우선 대상은 가로 화면.
4. v0.3 사용자 지시가 과거 실제 AU/동적 크기 결정을 대체. 최신 거리 조정에 따라 1 게임 AU = 140/53 월드 단위로 렌더링하며 실제 km와 환산하지 않음. 이전 1:1 렌더링만 대체하고 AU 표기·시뮬레이션 궤도 값은 보존.
5. 게임 장반경은 수성 53, 금성 79, 지구 100, 화성 142, 목성 280, 토성 420, 천왕성 570, 해왕성 730. 모두 중심 간 거리. JPL의 시간에 따른 장반경이 이 값을 덮어쓰지 않음.
6. Planet Size = round(15 × sqrt(realRadiusKm / 6371)). 고정 월드 표시 지름으로 사용. 지구는 15, 가스 거인의 큰 Size는 지상 건설 가능성이나 건설 수량을 의미하지 않음.
7. 태양은 G2V·G형 주계열성·광도계급 V·5,772 K·실제 반지름 696,340 km·1 R☉를 유지. Star Size 90 × (70/90) = 월드 표시 지름 70. 거리 환산으로 표현하면 26.5 게임 AU이며, 표면 메시의 크기는 이전과 같음. 항성 분광 계열·광도계급과 변환 프로필을 구분.
8. 위성은 Planet Size와 다른 고정 지름 규칙 및 개별 게임 궤도 사용. 달 기준 월드 표시 지름 0.8과 최소 위성 월드 지름 0.3는 이번 프로토타입 조정값. 모든 위성은 모행성·고리·형제 위성과 최소 1 AU 여유.
9. 행성 시스템 전체의 보수적 방사상 포락선까지 최소 1 AU 간격 검증. 지구 100과 모든 Planet Size 및 초기 행성 궤도표를 수정하지 않고 통과.
10. NASA/JPL 원본 수치 파일은 보존. `referenceElementsAt/OrbitPosition/WorldPosition`은 현실 천문 참고 좌표, 기존 이름의 계산 함수는 게임 좌표. 오른손 황도 기저 `(x,z,-y)`와 IAU 로컬 축 자전은 유지.
11. 동적 반지름 확대 제거. 작은 천체만 화면 좌표 보조 선택, 가려진 천체는 제외. 불투명 메시 실제 선택을 우선하며 보조 선택은 화면 거리·깊이를 사용.
12. 카메라 전체·내행성·표면·위성 추적 범위를 게임 크기에 맞춤. 기본/전체보기 최소 거리는 태양 반지름 밖으로 제한. 표시 눈금은 게임 AU만 사용.
13. 실제 지도, 구름, 토성 고리와 라이선스 유지. 브라우저 정적 실행 방식 유지. 이번 변경은 별도 브랜치와 PR로 제출하고 main 병합은 사용자 승인 후 수행.
14. 거리 추가 조정: 태양–수성의 AU 수치를 140으로 바꾸지 않음. 53 AU를 유지한 채 렌더링 장반경을 기존 목성–토성 장반경 차이 140 월드 단위로 확장. 행성·위성·소천체 영역·카메라 거리에 같은 환산을 사용하고 크기 메시에는 적용하지 않음. 충돌/여유 검사와 AU 눈금은 월드 반지름을 게임 AU로 역환산해 계산.

## v0.4 공용 UI·육각 섹터 결정

최신 [통합 지시서](v0.4/REQUEST_KO.md)가 이번 패치의 범위를 정함. 기준 커밋은 검증된 v0.3 `6bfd7d8`이며 선행 PR #1이 미병합이므로 새 PR은 v0.3 작업 브랜치를 대상으로 함. 사용자 승인 전 main 병합 없음.

1. 태양계 어댑터와 공용 `createSystemContext()`를 분리. 뷰어·패널·카메라는 활성 컨텍스트만 사용. 태양계 ID별 텍스처·구름·고리 정보는 어댑터에 한정.
2. 기본 화면은 최소 HUD. 시점·천체 찾기·축·라벨·궤도는 숨겨진 설정에 배치. 천체 단일 선택은 확대하지 않으며 정보 탭의 확대 버튼으로만 접근. 과거 더블클릭/F 접근은 새 입력 흐름으로 교체.
3. DOM 정보 탭은 매 프레임 투영 위치를 따라가고 좌우 뒤집기·클램프·정수 픽셀 배치. 화면 밖·구체 뒤에서는 숨기되 선택 유지. 작은 가로 화면에서는 내부 스크롤로 버튼 접근 보장.
4. 공통 육각 반경 210 게임 AU를 초기 프로토타입 값으로 채택. **중심→꼭짓점 = 변 길이**. 항성계별 크기 조정 없이 최소 정수 링 수만 자동 계산. 210은 최종 밸런스 확정값을 의미하지 않음.
5. 범위는 원일점·크기·위성·고리·소천체 외곽·명시적 범위·원점 오프셋을 보수적으로 합하고 10% 여유 적용. 격자 실제 외부 경계의 모든 선분까지의 최소 거리로 원형 범위 포함 검증. 최외곽 중심만 비교하지 않음.
6. 경계 동률은 안쪽 링, q 오름차순, r 오름차순. ID는 `systemId:q:r`. 외곽 확장은 기존 ID·좌표·중심·반경을 유지하며 축소하지 않음. 프레임마다 재생성하지 않음.
7. 평면 원점·법선·접선은 데이터. 3D 위치를 직교 투영하여 소속 섹터를 조회하며 실제 위치·고도를 수정하지 않음. 천체의 현재 섹터와 섹터 내 천체 목록은 현재 시각으로 조회.
8. 입력 우선순위는 DOM UI → 실제 천체 메시 → 작은 천체 보조 선택 → 섹터 → 해제. 드래그·다중 터치와 거의 평행한 레이는 클릭으로 처리하지 않음. 근접 시 섹터 표현만 희미해지고 논리 좌표는 유지.
9. 공통 경계선은 하나의 LineSegments로 배치하고 중앙·호버·선택 강조만 별도. 선택마다 격자 재생성 없음. 전환 시 이전 컨텍스트 이벤트·Geometry·Material·광채 Texture·라벨을 정리하고 기존 renderer를 재사용.
10. 개발용 작은 K형 시험계와 이동·경사진 다중 항성 시험계를 추가. `?dev=1`에서만 선택 UI 공개. 실제 천문 자료·정식 플레이 콘텐츠가 아니며 쌍성 역학은 구현하지 않음.
11. v0.3의 140/53 AU 환산·거리표·Size·실제 자료·궤도/자전 수식은 보존. `model.js`는 컨텍스트 선택/강조를 위한 map 주입만 확장. 태양계 초기 설정 검증은 Sol 어댑터에서 유지하고, 보조 기준 평면도 임의 평면으로 변환하여 설정에서 사용. 기존 자동 테스트를 삭제하지 않음.

자료와 구체적 근사 한계는 [SOURCES.md](SOURCES.md)에 기록.

## 이후 구현할 이동 구상 — 이번 빌드에는 없음

- 함선은 천체·소행성·지점을 목적지로 이동하며, 도중에 정지하고 새 명령을 받을 수 있음.
- 출발 행성이 목적지를 가리면 행성 표면 방향의 이동점을 생성하고 그 지점 상공으로 돌아 나옴. LOS 확보 후 행성 간 이동으로 전환.
- 항성계 항로의 다른 행성·항성이 경로를 막으면 플레이어가 자동 우회 버튼 또는 수동 경유점을 선택.
- 행성 화면의 표면 클릭을 해당 방향 상공 이동과 연결하는 방향. 고도·감속·도착 조건 등 상세 수치는 추후 결정.
- 입체 공간을 이용한 채굴·거점·물류 입지는 후속 설계 대상.

## 아직 결정하지 않은 것

함선 미술 방식, 이동·충돌 모델, 실제 궤도 운동 적용 정도, 영구 저장, 건설 UI, 싱글/멀티플레이의 최종 범위는 이 지도 프로토타입으로 확정하지 않음.

## v0.5A 행정구역과 시간 제어

- [최신 지시서](v0.5/REQUEST_KO.md)에 따라 v0.4 `b303764`에서 새 브랜치/후속 PR을 생성. GitHub main 병합 없이 기존 Sites 접근 범위를 유지하여 실행 링크와 HTML ZIP 제공.
- 기초 육각 크기 210 AU·좌표·ID는 불변. 행정구역은 시스템별 기초 섹터 ID 집합. 미지정 허용, 공유 변 연결 필수, 구멍 허용, 연결이 끊기는 제거는 원자적으로 거부. 통합 시 대상 ID/이름/색 유지. ID는 단조 일련번호이며 실행 취소 후에도 재사용하지 않음.
- 행정구 내부선 0.028, 미지정 경계 0.17, 외곽 0.55, 선택 외곽 0.85, 구역 면 0.075의 초기 알파. 중복 변 없는 배치 레이어를 편집 시만 갱신. 카메라 근접 페이드와 임의 평면을 유지.
- 편집에 명시적으로 진입했을 때만 셀이 천체보다 우선. 정상 보기에서는 기존 천체 우선 순서. 적용 전 선택은 미리보기이고 드래그/다중 터치는 편집하지 않음. 실행 취소 최대 20개를 시스템별로 보유.
- `currentSectorId`와 현재 위치의 행정구 조회는 공간적 조회. 미래 `administrativeRegionId`는 행성/거점의 고정 소속으로 별개이며 공전으로 자동 변경하지 않음. 현재 행성 고정 소속·경제 재고를 생성하지 않음. 미래 구역 재고는 행성/창고 집계로 제공하며 복제 보유하지 않음.
- `space-project:administration:v1`에 schemaVersion 1 JSON 저장. 알 수 없는 버전은 덮어쓰지 않고 편집 차단. 잘못된 시스템 상태는 해당 시스템만 격리. 명시적 복구 시 원본 전체를 `:backup` 키에 보존. 저장 실패는 현재 탭 편집만 유지하고 알림.
- UI 1× = 현실 1초당 게임 10초. 전술 0.1/0.25/0.5/0.75/1×, 전략 1/2/5/10/50/100×. requestedSpeed·effectiveSpeed·speedCap·paused 분리. cap은 요청을 보존하고 해제 시 요청 배속으로 복원. 위험 감지는 구현하지 않으며, 미래 위험 진입의 기본 0.1× 정책은 후속 컨트롤러 계약.
- 전경의 정상 프레임 지연은 전부 시계에 누적하고, 렌더 전환 보간만 0.1초로 제한. 숨김 전환마다 기준 시각을 갱신하여 복귀 시 숨김 시간을 적용하지 않음. visibility 이벤트 없이 60초 이상 멈춘 간격은 시스템 대기로 간주하여 진행을 건너뛰고 알림. 일시정지/배속 변경은 기존 정책으로 경과 시간을 먼저 반영. 날짜·시각은 UTC.
- 시계/배속은 저장하지 않고 새로고침 시 1×로 시작. 미래의 1 POP=100만 명, 오프라인 UI 1.25×(현실 12.5배), 최대 게임 60일, 위험 중 종료/이벤트 시점 정지 규칙은 문서만 유지. 현재 오프라인 진행·생산·보상·위험 트리거 없음.

항성계 보기 전환은 세계 시계의 days를 되감지 않습니다. 월드 UTC epoch를 고정하고 선택 네임스페이스만 바꿉니다. v0.4의 전환 시 days=0 기대값은 이번 단일 세계 시계 계약에 맞게 수정했으며 해당 테스트를 유지했습니다.
