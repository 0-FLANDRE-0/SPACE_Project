# SPACE_Project — 범용 항성계 게임 UI 및 고정 크기 육각 섹터 기반 구현 지시서

- **문서 종류:** Codex 작업 지시서 (기존 2개 지시서 통합·충돌 제거본)
- **대상 저장소:** `0-FLANDRE-0/SPACE_Project`
- **기준:** v0.3 게임 AU / Planet Size / Star Size 프로토타입
- **권장 목표 버전:** v0.4 (가칭)
- **작업명:** Universal Star System Game UI & Fixed-Size Hex Sector Foundation
- **우선 적용 규칙:** **모든 항성계에서 육각형 한 칸의 크기는 동일하다. 항성계 범위가 넓을수록 육각형 링과 총 개수가 늘어난다.**

> 이 문서는 기존의 「범용 항성계 게임 UI 및 육각형 섹터 시스템 구현 지시서」와 「육각 섹터 고정 크기 및 가변 확장 규칙 수정」을 합친 **단일 기준 문서**다. 이전 지시서의 ‘항성계마다 육각형 크기 변경’, ‘모든 항성계 37개 고정’ 조건은 **폐기**한다.

## 0. 목표와 작업 경계

현재의 천체 관측 프로그램 스타일 UI를, 이후 탐사·개척·건설·함선 운용에 재사용할 수 있는 **게임형 항성계 지도**로 재구성한다. 이번 단계의 산출물은 다음 세 가지다.

1. **공용 항성계 뷰어:** 태양계뿐 아니라 임의의 항성계 데이터를 주입해 같은 카메라·선택·렌더링 기능을 사용한다.
2. **게임형 맥락 UI:** 화면을 가득 차지하는 상시 관측 패널 대신, 천체를 선택하면 천체 옆에 작은 정보 탭이 뜨고 그 탭의 `확대` 버튼으로 카메라가 이동한다.
3. **고정 크기 육각 섹터:** 같은 게임 AU 크기의 정육각형을 항성계 중심에서 링 단위로 확장한다. 각 항성계는 필요한 링 수만 생성한다.

이번 단계에서 자원·시설·함선·전투·연구·성간 이동은 구현하지 않는다. **공용 공간·상호작용 기반부터 만들고, 실제 게임 루프는 후속 단계에 추가**한다.

**기존 v0.3을 유지해야 할 사항**

- Three.js 기반 3D 천체·공전·위성 추적·자전·텍스처.
- 게임 AU와 월드 좌표 환산, Planet Size / Star Size, 고정 월드 지름.
- 천체 선택 보조, 가림 판정, 궤도 강조, 카메라 회전·줌·전환, 시간 일시정지·배속.
- 기존 실제 천문학 참고 데이터와 게임 좌표의 분리.
- PC 및 모바일 가로 화면 조작, 기존 검증 가능한 기능.

기존 UI를 **제거**한다는 뜻은 과학 관측용 상시 인터페이스를 **교체**한다는 뜻이다. 그 UI가 사용하던 엔진 기능이나 데이터를 삭제하라는 뜻이 아니다.

## 2. 모든 항성계에서 공통으로 작동할 데이터 구조

### 2.1 활성 항성계 컨텍스트

범용 시스템은 `ActiveSystemContext` 또는 동등한 구조로 현재 항성계를 제공받아야 한다. 추천 개념 필드는 다음과 같다.

```js
{
  systemId: 'sol',
  displayName: '태양계',
  systemCenterGameAU: { x: 0, y: 0, z: 0 },
  sectorPlane: {
    originGameAU: { x: 0, y: 0, z: 0 },
    normal: { x: 0, y: 1, z: 0 },
    tangentU: { x: 1, y: 0, z: 0 }
  },
  stars: [],
  planets: [],
  moons: [],
  belts: [],
  managedExtentGameAU: null // 미지정 시 데이터의 최대 궤도·영역으로 산출
}
```

이는 **인터페이스 예시**이지 필드명을 무조건 그대로 사용하라는 명령은 아니다. 기존 구조에 자연스럽게 연결하되 의미를 보존한다.

- 항성계 식별자는 천체·섹터 ID에 반드시 포함하거나 상위 범위로 보장한다.
- 모든 천체는 유형(`kind`), 고유 ID, 명칭, 현재 위치 또는 위치 계산을 위한 궤도 정보 등을 가진다.
- 태양계에서만 통하는 천체 ID·행성 수·거리값을 공용 UI·섹터 함수에 하드코딩하지 않는다.
- 소천체 영역이 없거나 위성이 없는 항성계도 정상 지원한다.
- 단일 항성계의 중심은 중심 항성에 둘 수 있지만, 쌍성계 등을 위해 **항성계 중심/섹터 원점이 반드시 첫 번째 항성 위치일 필요는 없게** 만든다.
- 실제 쌍성의 복잡한 공전 계산은 이번 범위에 없다. 다중 항성·비중앙 원점 자료가 들어와도 공용 UI/섹터 로직이 무너지지 않게 하면 된다.

### 2.2 태양계 어댑터

현재 `SUN`, `PLANETS`, `MOONS`, `BELTS` 배열은 첫 번째 항성계인 `sol` 데이터로 묶어 전달한다. `SystemViewer`는 가능한 한 `SystemViewer(container, systemContext, ...)` 또는 유사한 형태로 **항성계 데이터를 주입받도록** 수정한다.

천체 렌더링, 화면 투영, 카메라 전체보기, 정보 패널은 주입받은 항성계만 참조해야 한다. 태양계 전용 표기는 `sol`의 데이터/설명에만 존재하도록 한다.

### 2.3 항성계의 전환·재생성

후속 구현에서 다른 항성계로 전환할 때 이전 항성계의 선택, 추적 대상, 팝업, 섹터 호버 및 렌더링 자원 등이 남지 않도록 수명주기를 정리한다.

이번 단계에서는 최소한 **태양계와 시험 항성계의 전환/재생성 테스트**로 이 계약을 검증한다.

## 3. 관측 UI를 게임형 HUD로 개편

### 3.1 기본 화면

상시 천체 목록 사이드바, 커다란 우측 관측 정보 패널, 과도한 천문 수치/디버그 표시를 기본 화면에서 제거하거나 교체한다.

기본 화면은 3D 우주가 대부분을 차지하고, 필요한 최소 HUD만 남긴다.

- 일시정지·재개, 시간 배속
- 현재 항성계 전체보기/복귀
- 필요할 경우 작은 확대·축소 조작
- 육각 섹터 표시/숨김 토글
- 선택이 있을 때만 나타나는 맥락형 정보 패널
- 설정 또는 개발용 디버그 기능은 작게 분리하거나 기본 숨김

전술용 UI, 자원·건설 메뉴, 탐사 메뉴는 기능이 실제로 구현될 때 추가한다. **미구현 버튼을 작동하는 것처럼 표시하지 않는다.**

### 3.2 천체 클릭 흐름

1. 3D 천체 메시 또는 기존 화면 선택 보조로 대상을 선택한다.
2. 선택 링/하이라이트 및 필요한 공전 궤도 강조를 표시한다.
3. 해당 천체의 화면상 위치 근처에 **소형 정보 탭**을 띄운다.
4. 탭에 `확대`, `닫기`를 제공한다.
5. **천체를 한 번 선택하는 행위 자체는 자동 확대를 일으키지 않는다.**
6. `확대`를 누르면 기존 카메라 전환 함수를 통해 천체로 부드럽게 이동한다.
7. 다른 천체 선택 시 패널을 새 대상으로 갱신하고, 빈 공간 클릭·닫기 버튼·해제 조작 시 닫는다.

기존 선택 우선순위(실제 메시 → 작은 천체 보조 선택)를 유지한다. 같은 지점을 클릭했을 때 뒤쪽 섹터가 천체를 가로채면 안 된다.

### 3.3 정보 탭 내용

**행성 예시**

```
[지구]
암석형 행성
Planet Size 15
궤도 장반경 100 게임 AU
[확대] [닫기]
```

**항성 예시**

```
[Sol]
G2V · G형 주계열성
Star Size 90
[확대] [닫기]
```

위성·소천체 영역 등은 공용 `kind`별 데이터 렌더러로 구성한다. 없는 필드는 생략하고, 실제 천문학 참고 상세 수치가 필요하다면 별도의 선택적 상세보기/개발용 모드에 배치한다. 태양계 천체명이나 개수를 공용 템플릿에 직접 넣지 않는다.

### 3.4 패널 위치·모바일 대응

- 선택 대상 3D 위치를 카메라로 화면 투영해 패널을 배치한다.
- 천체에 가까이 붙이되 천체를 과도하게 가리지 않는다.
- 화면 가장자리에서는 자동으로 좌/우 또는 위/아래 위치를 바꿔 **클리핑을 방지**한다.
- 카메라 이동·천체 공전 시 대상 위치를 부드럽게 따라가고 떨림을 최소화한다.
- 대상이 시야 밖으로 나가거나 다른 천체에 가려지면 패널의 표시/숨김 정책을 일관되게 처리한다.
- PC 마우스와 모바일 가로 터치 모두 버튼을 누르기 쉬워야 한다.
- 패널이 뜬 상태에서 드래그·휠·핀치 조작과 충돌하지 않아야 한다.

권장 구조는 Three.js 화면 위 DOM 오버레이이며, 반드시 3D 메시로 UI를 만들 필요는 없다.

### 3.5 카메라

확대·근접보기는 천체의 데이터와 `kind`에 따른 크기·범위로 결정한다. 항성계 전체보기 거리는 **해당 항성계의 관리 범위**를 기준으로 산출한다. 태양계 전용 카메라 상수나 행성 8개를 전제로 한 계산을 공용 로직에 두지 않는다.

기존 회전·이동·줌·시간 흐름·궤도 추적은 보존한다. 섹터 UI 추가 때문에 카메라가 임의로 중앙을 향하거나 플레이어 조작을 덮어써선 안 된다.

## 4. 고정 크기 육각 섹터 — 절대 핵심 규칙

### 4.1 섹터는 공용 게임 AU 단위의 고정된 공간 구획

**육각형 한 칸의 크기는 모든 항성계에서 동일하다.** 항성계가 커졌다고 각 칸을 넓히거나 줄이지 않는다.

- 섹터 크기를 `HEX_SECTOR_RADIUS_GAME_AU` 등 **전역 공통 설정 하나**로 정의한다.
- 이 값은 정육각형 중심부터 꼭짓점까지의 길이(육각형 변 길이와 같음)인지, 내접원 반지름인지 **명확히 문서화**한다. 권장: 중심→꼭짓점 반경.
- 모든 항성계에서 동일한 `HEX_SECTOR_RADIUS_GAME_AU`를 사용한다.
- 항성계별로 달라지는 것은 섹터 `ringCount`와 `sectorCount`뿐이다.
- 논리적 계산은 게임 AU에서 수행하고 렌더링할 때만 `gameAUToWorld()`를 사용한다.
- 게임 AU 환산계수를 섹터마다 별도로 설정하지 않는다.

섹터는 물리적 벽이 아니며 함선/천체의 3차원 이동과 충돌 판정을 제한하지 않는다.

### 4.2 중심 섹터와 링 확장

항성계의 `sectorPlane.originGameAU`에 중심 육각형 `(q=0, r=0)`을 놓는다. 태양계에서는 Sol 주변이지만, 다른 항성계는 별도 중심을 사용할 수 있다.

육각형은 중심에서 육각 링 단위로 바깥으로 확장한다.

| 최대 링 수 R | 총 섹터 수 `1 + 3R(R+1)` | 중심축 한 줄의 칸 수 |
|---:|---:|---:|
| 0 | 1 | 1 |
| 1 | 7 | 3 |
| 2 | 19 | 5 |
| 3 | 37 | 7 |
| 4 | 61 | 9 |
| 5 | 91 | 11 |

- 위 표는 **가능한 규모의 예시**다. 모든 항성계를 37칸으로 고정하지 않는다.
- **태양계는 초기 조정 기준으로 중심축 한 줄 약 7칸(3링/37개)을 목표**로 한다.
- 태양계보다 작은 시스템은 적은 링, 더 큰 시스템은 많은 링을 생성한다.
- 링 수를 늘리더라도 기존 칸의 크기·위치·ID는 바뀌지 않아야 한다.

### 4.3 공통 섹터 크기 초기 캘리브레이션

태양계의 카이퍼대 외곽 등 **현재 게임용 관리 범위**를 참조해서 모든 항성계가 공통으로 쓸 육각형 크기의 **초기값을 한 번 정한다.**

초기 목표: 태양계의 전체 관리 범위를 약 3링, 즉 중심을 지나는 7칸으로 덮는다. 태양계의 소천체 외곽이 게임 AU로 약 900이라면, 10% 수준의 여유를 포함한 약 990 게임 AU 반경을 3링 군집으로 덮는 식으로 검증한다.

**공통 육각 반경 210 게임 AU**를 초기 실험 후보로 써볼 수 있다(중심→꼭짓점 반경, 아직 확정 밸런스 아님). 단, 최종값은 실제 정육각 격자 기하와 항성계 외곽 전 방향을 대상으로 검증한 뒤 결정한다. 정확한 값이 조정되더라도 **전역 상수 하나만** 조정하고, 개별 항성계는 그 값을 그대로 사용해야 한다.

중요: 초기값을 정할 때 태양계 데이터를 참고하는 것은 허용되지만, 런타임 섹터 생성 코드에 `neptune`, `kuiper-belt`, `sol` 등 이름을 조건으로 박아 넣는 것은 금지한다.

### 4.4 필요한 링 수 자동 계산

모든 항성계는 공통 육각형 크기를 사용한 상태에서, 자신의 관리 범위 전체를 덮는 **최소 정수 링 수**를 계산한다.

관리 범위 산정은 다음을 사용한다.

- 모든 행성의 **원일점**과 해당 행성의 크기
- 위성계의 최외곽 궤도(필요한 경우 고리 포함)
- 소행성대·카이퍼대와 같은 소천체 영역의 외곽
- 항성계 데이터에 명시된 추가적인 관리 범위(있다면)
- 설정 가능한 외곽 여유(초기 제안 약 10%)

천체의 한 순간 위치만으로 항성계 규모를 계산하지 않는다. 앞으로 공전해도 섹터 밖으로 벗어나지 않도록 궤도 포락선을 기준으로 한다.

육각형 링 집합은 원형이 아니다. **최외곽 섹터 중심의 반지름만으로 충분하다고 판단하지 않는다.** 관리 범위 원/다각형을 모든 방향에서 실제 생성된 육각형들이 덮는지 수치적으로 검증한다. 필요 링 수를 증가시키되 **섹터 한 칸의 크기는 절대 변경하지 않는다.**

외곽 신규 천체의 발견 등으로 관리 범위가 넓어지면 바깥 링을 추가할 수 있다. 이때 기존 섹터를 다시 맞춰 놓거나 리사이즈하면 안 된다.

### 4.5 축 좌표·섹터 ID

Axial Coordinates `(q,r)`를 사용하고 필요한 경우 cube 좌표로 변환/반올림해 2D 점→섹터를 판별한다.

중심에서의 링 거리는 다음 규칙을 사용한다.

```js
hexRing = Math.max(Math.abs(q), Math.abs(r), Math.abs(q + r));
```

ID는 `systemId + q + r`을 조합해 **항성계 간에 겹치지 않게** 만든다.

예시: `sol:0:0`, `sol:1:-1`, `alpha-centauri:0:0`.

같은 게임 AU 좌표가 들어오면 항상 같은 칸을 반환하도록 결정적(deterministic)으로 구현한다. 경계선 위 반올림의 동률은 명시적인 우선순위로 결정한다.

### 4.6 항성계 기준 평면과 3차원 위치 투영

육각형은 **항성계 로컬 기준 평면**에 생성하고, 원점·법선·방향을 포함하는 변환으로 월드 공간에 배치한다.

- 태양계는 기존 황도 기준면을 쓸 수 있다.
- 다른 항성계가 월드의 다른 위치에 있거나 기준 평면이 기울어져도 동작해야 한다.
- 모든 항성계의 섹터가 월드 `Y=0`에 있다고 하드코딩하면 안 된다.
- 3D 천체/함선의 섹터는 **해당 위치를 항성계 기준 평면에 직교 투영한 2D 위치**로 조회한다.
- 투영은 섹터 관리용일 뿐 천체/함선의 실제 고도 및 3D 위치를 변경하지 않는다.

### 4.7 생성·조회 인터페이스

세부 함수명은 코드 구조에 맞추되 다음 기능을 제공한다.

```js
createHexGrid(systemContext, globalHexRadiusGameAU);
findMinimalRingCount(systemExtent, globalHexRadiusGameAU);
worldPositionToSector(systemContext, positionWorld);
gamePositionToSector(systemContext, positionGameAU);
sectorCoordsToCenter(systemContext, q, r);
getSectorNeighbors(systemContext, q, r);
```

항성계 컨텍스트/기하 조회 기능은 Three.js나 DOM에 의존하지 않는 순수 함수로 테스트할 수 있어야 한다.

### 4.8 고정 섹터와 이동 천체의 관계

섹터는 세계에서 **고정된 구획**이다. 행성은 공전하고 함선은 이동하므로, 천체의 현재 소속 섹터는 시간에 따라 바뀔 수 있다.

천체의 섹터를 게임 시작 시점에 한 번 기록하여 영원히 고정하지 않는다. 현재 게임 위치를 투영해 필요 시 조회한다. 나중에 저장할 탐사 상태·자원·시설은 해당 섹터의 **불변 ID**에 연결할 수 있도록 한다.

## 5. 섹터 평면의 시각화 및 상호작용

### 5.1 표시 방법

- 항성계 기준 평면 위에 아주 희미한 **정육각형 경계선**을 표시한다.
- 기본은 어두운 청회색 계열의 낮은 불투명도. 천체·궤도·함선을 가리지 않는다.
- 중심 섹터·호버 섹터·선택 섹터는 구분 가능한 강조를 사용한다.
- 육각형 경계가 위성·행성 텍스처 위로 억지로 떠보이지 않도록 깊이/렌더 순서를 관리한다.
- 지도 줌이 천체 근접 수준으로 들어가면 경계선 투명도를 낮추거나 화면에서 숨길 수 있지만, 논리적 섹터 계산은 계속 작동한다.

### 5.2 표시 토글 및 중심→외곽 연출

작은 HUD 버튼으로 섹터 오버레이를 표시/숨김할 수 있게 한다. 숨기더라도 ID/좌표 조회는 계속 유효해야 한다.

선택적으로 **중심 섹터 → 1링 → 2링 → ...** 순서의 짧은 표시 연출을 허용한다. 연출은 그래픽 효과일 뿐 섹터 데이터 자체의 생성/존재 여부나 게임 상태를 바꾸지 않는다. `prefers-reduced-motion` 또는 성능 상황에서는 생략 가능하다.

### 5.3 섹터 호버 및 클릭

- 섹터 평면의 **천체가 아닌 빈 공간**을 클릭하면 해당 섹터를 선택할 수 있다.
- 화면 포인터에서 섹터 평면으로 레이를 쏘아 교점을 계산하고, 항성계 로컬 2D 좌표로 바꾼 뒤 해당 육각형을 찾는다.
- 레이가 평면에 거의 평행하거나 유효 범위를 벗어나면 잘못된 선택을 발생시키지 않는다.
- 클릭한 섹터를 가볍게 강조하고 `섹터 ID`, `링 거리`, `현재 위치에 속한 천체(정확히 조회 가능한 경우)`만 표시한다.
- 향후 탐사·자원·소유권처럼 **아직 구현되지 않은 상태를 임의로 생성해 표시하지 않는다.**

**입력 우선순위:**

1. 화면 UI 버튼
2. 천체 및 향후 함선·시설
3. 육각형 섹터 평면
4. 빈 공간 클릭에 따른 선택 해제

드래그로 카메라를 움직이려는 동작을 섹터 클릭으로 오인하지 않게 한다. 기존 작은 천체의 보조 선택과 가림 검사를 보존한다.

### 5.4 성능·수명주기

37개 이상으로 섹터가 늘어날 수 있으므로, 칸마다 불필요하게 무거운 메시와 이벤트 리스너를 생성하지 않는다. 공용 Geometry/배치 렌더링, 선택 강조 별도 레이어, 화면 밖 섹터 렌더 생략 등을 고려한다.

항성계 변경, 뷰어 재생성, 화면 해제 시 이전 섹터 Geometry·재질·DOM·이벤트 자원을 정상 정리한다. 섹터 클릭마다 전체 그리드를 재생성하면 안 된다.

## 6. 이후 게임 시스템과의 연동(현재 구현하지 않음)

섹터 모델은 미래에 다음 데이터를 붙일 수 있도록 **기하 정보와 게임 상태를 분리**한다.

- 섹터 발견/탐사 상태 및 미확인 신호
- 자원지대·특이 현상·유물·난파선
- 위험도·적대 신호·함선 활동
- 시설과 소유/관리 정보

현재 단계에서는 위 기능을 더미 상태로 만들거나 가짜 UI로 표시하지 않는다. 섹터는 함선 이동 경로를 육각형 중심점 연결로 강제하는 구조가 아니다. **함선은 미래에도 자유로운 3차원 게임 AU 공간을 이동**하고 섹터는 인덱스/탐사 관리 레이어가 된다.

## 7. 테스트용 항성계 세트 및 범용성 검증

태양계만 통과했다고 완료 처리하면 안 된다. **서로 다른 크기의 항성계 3개 이상**으로 동일한 공용 코드를 검증한다.

| 시험 시스템 | 개요 | 검증 목표 |
|---|---|---|
| A. 현재 태양계 | 중심 항성, 행성 8개, 대표 위성 11개, 소천체 영역 | 기존 기능 유지, 약 3링/7칸 목표 |
| B. 작은 가상 항성계 | K형 또는 다른 분광형 항성, 행성 2~3개, 위성 일부, 외곽 영역 없음 | **동일 육각 크기**, 더 적은 링, 같은 UI |
| C. 큰 가상 항성계 | 더 넓은 외곽 궤도/영역, 별도 중심 위치와 기울어진 기준 평면 | **동일 육각 크기**, 더 많은 링, 올바른 투영 |

시험 항성계는 개발 fixture로 구성하며 이번 버전의 정식 플레이 항성계로 공개할 필요는 없다. 이름과 개수 하드코딩 없이 아래를 보장한다.

- 항성/행성/위성/소천체 영역 개수가 달라도 에러 없이 생성된다.
- 항성계 전체보기 카메라 거리가 데이터로부터 결정된다.
- 선택 패널이 다른 항성계에도 동일하게 작동한다.
- 섹터 크기(`HEX_SECTOR_RADIUS_GAME_AU`)는 **세 항성계에서 정확히 동일**하다.
- 시스템마다 링 수/전체 섹터 개수는 다르다.
- 항성계 중심 이동·평면 회전에도 섹터 위치 조회와 렌더링이 일치한다.
- ID 충돌이 없고, 외곽 링을 추가해도 기존 좌표·경계·ID가 보존된다.
- 공전하는 천체가 섹터 사이를 넘어가면 현재 섹터 조회도 따라 변한다.

### 7.1 자동 테스트(필수)

- Axial 좌표의 고유성, 링 거리, 총 섹터 수 `1 + 3R(R+1)`.
- 일관된 공통 반경, 인접 육각형 타일링(틈/중첩 없음).
- 주어진 점의 섹터 좌표와 육각 중심 좌표 왕복 조회.
- 경계선 위 결정성, 이웃 섹터 조회.
- 항성계 관리 범위 완전 포함; 영역 확장 시 링 수 증가.
- 기준 평면/원점을 바꿔도 3D 투영·역변환 정상.
- 링 추가 전후 기존 섹터 ID/중심/크기 불변.
- 게임 AU↔월드 환산 일관성.
- 공전·시간·카메라·선택 관련 기존 회귀.

### 7.2 브라우저 검증(필수)

- 데스크톱 1440×1000 등 표준 PC 화면.
- 모바일 가로 844×390 및 667×375 등 작은 화면.
- 빈 화면→천체 선택→옆 정보 패널→`확대`→전체보기 복귀.
- 선택 중 공전/카메라 회전 시 패널 위치 업데이트.
- 패널이 가장자리에서 잘리거나 버튼이 조작 불가능해지지 않음.
- 천체/위성 선택과 섹터 선택 우선순위가 올바름.
- 섹터 표시·숨김/호버/클릭 정상.
- 태양계 전체·내행성·행성 근접의 가독성.
- 다른 항성계 fixture에도 동일 UI·그리드가 렌더링됨.
- 브라우저 예외·콘솔 오류 없음, 가능하면 작업 전후 성능 비교.

검증하지 않은 항목은 통과했다고 쓰지 않는다.

## 8. 변경 범위와 권장 모듈 책임

최종 파일명은 현재 코드 구조를 확인한 뒤 결정한다. 책임은 최소 다음처럼 분리한다.

| 책임 | 예시 모듈 |
|---|---|
| 항성계 데이터 컨텍스트/태양계 어댑터 | `system-context.js` |
| 순수 육각형 좌표·링·범위·조회 | `hex-sectors.js` |
| Three.js 육각 그리드 렌더링·입력 교차 | `sector-view.js` |
| 공용 선택 우선순위·상태 | `selection-controller.js` 또는 기존 `selection.js` 확장 |
| 천체 옆 맥락 정보 탭 | `context-panel.js` 또는 기존 `main.js`의 명확한 책임 분리 |
| 기존 게임 AU 변환·카메라·천체 렌더러 | `game-space.js`, `scene.js` 등 재사용 |

이름보다 **데이터·시뮬레이션·선택·렌더링·DOM UI가 서로 직접 얽히지 않는 것**을 우선한다. 기존 `game-space.js`의 현재 환산 설정은 이번 패치에서 독단적으로 재조정하지 않는다.

## 9. 명시적 비범위

이번 패치에서 구현하지 않는다.

- 자원 발견·채굴·생산, 행성 개척·건설·개발
- 함선 제작/설계, 함선 이동, 전술 전투
- 연구, 유물, 초광속, 실제 성간 항행
- 실제 Fog of War 및 탐사·자원/위험 상태의 자동 생성
- 외교·정치 및 다른 시스템의 본격적인 경제 시뮬레이션

미래 API를 고려하되 이번 빌드에서 모두 구현하려고 하지 않는다.

## 10. 완료 기준·제출 형식

### 완료 필수 조건

1. 기존 상시 관측 UI를 최소 게임 HUD 및 천체 옆 정보 패널로 교체.
2. **천체 선택 자체는 줌하지 않고**, 패널의 `확대` 버튼만 카메라 접근 실행.
3. 맥락 패널이 천체 공전·시점 변화·화면 경계·모바일에 정상 대응.
4. 공용 항성계 컨텍스트를 통해 태양계 외 시험 항성계에서도 UI와 카메라 정상 작동.
5. 육각형 한 칸의 게임 AU 크기가 **모든 항성계에서 동일**.
6. 태양계의 초기 약 3링/37칸 목표를 검증하되 다른 항성계는 **링 수 자동 증가/감소**.
7. 항성계의 공전/소천체 전체 관리 범위가 실제 육각형 영역 내부에 포함됨.
8. 섹터 ID·좌표·크기·중심이 링 확장 후에도 불변.
9. 3D 위치의 기준 평면 투영과 섹터 선택, 천체 우선 선택 정상.
10. 기존 game AU·Planet Size·Star Size·공전·자전·시간·텍스처·카메라 기능 회귀 없음.
11. `npm run check`, `npm test`, 가능한 환경의 브라우저 회귀 검사 통과.

### 제출

- 별도 브랜치에서 개발하고 사용자 승인 전에는 `main` 병합 금지.
- 실제 변경 파일·새 구조 설명·조작법·섹터 공통 크기 설정값(게임 AU) 기재.
- 태양계/작은 항성계/큰 항성계 각각 **링 수·섹터 총수·커버 범위** 보고.
- UI 선택·확대 및 육각 표시·선택 스크린샷, 모바일 화면 포함.

## 11. 이전 지시서와 충돌하는 부분의 최종 판정

다음 규칙은 **폐기**한다.

- 항성계 크기에 따라 육각형 1개의 크기를 늘리거나 줄이는 방식.
- 모든 항성계를 항상 정확히 37개 육각형으로 만드는 방식.
- 새로운 외곽 범위가 등장할 때 기존 섹터의 위치나 ID를 바꾸는 방식.
- 태양계 천체명·행성 수·AU 반경을 공용 UI 또는 섹터 함수에 직접 하드코딩하는 방식.

다음 규칙은 **확정**한다.

> **고정 섹터 크기 / 가변 링 수 / 중심부터 육각 링 확장 / 항성계 공용 데이터 / 천체 옆 맥락 UI / 데이터 기반 카메라 / 게임 AU 일관성.**

**최종 목표:** 하나의 특정 태양계 관측 화면이 아니라, 어떤 항성계든 불러와 선택·확대·관리할 수 있는 게임형 전략 지도와 확장 가능한 육각형 섹터 기반을 구현한다.
