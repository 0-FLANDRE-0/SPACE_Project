### 반드시 보존할 게임 규칙

- 항성계 육각 섹터는 반경 210 게임 AU 고정, 행정구역은 그 섹터 ID의 집합. 행성 **표면** 구역은 완전히 별도 좌표·ID 시스템.
- 지구·금성 표면 92칸, 화성 42칸, 목성 642칸 등 **현재 해상도·셀 ID·경계·이웃·해시·자전·표면 텍스처를 바꾸지 않는다.**
- 모든 행성 8개 + 위성 11개, 시험 항성계의 행성·위성, 미래 랜덤 항성계를 공용 함수로 처리. `earth` 같은 이름으로 분기하는 것은 **실지구 자료 적용 어댑터**에만 한정.
- 정부·민간 경제는 **아직 미구현**. 자원 실제 매장지와 2100년 초기 문명 데이터만 생성한다. 플레이 중 채굴·수익·인구성장·테라포밍·전쟁은 수행하지 않는다.
- **광석 1종 → 합금 1종**이 기본 산업 체계. 희귀 전략자원은 등록된 자연매장 자원일 때만 추가 가능. 일반 광석 **품질/화학성분별 재고 시스템을 새로 만들지 않는다.**
- 전투·탐사 타이머·오프라인 보상·함선 속도·연구 등 다른 시스템을 무단으로 만들지 않는다.

## 1. 사용자가 실제로 원하는 작업 흐름

개발자가 매 행성 수십~수백 칸을 수동 편집하는 일이 없도록 한다. **자동 초안 → 검토 → 수동 예외 조정 → JSON 확정**이 기본이다.

1. 기존 모바일 숨김 개발자 진입으로 개발자 도구를 켠다. 새 URL 입력을 요구하지 않는다.
2. 임의의 `planet` 또는 `moon`의 **표면 지도**에 들어간다.
3. `행성 자동 설정` / `일괄 편집` 메뉴를 연다.
4. **생성 범위**를 고른다: 모든 표면 섹터 / 선택한 섹터들 / 미설정 섹터·필드만.
5. **생성할 분야**를 개별 선택한다: 지형·육지/해양 / 환경 / 자연 매장지 / 인구 / 도시화·기반시설.
6. 행성 환경 프로필·시드·자원 총량·초기 총인구 등 상위 기준값을 확인/설정한다.
7. **미리보기**를 누르면 실제 작성될 셀 수·변경될 필드 수·자원 총량·총 POP·보존될 수동 편집·데이터 출처·경고를 확인한다. 표면 지도에 분포를 색상으로 볼 수 있어야 한다.
8. `적용` 전에는 템플릿·로컬 저장·행성 렌더 데이터가 변경되지 않아야 한다.
9. 승인하면 **원자적으로 한 번에 적용**, 저장 상태를 안내하고 **되돌리기**와 **JSON 내보내기**를 제공한다.
10. 특별히 중요한 지구의 섹터나 특정 광맥만 손으로 고쳐 최종 시작 데이터를 확정한다.

### 기본 적용 정책: 기존 편집 보존

- `미설정 값만 채우기(fill-unset)`가 **항상 기본 선택**이다.
- `0`은 의도적으로 입력한 **0**, `[]`는 의도적으로 **매장지/시설 없음**, `false` 등 명시값은 그대로 보존한다.
- 현재 v1 모델의 `null`은 미설정을 뜻하며 일반적으로 채움 대상이다. 단, 필드를 따로 잠그는 잠금 기능이 필요하다면 **v1 JSON에 몰래 새 키를 넣지 말고 별도의 작성 메타데이터**로 관리한다.
- 육지·해양 비율 두 값은 **함께 생성/보존하는 불가분의 쌍**이다. 한쪽만 바꿔 합계가 1이 아닌 데이터를 남기지 않는다.
- 기존 매장지 목록이 `[]`이면 새 광맥을 끼워 넣지 않는다. 목록이 `null`인 경우에만 자동 생성한다. 명시적인 덮어쓰기 모드에서만 예외.
- 기존 인구 `0명`을 '미설정'으로 취급해 이주민을 자동 배치하지 않는다.
- `전체 재생성/기존 값 교체`는 별도 위험 동작: 변경 차이·대상 범위를 미리보기로 표시하고 **별도 확인 후 백업**한다. 기본 버튼으로 사용하지 않는다.
- 미리보기는 기존 사용자가 직접 입력한 값을 보호하고, 정적 프리셋과 현재 초안 중 무엇을 기반으로 삼는지도 보여줘야 한다.

## 2. 데이터 소유권과 미래 테라포밍 계약

**이번 패치의 가장 중요한 구조적 규칙**이다. 테라포밍은 장래 게임 플레이 중 **행성의 환경을 바꾸는 것**이지, 행성 원본과 그 안에 있던 광맥을 새로운 행성으로 다시 생성하는 것이 아니다.

```text
표면 격자 / GridDefinition               고정: tileId, 중심, 경계, 이웃, 면적, fingerprint
          │
          ├── Geology & Baseline Template  초기 지형·자연환경·원래 매장지(고정 원본)
          │       └ 자동 생성 → 개발자 수정 → 승인한 초기 JSON
          │
          ├── StartingScenario (2100)      초기 POP·도시화·기반시설·문명·초기 지식
          │       └ 자동 배치 또는 수동 수정 → 초기 JSON
          │
          └── Future Runtime State         채굴 잔량·인구 변화·시설·현재 기후·테라포밍
                  ├ 행성 전체 대기/기온/수위 등의 가변 상태(향후)
                  └ 섹터별 현재 육해·환경·거주성·시설·피해(향후)
```

- `geology.cells[id].deposits[].initialReserveU`는 **시작 원래 매장량**. 채굴 잔량을 여기에 덮어쓰지 않는다.
- 예를 들어 건조한 행성이 나중에 해양화되어도 **같은 셀 ID와 광맥을 유지**한다. 이후 게임 로직에서 수몰·개발 난도 같은 **접근 조건만 달라질 수 있다**. 현재 패치에서는 그런 변화를 실제로 발생시키지 않는다.
- 원본 환경(초기 `temperatureK`, `landFraction`, `waterFraction`, `habitability` 등)과 **게임 시점의 현재 환경**은 서로 다른 레이어. 초깃값을 덮는 방식으로 테라포밍을 구현하지 않는다.
- 장래 행성 전체 테라포밍 상태는 대기압, 대기 조성, 평균 온도, 표면수, 빙권 등 **행성 수준**, 실제 지역 효과는 표면 섹터 수준으로 연결할 수 있도록 인터페이스·설계 문서에 정의한다. 이들의 현실 물리 단위 및 변환식은 이번 패치에서 확정하지 않는다.
- 가스 거대행성은 계속 **대기 기준층**으로 취급한다. 미래 테라포밍을 핑계로 고체 표면으로 변환해 버리지 않는다.
- 새 기술로 미발견 광맥을 찾을 때도 지질 원본은 변하지 않고 **문명별 발견 기록만 증가**한다. 자동 생성기가 현행 `startingScenario.cells[].knowledge`를 몰래 전부 완료시키지 않는다.
- 나중에 한 섹터의 도시나 광산이 파괴되어도 초기 시나리오 파일은 원형을 유지해야 한다.
- `docs/architecture/TERRAFORMING_DATA_CONTRACT.md` 같은 문서에 **불변 원본/초기 시나리오/변화 레이어의 우선순위와 합성 방법**을 제시한다. 가능하다면 작동하지 않는 순수 계산 예제와 테스트를 둬도 좋으나 **기후 변화 시뮬레이터를 억지로 구현하지 않는다.**

### 중요: 현행 v1 스키마를 존중할 것

현재 `validateSurfaceTemplate()`은 허용 필드를 엄격하게 검사한다. 즉, JSON 최상위나 `geology` 아래에 `seed` 또는 `terraformingState` 키를 무심코 추가하면 기존 가져오기가 실패한다.

**기본 구현 방침:** 실제 게임 초기 JSON의 `schemaVersion: 1` 및 기존 `grid` 정의를 유지하고, 생성 시드·프로필·작성자 설정·자동/수동 출처 같은 **제작 메타데이터는 별도 sidecar/편집기 설정/전용 다운로드**에 저장한다. 새로운 필드가 정말 필수라면 독립 버전 2와 **실제 v1→v2 마이그레이션/검증/테스트**를 완료한 경우에만 허용한다. 무단 포맷 교체 금지.

## 3. 자동 생성 코어 — 순수 함수와 재현성

권장 신규 모듈(파일명 변경 가능, 역할은 분리):

```text
dist/src/planetary-generation-profiles.js  행성 유형별 환경·자원·문명 배치 프로필
dist/src/planetary-data-generator.js      시드 기반 표면 데이터 생성 순수 함수
dist/src/planetary-generation-merge.js    null/0/수동 입력 보존, 변경 미리보기, 예산 검증
dist/src/planetary-generation-ui.js       개발자 일괄 생성·지도 미리보기·확정 UI
dist/src/planetary-surface-layer.js       (필요할 때만) 원본 + 향후 runtime 환경 합성 계약
tests/planetary-data-generator.test.js   시드/지형/매장량/인구/합치기/JSON 검증
```

핵심 코어는 **DOM, Three.js, 로컬 저장소, `fetch`, 시간, `Math.random()`에 의존하지 않는 순수 함수**로 만든다.

권장 인터페이스 예시:

```js
const draft = generatePlanetSurfaceDraft({
  systemId, body, grid,
  seed: 'sol-earth-2100-v1',
  generatorVersion: 1,
  profileId: 'terrestrial-earthlike',
  earthMask: optionalPreparedEarthMask, // 사용할 때만; 없다고 실지리라고 주장하지 않기
  resourceBudgetsU: { ore: 2_000_000 }, // 게임 밸런스 예시, 확정값 아님
  scenario: {
    populationTotalPersons: null, // 미지정. null이면 인구를 멋대로 만들어내지 않기
    civilizationId: null,
    urbanizationPolicy: 'optional',
  },
});

const preview = planSurfaceGeneration({
  template: currentTemplate,
  draft,
  scope: 'all',
  fields: ['terrain','environment','deposits'],
  policy: 'fill-unset',
});
// preview.nextTemplate는 기존 스키마 검증을 통과하지만 아직 적용되지 않음.
```

- 같은 `systemId`, `bodyId`, 시드, 생성기 버전, 프로필, 입력 자료로 **어떤 기기에서 어떤 순서로 호출해도 동일한 결과**를 낸다.
- `Math.random`, `Date.now`, 현재 게임 시간, 현재 카메라 위치를 자연 데이터 생성에 사용하지 않는다.
- 무작위 수는 명시적인 seeded PRNG 사용. **타일/필드/매장 종류별로 키가 분리된 난수 흐름**을 사용해 다른 셀 하나 추가·편집했다고 전 행성 데이터가 뒤집히지 않도록 한다.
- `grid.tiles`, `areaWeight`, `neighborIds`, `latitudeDegrees`, `longitudeDegrees`, 구면 중심/경계를 **기존 격자에서 읽고 재사용**한다.
- 자연환경 생성의 고유 ID와 지질 데이터는 미래 랜덤 생성 항성계에도 사용 가능. `sol/earth`에만 돌아가는 코드는 불합격.
- 생성 도중 행성·시스템 변경/개발자 종료 시 진행 중 미리보기를 무효화하고 다른 행성에 결과가 적용되지 않도록 세대 토큰·취소를 지원한다.
- 대규모 셀의 생성은 적절히 분할하거나 비동기 계산을 사용해 모바일 UI를 장시간 막지 않는다. UI와 코어 로직을 섞지 말 것.

### 생성기 프로필 / 환경 매개변수

최소한 다음 경향을 가진 프로필을 분리한다(이름은 예시):

| 프로필 | 생성 원칙 |
|---|---|
| 지구형·해양 포함 암석 | 연속적인 대륙/해양, 육상·해양·혼합 섹터. 행성별 육지 비율 목표와 기후 설정 사용. |
| 건조 암석형 | 물 비율이 기본적으로 낮고 암석·사막·산악 중심, 광석 매장 가능. |
| 진공 암석·소형 위성 | 일반적으로 `vacuum-rock`, 방사선/거주성 별도, 육지/물 **두 값은 유효한 기준에 맞게** 설정. |
| 얼음형 표면 위성 | 얼음 환경 우선, 지하 바다 등 실제 설정이 없으면 임의로 확정하지 않음. `terrainType:'ice'` 가능. |
| 가스·얼음 거대행성 | `surfaceType:'atmosphere'`, 육지/물 비율 반드시 `null`, 대기 기준층 환경만. 석재 지표 광산을 자동 생성하지 않는다. |
| 외계/미지 행성 | `body` 입력 메타데이터/명시적 프로필/시드로 생성. 지구와 같은 기후·인구를 무조건 복사하지 않는다. |

- 행성 유형 분류는 사용 가능한 `body.surfaceType` / 명시적 `geologyProfileId`/프로필 설정을 우선한다. 현재 `body.type`의 한국어 설명만을 유일한 신뢰 원천으로 삼거나 `body.id` 하드코딩을 남발하지 않는다.
- 기존 NASA/JPL 천문 참고 자료와 **게임 AU는 별개의 척도**다. 게임 AU를 현실 km/실제 AU처럼 취급해 태양 복사량이나 실제 기후를 계산하지 않는다. 물리 모델을 구현하지 않는 이상 기후·온도는 게임용 프로필 기반 가정으로 명시한다.
- 행성의 면적·위도/이웃·환경 차이를 반영하되, 임의 행성마다 텍스처 색상을 진짜 지질 조사 자료처럼 설명하지 않는다.
- 초기 프로필 수치는 **밸런스 조정 가능한 설정**이지 확정된 세계관의 실제 자원 총량이 아니다.

## 4. 지구의 육지·해양 비율 자동 산정 — 실제 자료와 가상 생성을 구분

**지구는 현재 실제 대륙 텍스처를 사용하는데, 섹터별 육지/해양 비율은 가능하면 실제 지리 자료를 이용해 자동 계산한다.**

- 권장 원천: Natural Earth `1:50m Land`(land polygon) 같은 **공개 라이선스가 확인된 육지 경계 데이터**. 공식 페이지: https://www.naturalearthdata.com/downloads/50m-physical-vectors/ ; 이용조건: https://www.naturalearthdata.com/about/terms-of-use/ .
- 실제 데이터를 사용할 경우 **출처·버전·가공 방법·라이선스·지형 해상도의 한계**를 기록하고, 필요한 처리 결과를 `dist/assets/` 또는 `dist/data/`에 로컬 포함. 브라우저 런타임에서 외부 API/도메인 요청 금지.
- 원본 경계 폴리곤을 미리 처리해 적절한 면적 판별 자료로 만든다. 기존 표면 타일의 구면 다각형 내부를 **여러 점 또는 면적 가중 샘플**로 평가해 섹터별 면적 비율을 도출한다. 단순히 타일 중심점의 색 하나로 0/1 판정하지 않는다.
- 위도·경도 매핑은 기존 격자의 `longitudeDegrees`(로컬 +X 기준, -Z 방향을 동쪽으로 표현), 자전 고정 프레임, 현재 Earth 텍스처의 경도 seam을 확인한다. 적어도 여러 알려진 대륙/해양 지역에 해당하는 셀의 지리 좌표가 서로 맞는지 브라우저 스크린샷과 테스트로 검증한다.
- 극지·날짜변경선·섬·해안·오각형에서도 샘플이 작동해야 한다. 전체 면적 가중 육지/해양 비율은 **원천 데이터와 합리적 범위**에서 일치해야 한다.
- 소스 파일 확보에 실패하면 **'지구 실제 지리 자동 인식' 기능을 완료했다고 주장하지 않는다.** 별도 `절차적 임시 지형` 모드로 표시하고 검증되지 않은 값은 출처를 분명히 한다. 현재 텍스처의 색상만 보는 부정확한 방법을 진짜 육지 경계로 가장하지 않는다.
- 지구의 `Planet Size` 및 기존 표면 지도·ID·텍스처·자전을 수정해 비율을 맞추는 꼼수 금지.

다른 실제 행성은 해당 데이터가 없으면 **게임용 절차적 환경 분포**로 생성하며, 근거 없는 '실제 관측값'이라고 표시하지 않는다.

## 5. 가상 행성의 지형·환경 분포: 주변 셀과 연결되는 생성

- 각 셀에 제각각 완전 독립 난수를 뿌려 지형이 **체커보드처럼 튀는 것**을 피한다.
- 구면상의 연속 노이즈 또는 `neighborIds`를 이용한 영역 성장/클러스터링으로 대륙·해역·암석·얼음·산악 등의 **연속된 지형대**를 형성한다.
- 셀별 `areaWeight`로 분포 목표를 평가한다. 같은 타일 1개에 같은 비율을 할당하는 방식은 면적이 다른 오각형/육각형에 편향될 수 있다.
- 환경 수치는 현행 스키마 범위 안에만 작성: `temperatureK >= 0`, `radiationLevel >= 0`, `terrainObstacle`/`habitability` 각각 `0..1`, `terrainType`은 현행 `TERRAIN_TYPES` 목록. 미확정 값은 `null` 유지.
- 가스 거대행성에서 `landFraction=0`/`waterFraction=1`로 억지 표현하지 말 것. **둘 다 `null`**이며 `surfaceType='atmosphere'`다.
- 얼음 지형과 해양 여부는 별도 개념이다. 얼음이 있다는 이유만으로 전체를 '액체 해양 100%'라고 판정하지 않는다.
- 가까운 섹터의 기온·지형 특성이 부자연스럽게 급변하지 않도록 하되, 산맥·극지 같은 의도적인 경계는 허용한다.
- 현실적인 기후/지질 연구 모델은 이번에 만들지 않는다. 생성 결과는 재현 가능한 **게임 초기 데이터**다.

## 6. 유한 자원 매장지 생성: U 단위·총량 보존·전략자원 호환

### 기본 규칙

- **1 U(Unit)=10톤.** `credits`는 화폐 C, `alloy`는 가공품이므로 **자연 매장지를 생성하지 않는다**.
- 시작 기본 자연 매장 자원은 `ore`. 추가 전략자원은 `RESOURCE_DEFINITIONS`에 `naturalDeposit:true`, `unit:'U'`로 **실제로 등록된 경우에만** 사용한다.
- 일반 광석은 하나의 재고 종류다. `저품질 광석 A`, `성분별 광석 B` 같은 별도 자원/품질별 창고를 임의 신설하지 않는다.
- 매장지는 `depositId`, `resourceId`, `initialReserveU`, `extractionDifficulty`, `discoveryTier`, `notes`라는 **현행 필드**를 사용한다.
- 매장량은 **유한**. 향후 채굴이 진행되면 원래 매장량과 별도 런타임 `remainingReserveU`가 감소하는 계약.
- `discoveryTier`는 그 자원을 볼 수 있는 센서·정밀 조사 단계 조건이다. 생성했다고 플레이어가 자동으로 발견한 것으로 기록하지 않는다.
- 석질 행성·금속성 소행성의 채굴 가능성 등은 향후 자원 프로필로 구분한다. **현재 행성 표면 생성기가 소행성대 개별 입자 모델까지 만들 필요는 없지만**, 자원 분포 코어는 미래 소행성 광맥에도 재사용할 수 있도록 의존성을 줄인다.

### 행성 전체 자원 예산(budget)

- 개발자가 `행성의 광석 총량 목표: N U`를 입력하면, 생성기가 선택된 섹터에 합계가 **N U**가 되도록 분배할 수 있어야 한다.
- `N`은 해당 프로젝트의 **총 초기 자연 매장량**이며, 이미 채굴된 재고/정부 창고가 아니다.
- 분배는 `areaWeight × 해당 지질의 매장 가능성 × 공간적으로 연속된 광맥 가중치 × 난이도 계수` 등을 사용하되, 총량 보존이 최우선이다.
- 부동소수점 반올림으로 새거나 과잉 생성되지 않도록 U를 **명시적인 최소 분배 단위**(예: 0.001 U)로 환산해 **결정적인 최대 잔여량 배분 방식**을 사용한다. 단위·반올림 규칙을 문서화한다.
- 여러 광맥을 생성하더라도 전체 합계와 셀별 제한(매장지 배열 최대 64개, 한 매장지 최대 `MAX_RESOURCE_U`)을 지킨다. 전체 예산이 설정 가능한 한도 밖이면 조용히 잘라내지 말고 명확히 거부한다.
- `depositId`는 같은 시드·천체·셀·자원·일련번호에 대해 **안정적이고 행성 내 유일**하게 생성. 현행 허용 문자와 길이 제한을 준수한다.
- 물·가스 등 아직 자원 카탈로그에 없는 종류를 `ore`로 위장하지 않는다. 특히 가스 행성은 표면 암석 광산을 임의로 생성하지 않는다. 적절한 대기 자원이 등록되기 전에는 **매장지 없음 `[]`** 또는 데이터 미설정 `null`을 올바르게 구분한다.
- 자원 종류별 목표치 `null`은 미정, `0`은 **0 U 확정**이라는 의미를 지킨다.

### 자동 생성 대상 범위와 수동 매장지 처리

- 기존 매장지가 있다면 기본 `fill-unset`에서는 **그대로 유지**, 신규 생성 목표 예산의 계산에서 기존 매장량이 차지하는 몫을 반영해야 한다. 전체 행성 N U 목표와 기존 고정 매장량이 모순되면 **오류/경고/수동 선택**으로 처리하고 조용히 재분배하거나 삭제하지 않는다.
- 일부 셀만 재생성하는 경우, **행성 전체 N U와 '선택된 영역에만 분배하는 예산'을 분명히 구분**한다. 예산을 무심코 선택된 셀 전부에 재주입하여 자원량이 복제되지 않도록 한다.
- 선택한 섹터/동일한 자원에 대해 재생성 버튼을 여러 번 눌러도 **중복 광맥 생성·재고 복제**가 일어나면 안 된다.
- `discoveryTier`가 높아도 고급 자원이 매장된 채 남아 있고, 나중에 탐사 기술로 드러나는 구조를 유지한다.

## 7. 초기 인류 문명·인구·도시화의 자동 배치

### 확정 단위와 합계

- **1 POP = 100만 명**, 내부 데이터는 반드시 **정수 명수(`populationPersons`)**로 저장.
- 지구 시작 인구는 **아직 사용자가 확정하지 않았다.** 예시로 쓰는 8,500 POP 등을 공식 시작 수치로 하드코딩하지 않는다.
- 개발자가 **행성 총 인구 목표(POP 또는 명수)를 입력**하면 자동으로 표면 셀에 배분하고 합계가 정확히 목표 정수 인구가 되게 한다.
- 분포 가중치에는 섹터 면적·육지/해양 비율·거주 적합성·지형·해안 선호·행성 환경·명시된 정착지 중심 등을 사용할 수 있다. 지구는 가능한 경우 공개 지리/인구 자료를 **근거 있는 시나리오 입력**으로 사용하고, 2100년 미래 예측을 확정 사실처럼 설명하지 않는다.
- 모든 섹터에 균등 배분하지 않는다. 선택한 해양 섹터에 해상 정착지가 있다면 0일 필요는 없지만, 자동으로 모든 바다에 동일 인구를 채우지도 않는다.
- 남은 1명 단위까지 합계가 정확하도록 결정적인 정수 최대 잔여량 배분을 사용한다. 음수·소수 사람·합계 유실 금지.
- 도시화율은 셀별 `0..1`, 기반시설은 정수 `0..5`. 인구밀집도가 높다고 반드시 모든 섹터의 도시화율이 1이 되도록 만들지 않는다.
- `civilizationId`, `ownerFactionId`, `controllerFactionId`는 사용자가 지정하거나 초기 시나리오 프로필에 근거한 경우에만 넣는다. 실제 통치 주체를 알 수 없으면 null.
- `startingScenario.knowledge` 및 `facilities`는 기존 편집내용 보존. 지구에 거주한다고 모든 광맥을 다 아는 것으로 만들지 않는다.

### 외계 행성과 인류 식민지

- **무인/미지 행성 기본값은 문명·인구를 임의 생성하지 않음.** 인구가 실제로 0명임을 설정하려면 명시적으로 0을 선택. 기본 `null`을 '무인 확정'으로 슬쩍 변환하지 않는다.
- 달/화성의 초기 작은 식민지 여부는 세계관 구상이지만, **정확한 초기 POP은 아직 미정**. 개발자가 상위 POP 총량과 초기 정착지 중심을 지정하면 자동 배치할 수 있어야 한다.
- 장래 랜덤 항성계에서 문명·외계 종족·기존 도시가 존재하는지 여부는 **해당 시나리오 생성기/세력 시스템이 명시적으로 결정**한다. 지질 생성기가 임의로 인류 도시를 만든다면 설계 오류.
- 별도의 인구/도시화 프로필을 지원해서 **자연 행성 생성과 문명 배치를 독립 호출**할 수 있게 한다.

## 8. UI 요구: 개발자용 일괄 생성·시각화·미리보기

기존 7회 로고 탭과 전체화면, 모바일 가로 UI를 유지한다. 개발자 모드 밖에서는 자동 생성기와 미발견 자원값이 보이지 않는다. 비활성화 시 입력 폼도 비운다.

### 8.1 생성 도구

표면 지도 화면에서 `자동 설정` 버튼(개발자 전용)을 열면 다음을 제공:

- **대상:** 현재 행성/위성, 필요 시 동일 항성계의 전체 행성/위성 일괄 생성(개별 행성 원본은 서로 분리, 시스템 변환 중 취소 가능).
- **필드 선택:** 지형·육해 / 환경 / 자연 매장지 / 인구 / 도시화·기반시설. 각각 독립 선택 및 조합.
- **대상 셀:** 전체 / 선택한 셀들 / 미설정 값만(필드 단위 보존).
- **쓰기 정책:** 미설정만 채우기(기본) / 명시적 덮어쓰기(백업+확인).
- **행성 프로필:** 자동 추천 가능하지만 실제 분류 근거 표시, 개발자가 변경 가능.
- **시드:** 문자열/정수 명시, 기본은 안정적인 시스템/천체 키 + 버전, '새 시드'도 사용자가 명시적으로 눌렀을 때만 변경.
- **자원 총량:** 자원별 U, 자원 미등록이면 선택 불가. 정수/소수 입력 유효성 검사.
- **시나리오:** 문명 ID, 총 POP/명수, 정착 중심 섹터 선택, 도시화·기반시설 초기 분포 정책.
- **자료 출처:** 지구 실제 경계 기반 / 절차적 생성 / 수동 프리셋을 구분해서 명확히 표시.

### 8.2 시각화/검수

개발자 지도 레이어를 전환할 수 있게 한다. 최소한 `육지·해양 비율`, `지형`, `광석 매장량`, `인구 분포`, `도시화`, `미설정 항목` 모드를 지원.

- 각 셀을 클릭하면 해당 **실제 계산값/이전값/예정값**을 비교.
- 색 범례, 단위, min/max와 비어 있는 값(null)의 구별. `0`과 `null`을 같은 색으로 묘사하지 않는다.
- 개발자 검수 레이어만 사용. 일반 플레이어가 실제 미발견 광맥을 지도 색상으로 추측할 수 있게 하면 안 된다.
- 새 지도 모드는 기존 고정 구면 타일 경계·선택 판정을 재사용. 색상 변경을 위해 매 프레임 수백 개 Mesh/DOM을 새로 만들지 않는다.
- Preview는 `작성 예정 셀 수`, `변경 필드 수`, `보호된 값 수`, `예상 총 광석 U`, `총 POP`, `매장지 수`, `경고/출처`를 계산. 전체 예산/인구 합계가 맞는지 한눈에 보여준다.
- `미리보기 → 적용 확인 → 저장 성공/실패 표시 → 되돌리기 → 기존 JSON 내보내기` 흐름을 모바일 터치로도 사용 가능해야 한다.
- 저장 실패/손상 초안 격리/구버전 파일은 현재 `SurfaceDrafts`의 경고/백업/가져오기 정책과 충돌하지 않는다.
- UI와 폼이 좁은 667×375·844×390 화면에서 상단/하단 HUD 및 전체화면 버튼을 막지 않고 내부 스크롤되어야 한다.

### 8.3 전체 항성계 일괄 생성 (선택적 추가 UI, 공용 코어는 필수)

현재 편집기가 한 천체만 열도록 설계되어 있으므로 **적어도 코어 수준에서는 한 항성계의 모든 `planet/moon`을 동일 정책으로 순회하여 각기 독립된 JSON 초안을 만드는 기능**이 있어야 한다. 가능하면 개발자 드로어에 `항성계 일괄 자동 설정`을 추가해 진행 상황/취소/대상별 성공·실패를 보여준다.

- 한 행성의 실패가 다른 행성의 기존 초안을 손상시키지 않는다.
- 시스템 전환 중 이전 행성 미리보기/결과가 섞이지 않는다.
- 모든 행성에 같은 프로필/인구를 일괄 복제하지 않는다. 실제 body metadata 기반으로 서로 다른 프로필을 고른다.
- 기본적으로 **자동 생성된 결과를 실게임 기본 프리셋에 조용히 영구 등록하지 않는다.** 개발자가 검토한 뒤 JSON 내보내기 및 manifest 등록을 확정한다.

## 9. 데이터 저장 및 가져오기/내보내기

- 최종 행성 JSON은 현행 `planet-surface-template` v1 형식을 유지(위 계약의 조건 충족 시 마이그레이션이 별도로 필요할 수 있음).
- `geology.cells`에는 자연 원본, `startingScenario.cells`에는 초깃값. 오프라인 생산·부채·게임 진행 후 자원 잔량 등은 절대 저장하지 않는다.
- 생성 시드·프로필·source id·자료 버전·작성 정책을 남기고 싶으면 `planetary-generation` 별도 메타데이터 JSON이나 개발자 로컬 설정으로 보관. 파일 내보내기에는 **기존 게임이 읽는 단일 v1 템플릿**을 반드시 제공한다.
- 기존 `importSurfaceJSON`, `validateSurfaceTemplate`, `SurfaceDrafts.commit`, 백업·Undo를 우회해 비검증 JSON을 바로 저장하지 않는다.
- 이미 등록된 `dist/data/planet-surfaces/index.json`의 파일은 사용자가 **명시적 승인한 결과만** 수정. 아직 `templates:{}`라면 이를 무단으로 지구 인구·매장량 예시로 채우지 않는다.
- 데이터 원천/시드가 같으면 export→import→export 정규화 결과가 같다. 수동 수정 후 '미설정만 채우기'를 실행해도 수정값이 유지되어야 한다.
- `1 U=10톤`이고 화폐 C는 질량 없는 별도 값. 자원 매장 원본에 `alloy`/`credits`가 생성되면 검증 실패.

## 10. 테라포밍 확장 준비 검증 (실제 테라포밍은 미구현)

향후 아래와 같은 데이터 합성이 가능해야 한다는 **계약을 문서로 확정**한다.

```js
// 미래 예시: 이번 패치에서 실제 동작하는 시뮬레이션을 만들라는 뜻 아님.
const original = template.geology.cells[tileId];
const scenario = template.startingScenario.cells[tileId];
const current = runtime.planetConditionsAndTileOverrides?.[tileId];
const effective = resolveEffectiveSurfaceState(original, scenario, current);
```

필수 설계 검증:

1. 건조 행성 셀의 초기 육지/물 `1.0/0.0` → 장래 테라포밍 후 현재값 `0.6/0.4` 가능. 초기 원본은 `1.0/0.0`으로 보존.
2. 셀 `ID`, `neighborIds`, `gridFingerprint`, 위치·광맥 원래 매장량은 변하지 않음.
3. 침수된 광산의 **접근 가능성**이나 지상의 시설 상태는 변할 수 있지만, 광맥 자체가 다시 생성되거나 사라지지 않음(채굴/재해 이벤트는 별도).
4. 환경 변화와 **초기 시나리오 인구·시설의 원본**도 분리됨. 현재 POP·도시화는 미래 runtime에서 따로 보관.
5. 플레이어 문명의 탐사 결과와 실제 지질 자원은 별개. 테라포밍 후 새로운 센서로 발견되는 내용은 미래 knowledge에 추가되는 형태.
6. 가스 행성에 땅이 생성되었다고 자동 처리하지 않음. 행성 종류 자체를 바꾸는 테라포밍은 이 계약 범위를 벗어난 향후 별도 기술/시스템.

위 내용의 원본/런타임 분리 예시를 문서 또는 순수 helper 테스트로 보여주되, 기후 방정식·테라포밍 비용·속도·연구/시설/이펙트는 **지금 구현하지 않는다.**

## 11. 성능·안정성·사용성

- 태양계 모든 행성·위성 **19개**의 표면이 공용 코어에서 생성 가능해야 한다. 지구 f3/92칸, 목성 f8/642칸, 토성 f7/492칸, 위성 f2/42칸 같은 기존 결과를 보존한다.
- 한 천체만 활성 렌더링, 기존 GPU Geometry/Material 재활용·dispose. 데이터 생성으로 구체 크기·텍스처·자전 프레임을 변경하지 않는다.
- 재시도·동일 시드·같은 값을 다시 적용할 때 전체 배열 복제/DOM/가시 레이어가 끝없이 쌓이지 않는다.
- CPU 작업은 `requestAnimationFrame`마다 전체 섹터 재생성 금지. 선택·미리보기·적용 시 필요할 때만 수행. 모바일에서 UI 프리즈를 최소화.
- 프로필/생성기 버전이 바뀌면 기존 타일·매장지 ID를 바꾸는 재생성을 자동 강제하지 않는다. 기존 JSON을 보존하고 명시적 재생성/마이그레이션 절차를 안내.
- `localStorage` 사용 가능 여부를 확인하고 실패하면 메모리 미리보기 + 파일 백업 안내. 무한 재시도/사용자 저장 원본 삭제 금지.
- 개발자 종료 시 폼과 미공개 지질·광맥 검수 UI를 정리. 숨김 개발자 모드는 보안·암호화가 아니므로 클라이언트 코드의 비밀 자체를 보호한다고 주장하면 안 된다.
- PC·모바일에서 전체화면 버튼, 지도 선택, 카메라, 표면/항성계 전환, 행정 섹터 편집, 시간 배속은 정상 유지.

## 12. 테스트와 완수 조건

### 12.1 새 순수 함수 자동 테스트

다음 시나리오를 추가하고 실수로 통과만 시키는 무의미한 단언은 금지:

1. **결정성:** 같은 seed/profile/body/grid → 완전히 같은 필드·매장지 ID·수치, 호출 순서를 바꾸어도 같음.
2. **차별성:** 시드·행성 프로필 변경 시 적절한 분포 차이 발생. 같은 설정으로 복귀하면 원래 결과와 동일.
3. **격자 보호:** v0.5B 고유 셀 ID/주파수/개수/neighborIds/fingerprint가 생성 전후 같음.
4. **오각형·극·경도 seam:** 생성 데이터가 모든 셀을 지원하고 지형·면적 집계 실패가 없음.
5. **실지구 마스크:** 실제 소스 사용 시 대륙·대양의 대표 좌표와 섹터값을 비교, 육지/해양 전체 면적 비중을 원천과 비교. 소스가 없다면 결과가 '절차적 임시'로 명확히 표시됨.
6. **육지·바다:** 고체형은 `0..1` 합계1, 대기형은 둘 다 null.
7. **환경:** 허용 지형 목록/유효 수치 범위/상식적인 공간 연속성; 입력 없는 환경값은 자동 거짓 과학 수치로 확정되지 않음.
8. **유한 매장량:** 고정 총 예산 N U일 때 정확하게 N 배분, 0 예산/미설정/null/최대 한도 검증.
9. **자원 제한:** ore/등록 자연 자원만; alloy/credits 생성 금지; 가스 행성에 지표 광산 임의 생성 금지.
10. **매장지 고유 ID:** 같은 seed 재생성 동일, 같은 행성 내 중복 없음. 일부 셀만 변경해도 기존 매장지 ID 안정.
11. **수동 값 유지:** 0명, 인구 1명, 육지0/물1, 매장지 `[]`, 직접 입력한 `initialReserveU`, 기존 시설·지식 보존.
12. **선택/전역 예산:** 선택한 셀에 전체 행성 예산을 중복 주입하지 않음. 고정 매장량이 목표 예산보다 크면 원자적 거부.
13. **POP 합계:** 입력된 총 인구가 정수 명수로 정확하게 분포, 소수 명수·허용 최대 초과 거부.
14. **무인 행성:** 지질을 생성해도 문명 인구/시설/지식은 명시적 시나리오 없이는 채워지지 않음.
15. **원본 불변:** 생성 이후 진입/종료/미리보기/실패한 적용은 저장 원본을 바꾸지 않음.
16. **원자성:** 검증 실패·타 천체 데이터·다른 격자 fingerprint·미등록 자원 등은 전체 적용 거부, 기존 초안 보존.
17. **입출력:** 자동 생성 → JSON export → JSON import → 검증·동등성 PASS, 기존 v1 파일 호환 유지.
18. **기존 데이터 우선:** 수동으로 수정한 값이 재생성 후에도 유지, 덮어쓰기 모드만 사전 확인/백업.
19. **테라포밍 계약:** 미래 현재값 override 예시를 합성하더라도 baseline 셀·매장지·ID 변경 0.
20. **모든 대상:** 태양계8+위성11+작은/큰 개발용 항성계 fixture의 기존 상태와 결과가 고립됨.

### 12.2 실제 브라우저 회귀

## 14. 작업 완료 판단 기준 — 핵심 요약

**v0.5C의 성공은 개발자가 매 셀을 수동으로 채우지 않아도 된다는 것으로 판단한다.**

1. 전 행성·위성에서 **일관된 시드 기반 지형/환경/광맥 데이터**를 한 번에 만들 수 있다.
2. 지구는 신뢰할 수 있는 공개 육지 경계 기반으로 섹터 육해를 계산하거나, **실제 자료가 없는 경우 그 한계를 정직하게 표시한다**.
3. 개발자가 **행성 전체 자원 목표량과 총 POP**을 지정해 여러 셀에 자동 분배할 수 있다.
4. 사람이 손으로 수정한 값은 기본 자동 채우기에서 보호되고, 덮어쓰기는 명시적으로 확인한다.
5. 완성한 행성 데이터는 **기존 v1 JSON 형식으로 내보내기/불러오기** 가능하다.
6. 미래 테라포밍·채굴·인구 성장으로 바뀔 값과 **원래 있던 자연환경/광맥/격자**가 섞이지 않는 데이터 계약을 문서화한다.
7. 기존 항성계·행정 지도·시간·전체화면·모바일 숨김 개발자 모드·3D 행성 렌더링이 모두 회귀 없이 유지된다.

기준이 모호하다면 무리하게 창작하지 말고, **확정되지 않은 밸런스 값은 프로필/개발자 입력으로 남기고** 재현 가능한 기본 예시로 테스트한다. 단, 검증에 필요한 순수 기능과 UI는 실제 작동 상태로 제출할 것.

**Codex에게: 위 기준에 맞춰 코드를 수정하고, `feat/v0.5c-planetary-data-generator` 브랜치에서 PR을 생성하되 기존 브랜치/main을 병합하지 말 것.**
