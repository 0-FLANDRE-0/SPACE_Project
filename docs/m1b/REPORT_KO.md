## 궤도 그래프와 이동 방식

19개 행성·위성에서 기존 `createPlanetarySurfaceGrid`의 frequency·꼭짓점·지문을 그대로 사용한다. 저1.05R/중1.3R/고1.6R에 동일 격자를 올렸으며, 고궤도만 해상도를 낮추지 않았다. 지구는 **층당180점/총540점**, 목성은 **층당1,280점/총3,840점**이다. 전체 천체의 수치는 [격자·라그랑주 감사](geometry-audit.json)에 있다.

점 ID는 `earth:low:v0` 같은 결정적 식별자다. 점은 **기존 축·자전 프레임과 함께 회전**한다. 도착 후 해당 ID와 localOffset을 유지하고 공전·자전을 추종한다. 선회/충전 중 취소해도 정지 중이던 점의 ID를 보존한다. 이동 중간에서 멈추면 그 위치를 천체 좌표계에 고정한다.

같은 층의 실제 이웃 꼭짓점과 동일 꼭짓점의 위·아래 층만 연결한다. 격자 밖 출발/도착 좌표는 각 층의 가까운 점6개와 가상 진입/도착 간선으로 연결한다. 기존 근접 좌표/아군 스냅샷을 불필요하게 격자 밖으로 돌리지 않도록 안전한 직접 연결도 가상 간선으로 처리한다 [구현 선택]. 이미 격자점에 있다면 그 점에서 시작하여 대각선으로 층을 건너뛰지 않는다. 0거리 진입은 실제 이동 구간/경로점으로 표시하지 않는다.

경로 탐색은 **이전 점+현재 점**을 상태로 둔 Dijkstra다. 같은 점에 도착해도 진입 방향이 다르면 다음 선회 비용이 달라지므로 구별한다. 간선마다 다음 비용을 비교하고 동률이면 추진을 택한다.

```
추진 = 선회 + 거리 / 추진속도
드라이브 = 선회 + 기본충전×질량계수 + 거리 / 드라이브속도
```

직선·선회 제외 손익분기는 펄스 **1gAU**, 하이퍼펄스 **약2.409gAU**다. 이는 간선별 기준이며 여러 꼭짓점을 지나는 전체 경로의 합산 거리에 한 번만 적용하지 않는다. 선택된 다음 구간의 추진/드라이브를 함선 상태에 표시한다. 행성권 밖 목적지는 계속 드라이브를 사용한다.

행성권 내부 드라이브도 자전·공전하는 **천체 좌표계**에서 계산한다. 선회 비용도 그 좌표계 기준이다. 메시/선택은 Three.js, 위치·프레임·탐색·시계는 순수 모델로 분리했다.

## 충돌 여유·LOS 즉시 출발

내부 여유는 **1.02R** [임시]로 분리했다. 외부 천체/항성 우회는 기존 **R+min(0.4gAU,0.2R)**를 유지한다. 따라서 지구 저궤도1.05R가 기존 약1.14R 여유 안으로 들어가던 문제를 해결한다. 모든 이웃/진입 간선은 중심을 지나는 직선의 최소 거리로 검사하며, 모든 기존 표면 해상도에서 저궤도 간선이 내부 여유 밖임을 검증했다. 다른 천체는 구간 시각별 위치로 검사한다.

출발 탐색은 세 층 전체를 후보로 하고 **점까지의 이동+선회+충전+예측 도착 순항**을 비교한다. LOS가 열리는 상태는 종착 후보로 기록하고 그 뒤의 궤도 간선을 더 확장하지 않는다. 선택된 경로에서도 열린 첫 점이 마지막 행성권 점이다. 무조건 고궤도로 상승하는 단계를 제거했다. 항성계 `driveRoute`의 우회 구조와 ‘최종 LOS가 바로 열리는 후보 우선’ 정렬은 유지한다.

도착 시각의 목표 위치, 정렬/충전 동안 출발 점이 자전하는 위치를 사용한다. 외부 우회점에서는 계속 재선회·재충전한다. 잘못된/차단된 경로는 실행하지 않고 기존 주문을 보존한다. 임시 최대 탐색 상태는100,000이다.

|---|---:|---:|
| 행성권 경로 종료 | 7,450.095초 | **6,228.405초** |

## 라그랑주점

**태양–행성40개 + 행성–위성55개 = 95개**다. 실제 질량·중력 평형 공식을 사용하지 않는다.

- L1/L2: 부모→대상 직선에서 지시서의 행성권/위성 궤도·이웃 간격 계수로 거리 d를 정한다.
- L3/L4/L5: 반주기/+1/6주기/−1/6주기 위상을 사용한다. 위성은 **현재 부모 위치+위상이 이동한 상대 궤도**로 계산하여 미래 부모의 평행 이동이 섞이지 않게 한다. 타원 궤도에서는 평균 위상 이동과 실제 중심각60°가 다를 수 있다.
- ID는 `sun-earth:L4`, `earth-moon:L2`. L4/L5 안정 여부 속성은 자리만 있고 효과가 없다.

| 쌍 | d(gAU) |
|---|---:|
| 태양–수성 | 5.4514 |
| 태양–금성 | 9.0857 |
| 태양–지구 | 12.22 |
| 태양–화성 | 12.35 |
| 태양–목성 | 50.7 |
| 태양–토성 | 76.7 |
| 태양–천왕성/해왕성 | 27.3 |

| 목성–이오/유로파 | 1.35 |
| 토성–엔켈라두스/타이탄 | 2.025 |

모든 점을 천체 여유·행성권 밖으로 보정하는 진단을 구현했다. 0/30/100/365/1,000일 **475개 실제 위치 검사에서 보정0건**이었고, 강제로 겹치게 만든 시험에서는 밀어내기 기록과 안전 여유를 확인했다.

마름모는 **이동 선택 중에만** 보인다. 항성계에서는 태양–행성40개, 행성 확대에서는 해당 위성 쌍으로 범위를 제한한다. 근접60gAU/키보드 포커스에서 이름을 보여준다. 화면의 천체가 작은 전체보기에서도 보이는 목표 마커를 먼저 판정하여 인접 천체의 클릭 보조 영역이 점을 빼앗지 않게 했다.

지정할 때 도착 위치를 예측하고, 도착 후 `holdingAt` ID로 점을 따라간다. 선회·충전 취소는 그 정위치 상태를 복구하며 순항 취소는 M1a의 행성권/허공 정지 규칙을 따른다. 일반 허공 지점과 구별한다.

## 자동 카메라와 표면 UI 보존

물리 행성권은 고정1.6R이며 줌 상태와 무관하다. 자동 카메라는 별도 순수 상태 모델이다. 임시 기준은 다음과 같다.

| 항목 | 값 |
|---|---:|
| 자동 진입/해제 거리 | 고궤도 반경×6 / ×7 |
| 중앙 진입/해제 오차 | 고궤도 반경×0.45 / ×0.8 |
| 고→중 / 중→저 / 저→표면 | 카메라 중심거리6R / 3.5R / 2R |
| 층 경계 히스테리시스 | 0.15R |
| 천체 주변 카메라 최소 | 1.2R |

고배속 위성은 한 프레임에 크게 움직일 수 있으므로 **기존 추종 천체의 평행 이동을 먼저 카메라에 적용하고 해제 경계를 판단**한다. 자동 추종은 선택/해제와 독립이며, 사용자가 팬/축소하면 해제된다. 작은 위성으로 직접 확대할 수 있도록 최소 줌도 화면 중심 천체에 맞춘다. 기존 포커스 버튼, 명시적 함선 확대, 전체 복귀 및 표면 모드는 유지한다.

한 층만 진하게, 바로 바깥 층은 희미하게 표시한다. 선은 기존 표면 렌더러처럼4분할해 작은 위성의 f2 표면 선이 천체 안으로 가라앉지 않게 한다. 이동 꼭짓점 수와 원본 격자는 바뀌지 않는다. 명시적 표면 모드에서는 궤도 미리보기·점 판정을 숨기고 기존 표면 ray/산업 섹터 선택을 우선한다.

브라우저의 pageerror·console error·HTTP 오류는 최종 M1b 전체 실행에서0건이다. 기존 회귀 스크립트의 산출물은 임시 작업 디렉터리에 생성하여 기존 공식 보고서/스크린샷을 덮어쓰지 않았다. 전체 단위 테스트에는 기존 경제 시뮬레이션 검증도 포함되며 경제 보정 실험이나 산출물 재생성은 하지 않았다.

최종 브라우저 재실행 중 표면 지도 초기화 대기 조건이 불충분한 시험 실패가2회 있었다. 버튼 직후의 `active`만 보던 조건을 실제 `entry`·표면 렌더러 준비 및 카메라 전환 완료까지 기다리고, 정수 픽셀 주변2px도 같은 셀에 속하는 내부 지점에서 클릭하도록 보완했다. 실패 로그도 [초기 실행](logs/browser-orbits-initial-failure.log)·[좌표 진단](logs/browser-orbits-click-boundary-failure.log)으로 보존하며 이를 제품 성공 결과에 포함하지 않는다.

## 임시 정책·남은 범위

표시 길이0.5, 전환3.0/3.7%, 저/중/고 배율1.05/1.3/1.6, 추진0.04gAU/분, 내부 여유1.02R, 기존 주파수 그대로, 표면 자전 추종, 가까운 점6개/층, 최대100,000탐색 상태, 줌 표의 수치, 라그랑주 계수와60gAU 이름 표시가 임시안이다. 모두 설정/데이터로 분리했다. L1/2 계수는 행성2/1.3/0.6, 위성0.1/2/0.45/0.45이며 밀어내기 여유0.001gAU·최대32회다.

함대는 계속 **탭 메모리 전용**이다. 새로고침·개발 캠페인/명시적 산업 JSON 적용·시험계 전환 초기화를 유지한다. 기존 산업v4 JSON과 구버전 이관을 변경하지 않았다. 공식 지질·인구·격자·궤도·게임AU·산업/SCU·경제 산출물도 바꾸지 않았다.

항법은 중심점 기반으로 선체 전체의 swept volume, 다른 함선·고리와의 물리 충돌을 계산하지 않는다. 특히 작은 위성보다 표시 함선이 클 수 있어 근접 외형이 겹치는 문제는 추가 표시/정박 설계가 필요하다. 이산 그래프 밖의 전역 연속 최단 경로나 모든 미래 사용자 정의 항성계의 최적 해를 보장하지 않는다.

행성/위성 자체 목표는 기존 접근측 고궤도 경계점, 명시적 궤도점 목표는 그 점을 유지한다. 표면 단계에서 산업 화면을 강제로 열지 않는다. 탐사·경제 값 연결·연구 런타임·화물 배송·전투/해적 방해·정거장/시설·건조·연료·다중 명령·호위·함선 저장은 이번에 구현하지 않았다.
