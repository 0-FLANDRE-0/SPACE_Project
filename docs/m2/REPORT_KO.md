## 구현된 흐름·조작

**PC·모바일 공통:** 함대에서 탐사함 선택 → 하단 **⌕** → 대략 탐사 / 정밀: 섹터 지정 / 정밀: 전체 스캔. 지원함의 탐사 버튼은 비활성이고 모델에서도 명령을 거부한다.

대략 탐사는 현재 행성권 안에서 진행한다. 새 탐사 명령은 현재 이동을 그 위치에서 중단하고 시작하며 순간이동하지 않는다. 정밀 명령은 섹터에 붙은 저궤도 꼭짓점으로 M1b 항법을 통해 이동한다. **저궤도 정지 조건을 충족한 시간만** 조사량으로 적립한다. 이동·다른 층·다른 섹터의 꼭짓점에서는 정밀 진행이 늘지 않는다.

**섹터 지정:** 이미 저궤도/표면 껍질을 보고 있다면 카메라를 유지한 채 그 껍질에서 직접 여러 구역을 클릭/터치한다. 다른 시점에서는 기존 표면 지도를 연다. 다시 누르면 해제한다. ‘탐사 확인’으로 공유 대기열에 추가한다. ‘← 취소’ 또는 PC **C/Escape**는 선택만 취소하고 새 명령을 내리지 않는다. 기존 표면 지도 버튼과 산업 구획 선택은 선택 모드 밖에서 계속 동작한다.

**협업:** 같은 천체에서 두 번째 탐사함도 전체 스캔/섹터 지정으로 합류시킨다. 탐사 메뉴의 함선 선택기로 표면 지도를 나가지 않고 명령할 수 있다. 메뉴 하단에 각 함선의 배정 섹터·진행·이동 상태를 표시한다. 단독 대기열은 가능성 높은 순→가까운 순이다. 복수 함선은 지시서의 협업 규칙에 따라 가장 가까운 미배정 섹터를 맡고, 미완료 섹터가 부족하면 같은 섹터에 합류한다. 여러 명령은 천체 공유 대기열에 중복 없이 추가되며 중단한 조사량은 남는다.

이동 명령·탐사 중단은 그 함선을 탐사에서 빼며 조사량을 보존한다. 실패한 이동 명령은 기존 탐사를 취소하지 않는다. 섹터/대략/대기열 완료를 알리고, **탐사 완료 시 일시정지**는 기본 꺼짐이다. 켜면 최초 완료 사건 시각에서 공통 게임 시계가 멈춘다.

## 지도·섹터 패널

상단의 기존 **탐사 섹터** 모드와 표면 분포 체계를 사용한다. 중복 탐사 지도 메뉴를 만들지 않았다. 탐사 섹터 모드에서 다른 분포를 선택하지 않으면 탐사 상태가 기본 겹쳐보기다. 매장량·인구·시설 분포는 기존 버튼으로 전환하고 같은 버튼을 다시 눌러 탐사 기본 보기로 돌아간다. 행정 모드에서는 탐사 기본 겹쳐보기를 숨긴다.

미탐사, 대략 탐사의 가능성 4단계, 정밀 배정/진행, 기본 정밀 완료, **현재 탐사 능력 기준 확인된 0**을 구별한다. 고단계/심부가 숨은 섹터에서 ‘확인된 0’은 현재 능력 범위의 결과이며 전체 지질이 비어 있다는 선언이 아니다.

탐사 정보는 기존 섹터 패널의 **왼쪽 정보 영역 상단**에 넣었다. 오른쪽 구획·월간 요약과 패널 크기를 유지한다. 확인 잔여량, 추정 **원래 총량** 범위, 품질 확률·신뢰도, 수소원 상태, 진행률과 게임/현실 예상 시간을 표시한다. 실제 채굴 잔여량과 원래 총량 추정을 구별한다. 큰 표시 수량은 만·억 단위로 반올림하며 내부 계산과 Q 단위는 바꾸지 않았다. 저궤도 직접 선택은 원본과 같은 격자의 임시 선택 껍질을 사용하며 원본 격자·천체 크기는 바꾸지 않는다. 취소/명령/종료 시 선택 뷰와 입력 후크를 해제한다. 내용은 왼쪽 영역 안에서 스크롤한다. 값 갱신은 기존 `patchDOM`을 재사용하여 읽거나 스크롤하는 노드를 매번 교체하지 않는다.

## 모델·시간·지식

`SurveyRuntime`은 DOM·실제 시계·저장소 없이 함대/카탈로그와 게임 초만 받는다. 천체별 대략 조사량과 섹터별 정밀 조사량을 **절대 작업량**으로 보존한다. 기술 속도는 남은 작업의 적립 속도에 적용하므로 기존 작업을 재계산하지 않는다. 같은 대상을 조사하는 함선 속도를 더한다.

도착·작업 완료·산업 시간 경계에서 시간을 나누어 처리하고 M1b 자동 이동의 다음 명령을 사건 시각에 발행한다. 실제 앱은 기존 ForegroundClock을 그대로 사용하며 함대·탐사·게임·산업의 단일 시계에 연결한다. 개발자 날짜 진행 버튼도 같은 조정자를 거친다. 숨김 탭/긴 대기 처리와 기존 배속 규칙은 그대로다.

예측 범위는 광맥별 결정적 시드 `세계 시드+depositId`에서 만든 u와 `w=1.5×(1−p)`를 사용한다. `[T×max(0,1−u·w), T×(1+(1−u)·w)]`는 실제값을 포함하며 진행할수록 좁아진다. 표층은 100%에서 확정하고 광맥은 유효 p를 상한으로 제한하여 범위가 남는다. 시작 확인율이 상한보다 높으면 그 시작값을 범위의 하한 지식으로 유지한다.

시작 지식이 없는 공개 가능 광맥도 총량의 넓은 추정 범위에는 포함하여 실제 총량이 범위 밖으로 빠지지 않게 한다. 탐지율이0인 개별 광맥의 ID·항목은 표시하지 않는다. 공개 단계 밖 광맥은 이 총량 범위에서도 제외한다.

확인율은 `max(시작 확인율, 종류별 상한×정밀 진행)`이다. **지구 시작 0.9/0.7**은 임시 광맥 상한0.6 때문에 낮아지지 않는다. 품질 신뢰도도 시작값에서 상한까지 올리고 천체 사전분포와 실제 품질 확률을 혼합한다. 빈 섹터의 Z 및 품질 사전분포는 공개 가능한 광맥만으로 계산하여 숨은 지질을 추가/변경해도 공개 결과·범위·개수가 변하지 않는다.

`discoveryTier > revealTier`와 미해금 심부는 플레이어 조회에 ID·개수·범위를 반환하지 않는다. 실제 지질·매장량 필드는 기존 개발자 전용 패널에만 남긴다. 정상 플레이 화면은 조사된 추정/확인값만 사용한다. 표층 100%에서 확정량이 실제 총량과 같아지는 것은 지시서대로다.

수소는 대략 탐사에서 천체 단위 가능성만 알리고 위치/개수는 공개하지 않는다. 해당 섹터 정밀50%에서 존재가 드러나고100%에서 확정한다. 달·화성처럼 데이터에 원천이 없는 곳에 원천을 생성하지 않는다.

## 산업·저장 보존

산업 상태 객체에 탐사 필드를 넣지 않았다. **WeakMap의 별도 메모리 지식 층**을 연결하고 자원 조회가 시작 지식과 M2 지식의 높은 값을 사용한다. 산업의 접근 가능량과 수소 인지가 새 층을 읽으며 기존 개발 픽스처의 명시적 원천/확인량은 유지한다.

`maximumDiscoveryTier=1`, `maximumDepth=25` 및 생산·비용·채굴/제련 공식은 바꾸지 않았다. M2에서 발견한 tier2 광맥은 표시되더라도 현재 채굴 단계 밖이라는 사유를 표시한다. 기존 산업 v4 JSON·검증·v1/v2/v3 이관은 바이트 단위로 보존한다. 수동 내보내기에는 함대/탐사 지식을 넣지 않으며 수동 산업 JSON 적용·캠페인/항성계 전환·새로고침에서는 새 탐사 세션을 만든다. 불러온 산업 실적은 보존하고, 재탐사 전 접근량이 모자라면 새 채굴을 제한한다.

기존 ECON 보존 테스트는 삭제하지 않았다. M2에서 실제로 수정이 필요한 `planetary-surface-ui.js`·`resource-knowledge.js`·`surface-distribution-ui.js` 3개만 역사적 변경 허용 목록에 추가하고 [M2 전용 엄격 보존 검사](../../scripts/m2-preserve.mjs)로 범위를 다시 제한했다. 경제 수치 단언·모델·설정·산출물은 변경하지 않았다.

M2 브라우저는 실제 메뉴·표면/저궤도 다중 섹터 선택·저궤도 카메라 유지·선택/토글·C취소·확인·두 척 대기열·품질 막대·0/50/100 범위·실제 배속 완료 자동정지·v4 수동 JSON 적용 시 탐사 초기화·새로고침 초기화를 검증했다. 최종 원문에서 pageerror·console error·HTTP 오류0건이다. 모바일 패널은 가로46% 너비/81% 높이 이내, 세로46% 높이 이내 검사(기존45%/80%/45% 목표의 반올림 여유)를 통과했고 지도 공간이 남는다. 기존 회귀의 출력은 임시 작업 디렉터리에 작성하여 과거 공식 보고서/스크린샷을 덮어쓰지 않았다.

재현 명령은 `npm test`, `npm run check`, `node scripts/m2-preserve.mjs`, `node scripts/m2-audit.mjs`다. 서버를 켠 뒤 Playwright 설치 환경에서 `node tests/browser-survey.mjs`를 실행한다. 필요하면 `PLAYWRIGHT_MODULE`, `CHROMIUM_EXECUTABLE`, `BASE_URL`을 환경에 맞춘다.

모든 브라우저 시험은 Chromium/SwiftShader다. 하드웨어 FPS나 실물 모바일/Safari 검증으로 보고하지 않는다. 화면 0/50/100 비교는 실제 UI로 명령한 뒤 순수 모델로 게임 시간을 정확히 진행시켜 촬영했고, 별도 단계에서 실제 HUD의8640×와 재개 버튼으로 다음 완료 자동정지를 검증했다. 시험 설정도 실제 M1b 항법으로 달에 도착하며 함선 순간이동·지질 변경은 사용하지 않았다.

저궤도 선택 전후 카메라 위치·target 차이를 1e−8 월드 이내로 검사한다. 엄격한 좌표 배열 일치 검사는 정상 부동소수점 반올림 차이를 실패로 보아 이 허용오차로 보완했다([원문](logs/browser-camera-roundoff-initial-failure.log)).

초기 UI 검증에서 주기적 전체 노드 교체가 품질 막대 스크롤을 방해하는 현상을 발견했다. 정보 영역을 기존 DOM 패치 방식으로 바꾸고 같은 상태의 불필요한 갱신을 생략했다. [최초 실패](logs/browser-quality-refresh-initial-failure.log)를 보존하며 최종 결과는 최종 실행 로그를 기준으로 한다.

| 임시 설정 | 적용값 |
|---|---|
| 기본 탐사 능력 | revealTier2 / 광맥 상한0.6 / 심부false / 속도1 |
| 대략 | √섹터수×1일×난이도1 |
| 정밀 | 섹터당4일×(1+terrainObstacle), 대략 미완료1.25배 |
| 대기/가스 추가 배율 | 각각1 |
| 예측 폭w0 / 빈 섹터Z | 1.5 / 공개 가능한 천체 평균 섹터 매장량 |
| 대략 탐지/범위 진행 상한 | 0.8 / 0.2 |
| 가능성 구간 | 범위 중앙값/Z의0.35·0.85·1.4 |
| 수소 존재 공개 / 확정 | 정밀0.5 / 1 |
| 좌표 판정 여유 / 완료 오차 | 1e−6 gAU / 1e−7 작업초 |
| 메모리 사건 기록 / 산업 시간 경계 | 최근160개 / 3,600게임초 |

이 값은 `survey-data.js`의 **SURVEY_TUNING**에 있다. M4는 함선 탐사 능력/속도와 공개 범위를 공급할 연결 지점이다. 새로운 센서 단계/심부 연구를 실제로 연결할 때에는 새 조사 층·추가 작업량 정책을 별도로 결정해야 하며 기존 완료 작업만으로 새 심부를 자동 확정하는 연구를 구현한 것으로 해석하지 않는다.

정밀 경로는 기존 이산 궤도 그래프를 사용하고 전역 연속 최단 경로를 보장하지 않는다. 경로 실패는 배정 상태에 중단 사유와 알림을 남기며 다른 미배정/완료 작업을 몰래 확정하지 않는다. 공식 지질의 가스 천체에는 현재 ore가 없을 수 있으며 수소 원천 데이터도 임의로 추가하지 않는다. 함선/탐사 저장, 심부, 연구 효과, 실제 물류와 경제 값 채택은 후속 범위다.
