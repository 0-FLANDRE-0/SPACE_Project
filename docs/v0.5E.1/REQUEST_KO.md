## 0. 이번 패치의 목표와 경계

**목표:** 행성 표면을 열면 상단에서 **알려진 매장량 / 인구 분포 / 시설 분포**의 세 가지 표시 모드를 선택할 수 있고, 실제 섹터를 누르면 **이동 가능한 소형 섹터 정보 탭**이 뜬다. 자원·인구는 섹터별 차이가 보이는 **검정 → 하늘색 단계별 색상**으로 표현한다. 지구의 초기 92섹터 인구는 근현대 지리적 인구 분포의 **실제 격자 자료 비율**을 이용해 재배분한다.

**이번 변경:**
1. 지구(`sol/earth`) 92개 표면 섹터의 `startingScenario.cells[tileId].populationPersons`만 현실의 최근 인구 공간 분포 비율로 **다시 배분**. 지구 총 인구 **8,893,000,000명 = 8,893 POP** 고정.
2. 일반 표면 지도 상단 **매장량(알려진) / 인구 / 시설** 3개 표시 모드 추가. 기존 개발자 전용 편집 버튼은 DEV 영역에서 계속 접근 가능하도록 재배치.
3. 인구·매장량의 **구간별 색상**, 검정=실제 0이 확인됨, 하늘색=최상위, 미확인/미설정=별도 회색. 모드별 작은 실제 수치 범례.
4. 표면 섹터 선택 → 기존 3영역 산업 정보 탭 유지, **탭 제목 부분을 마우스·터치로 드래그 이동**. 모바일에서는 지도 대부분이 보이도록 기존 크기 제한 유지.
5. 섹터 상세의 인구 표시를 **명수 대신 POP**로 통일(저장 숫자는 명수 정수 유지).
6. 기존 개발자 지질·자원 지도에서 확인된 **`log1p(value)/log1p(max)` 때문에 노란색에 몰리는 색상 문제도 보정**. 개발자 실제 원본 지도와 플레이어 인지 지도는 **서로 다른 데이터 접근**을 유지.
7. 지구 인구 재배분에 따른 기존 **산업 캠페인 저장·표면 로컬 초안**의 호환성 검증/보호.

**수정 금지:** 실제 지질·광맥 총량/배치/등급 확률·채굴/가공 난도·수소 원천, 원본 지구 `sources/earth-urban75-v1.json`, 격자/섹터 ID/지형/환경/천체 궤도·크기, 자원 19개 공식 프리셋의 인구 이외 부분, 2100 시작 시나리오의 인구 이외 필드. v0.5E 광업·제련 생산 공식·건설비·기간·슬롯 배치·재고/시간 계산·저장 정책은 바꾸지 않는다. 새로운 연구/전력/물류/민간/함선 시스템도 추가하지 않는다.

## 2. 지구 인구 분포 — 근현대 격자자료를 이용한 결정적 배분

### 2.1 출처·연도·확정/가정의 구분

- **우선 권장 공개 자료**: EU JRC **GHSL / GHS-POP R2023A**, **2025년(`E2025`)** 인구 수 격자. 2025년의 공간 분포를 **2026년 현재에 가까운 참고 비율**로 채택하는 것이며, 2100년 미래 인구 추정이나 사용자 확정 시나리오의 총인구를 대체하는 것이 아님.
  - 공식 설명: https://human-settlement.emergency.copernicus.eu/ghs_pop2023.php
  - 다운로드: https://human-settlement.emergency.copernicus.eu/download.php?ds=pop
  - DOI: https://doi.org/10.2905/2FF68A52-5B5B-4A22-8F40-C41DA8332CFE
  - 참조: 인구 **격자당 사람 수** 데이터이며, 일반적 밀도(명/km²)와 혼동하지 말 것. 재사용 시 출처 표기 필요.
- 동일 방법으로 이용 가능한 대안: **WorldPop Global2 R2025A**의 연도별 글로벌/국가별 인구 격자(https://hub.worldpop.org/project/categories?id=3). **두 자료를 혼합하지 말고**, 어떤 단일 제품/시점/해상도를 사용했는지 남길 것.
- **실제 원천 데이터를 다운로드·읽어 검증하지 못했다면**, 국가별 비중이나 섹터별 인구를 상상으로 작성하지 말 것. 인구 재배분 작업은 명시적으로 `자료 미확보`로 보고하고, 독립적인 UI 변경만 제출 가능.
- 저장할 출처 메타정보: 제품명, 버전, 기준 연도, 공간 해상도, 좌표계, 취득 URL/일자, 라이선스, 원본 체크섬, 재배분 스크립트/명령, 생성 산출물 체크섬. 실제 고해상도 원본 GeoTIFF 전체를 게임 런타임에 포함할 필요는 없음.

### 2.2 92개 표면 셀에 매핑

1. **고정된 지구 92섹터**를 `createPlanetarySurfaceGrid('sol', earth)`에서 얻는다. `tile.id`, `center`, `boundary`, `areaWeight`, `latitudeDegrees`, `longitudeDegrees`, `gridFingerprint`를 **그대로 사용**한다. 섹터/격자 재생성이나 수동 ID 치환 금지.
2. 선택한 인구 래스터(GHSL 등)의 **셀당 인구수**를 읽고, 원본 지도 좌표계를 명시적으로 확인/변환한다. 재투영·결측치/해양/타일 경계·180° 경도 절단·극지 처리에 주의할 것. 현재 격자는 로컬 **+Y 북극, +X 경도 0°, -Z 동쪽**이며 `longitudeDegrees = atan2(-center.z,center.x)`임.
3. 각 래스터 픽셀을 정확히 한 섹터에 배정하거나, 경계에 걸친 셀은 면적에 비례해 배분한다. **위도/경도 단순 거리로 가장 가까운 섹터를 찍는 방법보다 실제 구면 다각형 포함 판정**을 우선하고, 구체적 매핑 알고리즘은 결정적·검증 가능해야 함. 격자 원본 좌표·투영변환·픽셀 크기/면적 차이를 무시한 임의 재산정 금지.
4. 섹터 가중치 `w[tileId] = 그 섹터에 들어간 인구 자료상의 사람 수 합계`를 구한다. **해당 섹터의 면적 가중치를 한 번 더 곱하지 말 것**(이미 격자별 인구수 합산 값임). 원본이 인구 밀도라면 먼저 픽셀 면적을 반영하여 사람 수로 바꾼다.
5. 총인구 **정확히 8,893,000,000명**을 섹터별 비율 `w / Σw`로 정규화·배분한다. 각 섹터는 음수 없는 안전 정수 명수. 반올림은 **최대 잔여 방식(largest remainder)**으로 수행하고, 동률은 **섹터 ID 오름차순**으로 처리해 합계가 정확히 일치해야 함. 섹터 수 92, ID·지리 기반 셀 다각형은 절대 변경하지 않는다.
6. `startingScenario.cells[tileId].populationPersons`만 교체. `urbanizationRate`, `infrastructureLevel`, 정부/문명/통치 필드, `knowledge`, `facilities`, `geology`/`hydrogenSources`/`resourceConfiguration`/`initialResourceKnowledge` 및 그 외 필드는 **그대로**. 새 분포가 기존 도시화율과 어긋날 여지가 있으면 **후속 결정으로 보고만 하고 자동으로 도시화율을 수정하지 않는다**.
7. 원본 고정 프리셋을 재생성하는 `scripts/generate-sol-presets.mjs`와 호환되도록 **결정적 재배분 단계/재현용 소형 `tileId -> weight/population` 산출물**을 추가한다. 기존 공식 프리셋을 손으로 고쳐놓고 재생성하면 되돌아가는 상태는 불합격. 원본 19개 중 지구의 허용된 인구 필드 외에는 바이트/구조가 변하지 않도록 검사한다.
8. 출처와 2100 가정이 명시된 `docs/v0.5E.1/POPULATION_SOURCE.md` 및 전/후 비교(최대 섹터, 상위 집적지역, 0 인구 구역, 합계 등)를 제출한다. **지역별 대략적 현실성은 지도에서 직접 시각 검수**하고 수치 검증만으로 종료하지 않는다.

### 2.3 사용자 로컬 원본 보호

- 사용자가 보유한 기존 `space-project:surface:v1:sol:earth` 로컬 v1/v2 초안이 정적 공식 프리셋보다 우선한다는 정책 유지. 업데이트 시 **자동 덮어쓰기 금지**.
- 로컬 지구 초안이 존재하면 “새 공식 인구 배분 사용 가능”이라고 알리되, **인구만 반영하는 명시적 미리보기·백업·확인** 절차를 제공하거나 변경 전/후 비교 및 원본 파일 내보내기로 동일한 안전 절차를 제공한다.
- 다른 행성, 다른 사용자가 손수 만든 지구 광맥/환경/시설/인지 데이터의 변경 금지.

## 3. 표면 지도 상단 — 일반 플레이어 버튼 세 가지

`#surface-toolbar`에 **① `매장량(알려진)` ② `인구 분포` ③ `시설 분포`** 세 가지 표시 버튼을 둔다. **뒤로가기**(`← 항성계 지도`)와 천체 이름/식별 정보는 남기되, 이것들은 분포 모드 버튼으로 세지 않는다.

- **세 버튼은 단일 선택**: 한 번에 하나의 분포 레이어만 활성화. 이미 활성화된 버튼을 다시 누르면 **모두 꺼진 기본 표면 지도**로 복귀(별도 네 번째 버튼 불필요).
- 표면 지도로 처음 진입하면 **기본 지도(분포 레이어 없음)**를 표시. 섹터 클릭은 모드에 상관없이 가능.
- 지도 위의 선택 섹터 강조/테두리, 카메라 조작, 표면 셀 픽킹과 기존 3D 표면 지오메트리는 유지. 모드 변경이 선택한 섹터나 건설 작업을 취소해서는 안 됨.
- 기존 `자원 원본`, `행성 자동 설정`, `표면 편집`, `JSON` 등 **개발자 전용 버튼·기능을 삭제하지 말고 DEV 패널 안으로 이동/접근 경로 보존**. 일반 모드에는 원본/시드/숨겨진 광맥 정보가 노출되면 안 됨. 실제 개발자 원본 분포 지도와 일반 `알려진 매장량` 지도는 완전히 구분.
- 개발자 지도 편집/미리보기가 활성화될 때 일반 분포 레이어와 색 버퍼가 충돌하지 않도록 **표시 소유권/우선순위**를 중앙에서 관리. DEV 뷰를 닫으면 원래 일반 모드로 정상 복귀. 모드별 색 버퍼는 섹터 데이터/인지/인구/시설 갱신 시 또는 버튼 전환 시 갱신하고 **매 프레임 재생성하지 않는다**.
- 3D 표면 지도 상단 HUD 및 기존 HUD와 겹치지 않도록 배치. 모바일 가로/세로는 좁은 버튼·아이콘/짧은 텍스트 사용 가능하나 터치 영역은 보존.

## 4. 공통 색상 설계와 범례

| 양수 2단계 | `#245B85` | 적음 |
| 양수 3단계 | `#328BB5` | 보통 |
| 양수 4단계 | `#4DB9DA` | 많음 |
| 양수 5단계 | `#99E7FF` | 가장 풍부함 |
| 미확인·미설정 | `#626A77` | 아직 알 수 없음 (`null`/조사 불충분) |

- 같은 행성의 해당 모드에서 **양수인 알려진 섹터 값들의 분위수**를 기준으로 5개 등급을 만드는 방식을 기본으로 한다(예 20/40/60/80 분위). 실제 경계값은 행성·모드별 데이터에서 계산하고 **범례에 수치(`U`, `POP`)로 표시**. 이 5개 구간은 **행성 내 상대 순위**로, 행성 간 절대량을 비교하는 색이 아님을 `행성 내 상대 분포`로 명시.
- **동일한 수치를 색으로 억지 분리하지 않는다.** 양수 섹터가 5개 미만/값 종류가 적음/전부 같은 값/전부 0/전부 미확인/극단적 이상치인 경우에도 안정적으로 작동. 동률은 하나의 등급; 가능 단계가 적으면 실제 사용한 단계만 범례에 표시. NaN/Infinity, 빈 분위 구간 금지.
- 색으로만 의존하지 않도록 범례와 선택 섹터 정보창에 **실제 수치·상태 라벨** 제공. 검정(확인 0)과 회색(미확인)을 엄격히 구분. 기본 지형 텍스처 위의 버텍스 컬러 오버레이가 불투명도 때문에 모두 노랗거나 검정이 회색으로 보이지 않도록 합성/투명도 조정; 선택 테두리 가독성은 유지.
- **현행 개발자 자원 지도** `log1p(v)/log1p(max)`의 색상 몰림도 동일한 대비 개선 원칙으로 수정하되, 원본 수량 지도인지 품질·난도(0–100 또는 0–1) 지도인지에 따라 **정규화 종류를 구분**할 것. 품질/난도는 의미 있는 절대 스케일/범례로 표시하고, 매장량에만 상대량/분위수를 적용. 기존 고품질·연결 광맥·발견 지도 기능 유지.

### 4.2 매장량(알려진) 모드 — 정보 누출 방지 최우선

- 플레이어용 기본값은 **그 문명이 인지·확인한 섹터별 광석량**임. `initialResourceKnowledge`의 확인 비율과, 산업 런타임이 별도로 확인·소모한 양을 **공용 인지 질의 함수**로 일관되게 통합해 사용한다. 실제 `geology.cells[].deposits[].initialReserveU` 총량을 UI에 직접 쓰거나, 숨은 매장량을 전체 색상 스케일 산출에 포함하면 **불합격**.
- 가동 중 채굴로 확인량이 줄어들면 “현재 알려진/확인된 잔여량”이 갱신되도록 하되, 확인되지 않은 숨은 잔량을 역산해 공개하지 않는다. 이미 레포에 존재하는 `accessibleDeposits`의 인지·잔량 조건을 참고할 수 있지만, 시설 건설 자격과 지도 표시는 다른 목적이므로 필요시 읽기 전용 인지 집계 함수를 마련한다.
- **중요:** 현재 코드에서 `depositKnowledgeFor()`가 매장지를 반환하지 않는 사실은 “거기 자원이 0”의 증명이 아님. 또한 **탐사 티어 조사 100%도 전체 매장지 발견 100%를 뜻하지 않는 기존 계약**을 유지한다. 별도 **'없음 확인'(negative survey evidence)**이 없는 한 무인지 섹터는 검정이 아닌 **회색(미확인)**으로 표시한다. `confirmedU=0`이 단순 초기 미탐지라면 검정 처리 금지. 확인된 0을 안전하게 판정할 수 없는 현행 스키마에서는 해당 상태를 회색으로 두고, 음성 조사 기록은 탐사 시스템의 향후 확장 포인트로 남겨도 됨.
- 섹터 표시 수치와 색/범례에 사용된 수치는 **동일한 인지 집계값**이어야 함. 개발자 전용 스위치가 켜진 경우에만 진짜 지질 데이터를 표시하며 명시적 배지 `개발자 원본`을 붙인다.

### 4.3 인구 분포 모드

- 지구의 새 `populationPersons`와 각 행성·위성의 현재 `startingScenario`/진행 중 인구 상태(있다면 우선)를 사용한다. 기존 파일의 값 `null`은 미설정(회색), 명시적 `0`은 검정, 양수는 양수 5분위 색. 지구 이외 천체에 인구 데이터를 새로 생성하지 않는다.
- **1 POP = 1,000,000명**. UI는 `personsToPOP()`으로 표시하고 실제 저장값은 사람 수 정수 유지. 작은 양수 인구가 `0 POP`로 둔갑하지 않게 적절한 자리수(예 소수 6자리까지) 또는 작은 값 표시 보정. 0과 null 구분.
- `dist/src/industry-ui.js`의 섹터 일반 정보 인구 `...명` 표시를 `... POP`로 변경. 개발자용 기존 POP 편집/전체 인구 합계도 회귀 테스트.

### 4.4 시설 분포 모드

- **실제 건설된/건설 중인 정부 시설의 런타임 상태**(`industry state.facilityInstances`, 섹터/시설 ID)를 우선 소스로 사용. `governmentSlots`의 빈칸/잠긴 칸은 시설이 아님. `startingScenario.cells[].facilities`는 기존대로 **초기 메타데이터**이므로 실제 건설 시설과 혼합하지 않는다. 기존 시작 메타데이터를 실제 시설로 인정할 명시적 매핑이 없다면 지도에 임의 표시하지 않는다.
- 예시: 건설 중=노랑 점선 윤곽, 완공/가동=하늘색/녹색 외곽, 정지/고갈=어두운 윤곽, 시설 없는 섹터=기본 지도/낮은 강조. 색만으로 상태를 판단시키지 말고 섹터 클릭 시 아이콘·시설명·상태 확인.
- 정부 시설이 여러 개인 섹터는 해당 섹터를 한 번만 강조하고, 정확한 수량과 종류는 섹터 정보 탭에서 확인. 향후 민간 시설은 별도 소유권 규칙이 확정되기 전 자동 포함하지 않는다.

## 5. 이동 가능한 섹터 정보 탭 — 기존 작은 패널과 3영역 유지

- `#surface-info.industry-card`의 **상단 제목바(`.surface-card-heading`)의 빈 드래그 영역**을 마우스·터치로 잡아 이동한다. 기존 본문(좌측 상세 스크롤), 우측 육각 건설구획, 우측 하단 월 생산/소비/재고, X 닫기, 내부 버튼은 유지.
- **클릭과 드래그 구분:** 예컨대 6~8px 이상 움직였을 때만 드래그로 판정. `pointerdown/move/up/cancel`, pointer capture 사용, 드래그 중 텍스트 선택·지도 회전/패닝 방지. 제목의 X·버튼·링크에서는 드래그 시작 금지. 드래그 가능 영역만 `touch-action:none`; 정보 본문의 `touch-action:pan-y` 및 정상 스크롤 보존.
- 탭 위치는 **현재 뷰포트/안전영역 안으로 제한(clamp)**하고 모바일 상단 HUD/하단 시간바와 가급적 겹치지 않게 보정. 화면 회전·리사이즈·전체화면 진입/해제 시 위치 재보정. 도중에 지도 바깥으로 패널이 사라지는 상황 금지.
- 동일 행성의 섹터를 바꿔도 패널 이동 위치를 유지. 패널을 닫거나 다시 열 때에는 직전 세션 위치를 유지해도 되지만, **위치 초기화 기능**과 기본 위치 복구를 제공. 별도 영구 저장은 필수 아님.
- PC 기존 크기 기본값 유지. **모바일 가로에서는 대략 화면 너비 45% 이내**, 세로에서는 높이 **45% 이내**라는 기존 합의 유지. 탭이 너무 작다고 **전체 화면으로 자동 확장 금지**. 지도 본체가 눈에 보여야 함. 정보가 길면 좌측 내부만 스크롤. 기존 `667×375`, `844×390`, `390×844` 지원.
- 탭 내부 상호작용이 지도에 누출되지 않되, 탭 바깥 지도는 카메라 이동·섹터 선택 계속 가능. 분포 모드 전환 후에도 패널/선택 상태 동기화.

## 6. 기존 데이터·게임 기능 보존

- **지질과 생산**: `initialReserveU`, 품질 확률, 매장 그룹/섹터 분포, 14/33/52% 제련 수율, 광업 수소 부산물 최대 100U/월, 수소 보조 제련 +15%, 건설/증설/개량 비용, 시간, 월 정산 로직을 변경하지 않는다.

- **세계 시계/HUD**: 시간속도·일시정지·산업 고정 틱·선택/카메라·개발자 권한·HUD 위치/행정 지도 기능을 보존.

## 7. **필수: 산업 저장 서명 호환 / 원본 안전 이관**

현재 `templateSignature(template)`는 인구까지 포함한 전체 템플릿으로 서명을 만들며, 산업 저장은 `sourceSignatures`가 새 카탈로그와 다르면 로드를 거부한다. 따라서 지구 인구 필드만 변경할 때도 기존 v0.5E 저장이 격리될 수 있다.

- 인구 업데이트 전/후 **서명 변화가 있는 것을 테스트로 재현**한 다음, 단순히 서명 검사를 해제하는 식으로 해결하지 말 것.
- 새 서명 정책을 설계한다면 **지질·매장량·수소 원천·섹터 ID/격자·소유권·시설 참조 등 산업 운영에 영향을 주는 자료의 무결성** 검사는 그대로 보존. `startingScenario.cells[].populationPersons`만 달라진 **검증 가능한 버전 전환**을 특별 취급. (관련 새 스키마/마이그레이션 버전 도입 시 엄격히 명시.)
- **이전 공식 Earth 스냅샷/서명과 새 공식 Earth 스냅샷/서명을 특정해서** 허용된 92개의 인구 필드 외 변경이 없음을 검증하고, 기존 산업 세이브를 **원본 백업 후 1회 안전 이관**. 다른 천체 서명 불일치, 사용자가 수정한 지질/매장/시설 데이터 불일치, 알 수 없는 스키마는 이전 정책대로 **격리·경고·복구 가능**해야 함.
- 이관은 기존 시설 ID·슬롯·광석 채굴 잔량·수소 잔량·재고·생산 기록·게임 시간·개발 fixture/정식 분리를 **비트 단위 논리값으로 유지**해야 한다. 재고 재초기화, 시설 제거, 재정 재지급, 생산 중복 정산 금지.
- 사용자 로컬 표면 초안이 공식 정적 프리셋을 덮어쓰고 있다면 자동 변경 금지. 인구 업데이트 적용은 **명시적 동의+비교+백업** 또는 적용 가능한 안전 수동 절차를 안내.

## 8. 검증 절차와 제출물

### 8.1 기능 시험

1. **인구 재배분 정확성**: 지구 92개 ID 그대로, 합계 **8,893,000,000명** 정확히 일치, 모든 `populationPersons`가 0 이상의 정수. 2025 분포 기반으로 아시아 고밀도 권역 등 실제 인구 집중이 대략 드러나는지 시각 검토. 기존/신규 가중치와 변화 보고서. 지구 `geology` 및 관련 확정 필드 JSON deep-equal, 지구 외 18개 프리셋 바이트 불변.
2. **정적 재현성**: 고정 출처·정해진 입력/동률 정책에서 재배분 산출물 바이트가 반복 실행 시 동일. 재생성 스크립트 실행 시 새 분포 재반영. 외부 인터넷/GeoTIFF가 없는 게임 런타임에서도 정상 플레이.
3. **사용자 로컬 초안**: 로컬 지구 초안 우선순위 보존, 승인 없는 인구 덮어쓰기 없음, 원본 JSON 백업·미리보기·복구 가능.
4. **매장량 플레이어 지도**: 문명에서 확인한 값만 색상·범례에 사용. 미확인만 있는 셀은 회색, 실제 0이 조사로 확인된 셀만 검정, 높은 양수 셀은 하늘색. 은닉 광맥 값·실제 최대값이 색상/범례/건설 금지 이유로 누설되지 않음.
5. **인구 지도**: `0` 검정, `null` 회색, 양수는 검정~하늘색 상향 5구간. 92섹터 간 유의미한 색상 차이, 숫자 범례 및 `POP` 환산 정확. 다른 행성은 값 없으면 미설정 유지.
6. **색상 경계**: 양수 섹터 0/1/2/5개, 전부 같은 값, 극단적 이상치, 동률·NaN·Infinity·음수·대량 매장지에서도 안정. 양수 섹터가 충분히 다양하면 4~5단계가 실제로 구분되어 표시. `log1p(v)/log1p(max)`의 원래 '전역 노란색' 현상 재발 방지.
7. **시설 강조**: 시설 0개·1개·복수, `construction`/`rampup`/`active`/`stopped` 구별. 슬롯 빈칸/잠김을 시설로 오인하지 않음. 모드 변경 중 생산·기존 시설 상태 불변.
8. **모드 우선순위**: 개발자 전용 지질 지도 열기/닫기, 행성 변경, 표면 진입/종료, 파일 편집/미리보기, 일반 분포 지도 재진입을 반복해 색상 레이어 잔상·메모리/이벤트 누수 0.
9. **드래그 이동**: PC 마우스·모바일 터치 제목바 이동, 버튼/X 클릭과 충돌 없음, 내부 스크롤 유지, 패널 바깥 지도 조작 가능. 섹터 전환·줌·기기 회전·리사이즈·전체화면 토글 후 화면 밖 패널 0.
