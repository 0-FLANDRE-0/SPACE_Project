## 1. 작업 범위 / 하지 않을 것

### 이번에 완성해야 할 것

- 자원 종류의 기본 정의: `ore`(광석), `alloy`(합금), `hydrogen`(수소), `credits`(크레딧). **1 U=10톤**, Credits는 C이며 U가 아니다. 자연에 합금·크레딧 매장지를 만들지 않는다.
- 광석은 **실제 총량이 있는 단일 원천 자원**이다. 저·중·고품질별 매장량을 생성 시점에 미리 나누지 않는다. **채굴 시 확률적으로 품질 등급이 정해지는 모델**을 구축한다.
- 광석 매장 형태: `surface`(표면 전역형), `vein`(여러 섹터를 잇는 광맥형), `deep`(심층 매장형). 향후 `concentrated`(집중형) 등 확장 가능한 레지스트리 설계. 당장 이번 태양계 확정 배분에는 위 3형이 기준이다.
- 행성 유형·행성 시드·매장지 시드·매장 형태·광산/선광 기술에 따른 **품질 확률**의 공용 계산기와 결정적 시험용 품질 추첨기.
- **하나의 매장 형태 안에서도 각 섹터/광맥의 품질 확률을 조금씩 다르게** 하되, **매장량 가중평균을 내면 행성별·매장형별 사용자가 정한 기본 확률이 유지되는 생성**.
- 발견되지 않은 자원과 문명별 탐지·확인 정보를 구분하는 공용 모델. 개발자 화면과 일반 플레이 화면에서 노출 제어.
- 태양계 **행성 8개 + 위성 11개 = 19개**의 기본 데이터 파일 생성, manifest 등록, 다른 브라우저의 새 로컬 상태에서도 자동 로드되도록 완성.
- 지구·금성·화성·달의 확정 배분/품질값 반영; 나머지 천체는 합리적 **잠정 게임 밸런스 데이터**를 고정 시드로 생성. 일단 생성한 태양계 공식 프리셋은 게임 실행 때 재추첨하지 않는다.
- 개발자 UI에서 행성 전체 매장량, 매장형 비율, 기본 품질 확률, 시드, 개별 매장지, 공개/발견 상태를 확인·편집/재생성 미리보기·JSON 입출력 가능하도록 확장. 작은 모바일 화면에서도 접근할 수 있게 한다.
- 같은 공용 생성기를 **랜덤 항성계**가 호출할 수 있도록 별도 API 제공: 고정 예산이 없으면 시드별로 **총량 자체도 변하고**, 품질·형태·위치도 변한다.
- 미래 테라포밍, 자원 채굴, 정부/민간 시장이 추가되더라도 원본 매장지와 런타임 변화가 뒤섞이지 않도록 데이터 소유권 분리.

### 이번에 구현하지 않는 것

- 실제 광산/제련소의 건설·운영, 시간당 생산, 수익·지출, 보급, 민간 시장, 행성 간 수송, 함선 연료 소비, 연구 트리/UI, 탐사함의 작업 타이머, 오프라인 생산 정산, 테라포밍, 전투.
- 희귀 전략자원의 실제 부산물 추출/경제 투입. **고품질 광석에서 특정 전략자원이 회수될 가능성은 미래 확장 규칙으로만 준비**하며 이번에 임의 신규 전략자원 수십 가지를 만들거나 생산하지 않는다.
- **아스트로지늄(Astrogenium)**: 매우 희귀한 우주 공간의 특수 드라이브 연료라는 *예정 설정*만 문서화. 이번에 산출/소비/태양계 표면 매장지로 생성하지 않는다. 구체적 항행 소비율 확정 금지.
- 소행성대 자체는 기존 `belt`가 표면 격자를 갖지 않으므로, 이번 표면 19개 기본 프리셋과 동일한 셀에 억지로 매핑하지 않는다. 향후 소행성/우주 광맥 객체로 재사용 가능한 생성 인터페이스만 남긴다.

## 2. 절대로 변경하면 안 되는 경제·질량 계약

- 광석 총매장량은 `initialReserveU`를 기준으로 계산. 품질별 총매장량은 별도 확정하지 않는다.
- 기술·품질 확률·탐사 수준이 바뀌어도 **지질학적 총매장량은 바뀌지 않는다**. 탐사로 늘어나는 것은 '알려진 매장량', 채굴로 줄어드는 것은 미래 `remainingReserveU`이다.
- 채굴된 1 U의 광석은 저·중·고품질 산출량 **합계 1 U**가 되어야 한다(선별 폐기물이 있다면 명시적으로 별도 질량 손실 처리). 등급 판정 자체가 자원을 생성하거나 복제하지 않는다.
- **초기 기술 제련 기준 합금 수율**은 정확히 다음과 같다:

  | 등급 | 광석 1 U → 합금 U | 백분율 |
  |---|---:|---:|
  | 저품질 (`low`) | **0.14** | 14% |
  | 중품질 (`medium`) | **0.33** | 33% |
  | 고품질 (`high`) | **0.52** | 52% |

- 제련 기술이 발전하면 향상 가능하지만, 발전 단계와 공식은 임시 확장 가능 함수로만 작성한다. 합금 수율 1.0 초과, 음수, 물질의 무근거한 생성 금지. 잔여 질량은 폐석·부산물 등으로 설명 가능해야 한다.
- 품질 확률을 바꾸는 채굴/선광 기술과, 등급당 합금 수율을 바꾸는 제련 기술은 **서로 다른 입력**이다. 기술이 광석 원래의 확률이나 원래 매장량을 고쳐서는 안 된다.
- 희귀 부산물은 나중에 *특정 성분을 함유한 광맥 + 고품질 채굴 + 전용 정제 기술* 등이 모두 맞을 때만 회수하도록 확장. 어떤 고품질 광석에서나 전략자원이 무조건 나오지 않게 한다.

## 3. 네 천체의 확정 총매장량과 매장 형태별 예산 — 수치 강제 검사

> '억 U'의 단위 변환을 절대 틀리지 말 것. 저장과 검증은 U 또는 더 작은 정수 quanta로 계산한다. 현재 v0.5C는 0.001 U 정수 quanta를 사용하므로 유지하는 편이 좋다.

| 천체 ID | 행성/위성 | 총 ore (U) | 표면 전역형 | 광맥형 | 심층형 |
|---|---|---:|---:|---:|---:|
| `sol:earth` | 지구 | **78,600,000,000** (786억) | 25% = **19,650,000,000** | 65% = **51,090,000,000** | 10% = **7,860,000,000** |
| `sol:venus` | 금성 | **114,200,000,000** (1,142억) | 38% = **43,396,000,000** | 12% = **13,704,000,000** | 50% = **57,100,000,000** |
| `sol:mars` | 화성 | **48,900,000,000** (489억) | 70% = **34,230,000,000** | 20% = **9,780,000,000** | 10% = **4,890,000,000** |
| `sol:moon` | 달 | **100,000,000,000** (1,000억) | **100% = 100,000,000,000** | **0** | **0** |

**위 수치는 확정 계약이다.** 시드가 달라지더라도 이 네 천체의 공식 프리셋 총량과 매장 형태별 예산은 바뀌지 않는다. 시드는 **어디에/어떤 크기의 매장지가 생기는지, 개별 품질 편차**를 바꿀 수 있다. 개발자 모드에서 명시적으로 예산을 수정한 *새 대안 시나리오*는 허용하되, 별도 프리셋으로 저장하고 공식 시작 설정을 몰래 바꾸지 않는다.

### 중요: 지구 기존 파일 재배분, 추가 매장 금지

- 첨부된 지구 `SPACE_surface_sol_earth_schema1_urban75.json`은 **92섹터, 기존 ore 총 78,300,000,000 U (783억)**, **인구 8,893,000,000명**, 인구 가중 도시화율 약 **75%**이다.
- 새로운 공식 786억 U는 기존 783억에 새로운 786억을 **더하라는 뜻이 절대 아니다**. 기존 ore 매장 기록은 초기 재배분을 위한 가중치/참고값으로만 사용한 뒤, 최종 광석 단일 원천을 786억 U로 다시 나눈다. **목표 대비 순증은 300,000,000 U (3억 U)**이다.
- 원본 JSON의 지형, 면적, 환경, 인구, 도시화, 기반시설, 수동 편집, 셀 ID, 표면 fingerprint, `startingScenario`를 보존한다. 불필요한 필드를 0으로 초기화하지 말고, `null`/0/빈 배열을 구분한다.
- 원본을 파일로 별도 보관하고 SHA-256을 기록한 다음, 사용자 지정 매장 비율과 광맥 배치의 적용 결과를 명확한 diff로 보고한다. 원본 오염/기존 브라우저 초안 자동 덮어쓰기 금지.

### 달·화성 2100년 시작 식민지

- 달과 화성의 식민지 인구는 각각 **표면 섹터 하나에 집중**시킨다. 다른 섹터의 초기 인구는 0 또는 명확한 미설정 정책에 따라 처리; 시작 문명의 소유/인지 상태와 실제 지질 원본은 구분한다.
- 사용자 확정 수치는 **총인구 숫자가 아니라 '한 섹터에 집중'이라는 배치 원칙**이다. 총 POP와 정확한 식민지 위치가 아직 미확정이므로 기존 자료가 있다면 보존하고, 없다면 별도 `provisionalScenario`에 조정 가능한 임시치로 설정·보고한다. 임시 예시가 필요하면 달 0.2 POP, 화성 0.05 POP를 사용할 수 있으나 확정값이라 주장하지 않는다. 시작 시나리오에 들어가는 숫자는 명확하게 '임시'라고 표기한다.

## 4. 행성별 **매장 형태의 기본 품질 확률** — 확정값

> 순서는 항상 `[저품질, 중품질, 고품질]`. 값은 **매장 형태별, 그 형태에 속한 전체 광석의 매장량 가중평균으로 정의되는 기본 산출 확률**이다. **개별 섹터/광맥의 확률은 이 숫자와 조금씩 달라야 한다.**

### 지구 `sol:earth` — 확정

| 매장 형태 | 저품질 | 중품질 | 고품질 |
|---|---:|---:|---:|
| 표면 전역형 `surface` | **60%** | **38%** | **2%** |
| 광맥형 `vein` | **45%** | **50%** | **5%** |
| 심층형 `deep` | **23%** | **44%** | **33%** |

지구 전체 기본 품질 기대 확률은 매장 형태별 총량 가중으로 **저 46.55% / 중 46.40% / 고 7.05%**. 초기 기술의 기대 합금 수율은 **0.25495 U alloy / 1 U ore**. 고품질 실제 총량을 별도로 확정 저장하지 말 것: 이것은 확률적 기대값이다.

### 금성 `sol:venus` — 확정

| 매장 형태 | 저품질 | 중품질 | 고품질 |
|---|---:|---:|---:|
| 표면 전역형 `surface` | **33%** | **42%** | **25%** |
| 광맥형 `vein` | **8%** | **22%** | **70%** |
| 심층형 `deep` | **1%** | **17%** | **82%** |

금성 전체 기본 품질 기대 확률 **저 14.00% / 중 27.10% / 고 58.90%**. 초기 기술 기대 합금 수율 **0.41531 U / 1 U ore**. 단, 높은 품질은 낮은 생산비를 뜻하지 않는다. 금성의 극한 고온·고압·부식 환경과 심부 접근 비용은 별도의 채굴/시설 난이도로 불리하게 반영한다. 즉 **매우 좋은 광석이 많지만 실제 개발은 어려운 행성**.

### 화성 `sol:mars` — 일부 확정·일부 임시

- **확정:** 표면 전역형은 저·중품질 위주이며 고품질 산출 확률은 지구 표면형(2%)보다 **약간 높다**. 광맥형과 심층형은 **해당 지구 매장 형태보다 고품질 확률이 더 높다**. 전체 매장량 및 70/20/10 배분은 3절 확정값.
- **미확정:** 저/중/고 세 숫자의 정확한 조합. Codex가 필수로 넣어야 한다면 설정 파일에 '*잠정 제안*'이라고 명시하여, 예를 들어 아래처럼 시작할 수 있다.

| 형태 | 저 | 중 | 고 | 확정 여부 |
|---|---:|---:|---:|---|
| 표면 | 55% | 40% | 5% | **임시** |
| 광맥 | 28% | 42% | 30% | **임시** |
| 심층 | 15% | 35% | 50% | **임시** |

- 화성 표면을 고품질 20%로 무단 확정하지 말 것. 유저는 '지구보다 약간 높은 정도'라고 했다. 모든 수치는 행성 프로필 편집 UI에서 재설정 가능해야 한다.

### 달 `sol:moon` — 일부 확정·일부 임시

- **확정:** 광석 1,000억 U가 전부 표면 전역형이고 **저품질 산출 확률이 80%**. 광맥형/심층형은 0. 원료량이 방대하지만 **가공 난도가 높은** 특징을 가진다.
- 중품질/고품질의 나머지 20%는 **미확정**. 필요한 임시 기본값으로 중품질 17% / 고품질 3%를 사용할 수 있지만 **절대 사용자 확정값으로 소개하지 말 것**. 옵션으로 조정 가능해야 한다.
- 달의 높은 가공 난도는 품질 확률 이외의 `processingDifficulty` 또는 별도 전처리 비용 계수로 구현. 기본 수율 0.14/0.33/0.52 자체를 달 전용으로 멋대로 바꾸지 않는다. 가공 난도와 광석 품질을 중복 불이익으로 계산하는 방식은 명시적으로 구분·문서화한다.

### 나머지 행성과 위성

- 수성·기타 고체 행성과 포보스·데이모스·이오·유로파·가니메데·칼리스토·타이탄·엔셀라두스·티타니아·트리톤은 천체 유형·지질 프로필·해상도/면적·시드에 따른 고유 임시 매장량/품질을 생성한다. 이 값은 천문 관측치가 아니라 게임 디자인 데이터라고 표시한다.
- 태양계 공식 프리셋에 들어갈 때는 행성별 **고정된 공식 시드와 생성 결과**로 파일을 확정한다. 브라우저 새로고침/실행마다 시드 추첨 금지.
- 목성·토성·천왕성·해왕성의 현 **대기 기준층에는 암석형 ore 광산을 생성하지 않는다**. 수소·대기 채집원 등으로 차별화하되 공용 표면 격자/정체성은 유지한다. 고체 핵에 향후 별도 채굴 영역을 추가하는 것은 이번 범위 밖.

## 5. 매장지 배치 알고리즘 — '같은 행성인데 매번 똑같음' 방지

### 5.1 전체 예산 → 매장 형태 예산 → 실제 매장지

1. 행성별 `totalOreU`를 산정한다. 지구·금성·화성·달은 **고정 사용자 값**, 그 외 랜덤 천체는 시드 기반 값(6절).
2. 형태별 예산 `typeShare`(합계 100%)을 결정한다. 사용자 확정 4개 천체는 3절 고정값을 적용한다. 나머지는 행성형·지질학적 경향·시드에 따라 생성할 수 있다.
3. 타입별 매장량을 **정수 0.001 U quanta**로 정확히 배분한다. 세 형태 총량의 합은 최초 `totalOreU`와 항상 동일해야 한다. 합계 초과/미달, 부동소수점 누적, 같은 광맥 중복 카운트 금지.
4. 표면 전역형: 해당 행성의 허용 지형과 면적을 고려해 다수/전체 셀에 광석을 분포시킨다. 지질/육해 조건에 따라 셀별 매장량·난도는 다르며, 동일한 총량을 얇게 분산한다. 달은 **표면 전역형만** 생성한다.
5. 광맥형: `neighborIds`를 따라 **연결된 여러 셀**로 이어지는 1개 이상의 광맥 네트워크를 결정적 생성한다. 광맥마다 공유 `veinId/groupId`를 주되, 셀별 `depositId`는 기존 unique 계약대로 **전역 중복 없이 고유**해야 한다. 한 광맥의 총량은 그 광맥의 셀별 실제량 합이다. 연결성·분기·길이·두께/밀도·규모가 시드에 따라 바뀌어야 한다.
6. 심층형: 여러 후보 셀/광맥 아래에 매장지를 배치하되 일반적으로 높은 탐사/시추 기술을 요구하는 `discoveryTier`·`accessDepth`·`extractionDifficulty` 등이 있다. 표면형과 같은 셀에 공존 가능하며 기존 표면형을 덮어쓰지 않는다.
7. 집중형(향후): 단일/소수 지역에 대량 집중. 이번에는 생성기 인터페이스만 열어 두어도 된다. 사용자 확정 배분에 새 분류를 몰래 끼워 예산을 재해석하지 않는다.
8. 기존 v0.5C는 `ore` 한 개를 모든 셀에 분배하므로, 이번 변경에서 **기존 ore를 새 ore 위에 또 더하지 않는다**. `ore` 레코드를 타입별 재편성하되, 다른 자원과 초기 지형·인구·시설·수동 편집값은 보호한다.

### 5.2 광맥의 공간적 자연스러움

- 셀별 독립 난수로 무작위 점을 흩뿌리지 말고, 이웃 관계를 이용해 광맥이 연속된 형태가 되게 한다.
- 광맥의 연장 길이, 갈라지는 확률, 폭, 품질 편차, 난도는 seeded profile로 다양하게 선택. 극지/경도 seam에서도 연속성을 유지한다.
- 모든 매장지를 '매 섹터 딱 1개'로 강제하지 않는다. 하나의 섹터에 표면형+광맥형+심층형이 공존할 수도, 0개일 수도 있다. 특히 달에서는 표면형만 존재하도록 검사.
- 셀 ID·격자 f·면적·이웃·해시를 변경하지 말고, 기존 `grid.byId`를 활용한다. 저장 후 재생성되어도 동일한 grid를 유지한다.

## 6. 시드별 다양성 — 이번 추가 요구사항 (매우 중요)

**같은 지질/같은 Planet Size를 가진 두 행성이라도 서로 다른 시드라면 매장량·광맥 위치·품질 특성·난도·탐지 난도가 달라져야 한다.** 단순 위치만 다른 복제품은 불합격이다.

### 6.1 시드는 여러 독립 계층에 사용한다

- `worldSeed` 또는 `systemSeed`: 랜덤 항성계/세계 전체 시드.
- `bodySeed`: `(worldSeed, systemId, bodyId, generatorVersion)`으로 안정적으로 파생.
- `resourceSeed`: `(bodySeed, resourceId)`로 독립 파생.
- `depositSeed`: `(resourceSeed, depositKind, depositGroupId, tileId)` 등으로 독립 파생.
- 생성 순서·프로미스/Worker 스케줄·카메라·프레임·현재 게임 시각·브라우저 새로고침에 따라 결과가 바뀌면 안 된다. `Math.random()`을 생성의 기준으로 쓰지 말고 기존 `keyedRandom` 계열이나 검증된 seeded PRNG를 재사용한다.
- 자원 종류를 나중에 추가해도 기존 광석 배치가 멋대로 변하지 않도록 독립 키 스트림을 쓴다. **생성 알고리즘 버전**을 저장한다.

### 6.2 총매장량 산출을 시드에 따라 바꾼다

- **고정 예산 모드 (`fixedBudget`):** 태양계 지구/금성/화성/달처럼 총량과 형태별 예산이 명시된 경우 사용. 시드로 위치·개별 매장량·매장지별 품질 편차를 변경해도 합계와 형태별 비율은 변하지 않는다.
- **가변 예산 모드 (`proceduralBudget`):** 랜덤 항성계나 아직 확정되지 않은 태양계 다른 천체에 적용. 행성 유형, 실제 반지름/표면적, 암석/얼음/가스 분류, 환경적 접근성 *참고값*, `bodySeed` 기반 자원 풍부도 계수로 **총매장량을 생성**한다. 극소/보통/풍부/매우 풍부의 넓은 분포를 허용하고 극단치는 상한·하한으로 통제한다.
- 예를 들어 기준 예산에 시드별 풍부도 계수(잠정 범위 **0.25~3.0배**)를 곱하는 함수를 만들 수 있다. 이 범위는 **예시/튜닝 파라미터**이며 확정 밸런스 수치 아님. `resourceDefinitions`별 상한과 물리/환경 허용 조건을 준수한다.
- 자원 **존재량**과 **당장 경제적으로 회수 가능한 양**은 다르다. 풍부도가 높아도 고온·중력·고난도 때문에 초기 실효 생산성이 낮을 수 있다.
- 가변 예산이라도 생성 중 `0 U`가 실제로 의미 있는 부재 상태가 될 수 있어야 하며, `null=미정`, `0=없음`을 구분한다.
- 공식 Sol 프리셋 생성 후 파일에 고정된 seed와 결과를 저장한다. 이후 버전 업그레이드에서 로더가 재생성해 현재 데이터를 덮어쓰지 않는다.

### 6.3 품질 자체도 시드에 따라 달라진다

- 랜덤 행성의 **매장형별 기본 평균 확률**도 시드에 따라 달라지게 한다. 지구와 금성의 확정 평균 확률을 다른 행성에 일괄 복사 금지.
- 같은 행성의 **개별 섹터/광맥 확률**에는 가벼운 편차를 부여한다(7절). 인접한 광맥 섹터에서는 품질 편차가 서로 상관되어, 광맥 전체가 대체로 비슷하지만 국지적으로 조금 다를 수 있게 한다.
- 난도(`extractionDifficulty`, `processingDifficulty`)와 발견 난도도 시드/천체 특징으로 달라질 수 있다.
- **재현성 테스트 필수:** 같은 시드 + 같은 알고리즘 버전 + 같은 천체 정보 → 전체 매장량·각 depositId·그룹·품질 확률·JSON 해시가 같아야 한다. 다른 시드 → 적어도 총량 또는 매장지 분포 또는 품질 경향이 의미 있게 달라야 하며, 여러 시드 표본에서 거의 매번 같은 총량이 나오는 오류를 찾는다.

## 7. 섹터마다 '미묘하게 다른 품질' + 지정 평균 보존 (이번 대화의 핵심)

### 정의

매장 형태별 **행성 기본 확률** `P_{body,type}=[pLow,pMedium,pHigh]`가 있다. 각 실제 매장지 `i`는 `P_i`를 갖는다. 각 `P_i`는 0~1, 합 1이다. 그 매장 형태의 매장량을 `w_i=initialReserveU_i`라 할 때 **품질별 매장량 가중평균이 지정 확률과 일치**해야 한다.

```text
∀ quality ∈ {low, medium, high}:
  Σ_i (w_i × P_i[quality]) / Σ_i w_i = P_body_type[quality]

모든 i: P_i[low] + P_i[medium] + P_i[high] = 1
기본 확률 P_i는 '미래 채굴할 때 각 등급이 나올 확률'이며,
         '지금부터 저품질 n U / 고품질 m U를 예약한 매장량'이 아니다.
```

**동일한 확률을 전체 섹터에 복사해서 조건을 통과시키는 건 요구사항을 충족하지 못한다.** 다수의 섹터에 *미묘하지만 실제로 다른* 확률이 존재해야 한다. 다만 매장지가 하나뿐이거나 확정 품질 성분이 0 또는 100%인 경우의 수학적 한계는 예외로 문서화한다.

### 권장 구현 원리: 가중 중심화 편차 + 전체 강도 조절

1. 각 매장지의 시드 기반 저·고품질 편차 `dLow_i`, `dHigh_i`를 생성한다. 같은 광맥에 속한 구역끼리는 공유된 광맥 편차 + 약한 국지 편차를 합성해 공간적으로 연속되게 한다.
2. 매장량 가중평균을 빼서 `δLow_i=dLow_i-weightedMean(dLow)`, `δHigh_i=dHigh_i-weightedMean(dHigh)`로 보정한다. `δMedium_i=-(δLow_i+δHigh_i)`.
3. `P_i = P_target + α × δ_i`로 설정한다. α는 충분히 작게 시작하거나 전체 매장지에 공통으로 줄여서 **모든 품질 성분이 0~1 범위**에 들어가도록 한다. 각 매장지를 따로 clamp해 가중평균을 깨뜨리는 로직 금지.
4. 최대 편차는 설정값(가령 기본 ±3~5%p 수준, **잠정값**)으로 조절한다. 행성/타입에 따라 폭을 다르게 해도 평균 보존을 지킬 것.
5. 최종 저장 정밀도(예: 품질 확률 0.000001 단위)로 반올림할 때에는 잔차가 생길 수 있다. **정수 기반 고정소수점, 결합 알고리즘/잔여 보정, 또는 허용오차 1e-6 이하의 결정적 정리**를 통해 평균을 검증한다. 모든 3종 확률 합도 검증한다. 낮은 확률 1~2%인 지구 표면/금성 심층에서는 음수가 되지 않게 특히 주의한다.
6. 기술 보정은 **기본 지질 확률 `P_i`에 사후 적용하여 최종 생산 등급 확률 `P_effective`를 구한다**. 기술로 인해 실제 생산의 행성 평균이 기본 확률과 달라지는 것은 정상이다. **원래 `P_i`와 행성 기본 타깃은 불변**이다.

### 반드시 테스트할 평균 보존

- 지구 표면형 전체 고품질 확률의 `w`가중 평균은 **2%**, 광맥형 **5%**, 심층형 **33%**.
- 금성 표면형 전체 고품질 확률의 `w`가중 평균은 **25%**, 광맥형 **70%**, 심층형 **82%**.
- 지구 전체 고품질 기대확률 **7.05%**, 금성 **58.9%**. 각 유형의 비중을 변형하지 않는 한 여러 시드에서도 (공식 고정 예산 모드) 정확히 유지되어야 한다.
- 가중치는 **섹터 개수도, 광맥 개수도, 셀 면적도 아니라 해당 매장지가 포함한 광석의 실제 매장량**이다. 표면/광맥/심층 모두 동일.
- 같은 시드인데 추첨/재배분의 호출 순서만 바뀐다고 숫자가 바뀌면 안 된다.

## 8. 광석 채굴 품질 판정·제련 계산: 엔진 함수만 준비

- 순수 함수 예: `getBaseGradeProbabilities(deposit)` / `getEffectiveGradeProbabilities(base, {miningTech, beneficiationTech})` / `sampleGradeBatch({depositId, batchSerial, oreAmountU, gradeProbabilities, seed})` / `computeAlloyYield(gradeAmountsU, smeltingTech)`.
- 출력은 **저·중·고품질 광석** 세 가지 별도 산출분으로 다룰 수 있어야 하며 합계 U는 입력 광석량과 같게 한다. 나중에 창고에는 `ore.low/medium/high` 또는 ore 등급 서브인벤토리로 저장 가능하도록 인터페이스 마련. '전체 광석'은 세 등급 합산 표시.
- **미래 채굴 생산의 확률 표본**은 매장지별 seeded batch counter 기반으로, 동일한 배치에 대해서는 재시작/재계산 시 결과가 동일해야 한다. `Math.random`, 시각 기반 랜덤, 호버/프레임 호출, 재접속 재추첨 금지. 물량이 클 때 `0.001 U`를 하나씩 수천억 회 루프 돌지 말고 일정 생산 배치 처리 알고리즘을 만든다.
- 실제 광산의 `remainingReserveU`나 창고 수량·정부/민간 소유권을 **이번 프로토타입에서는 변경하지 말 것**. 함수 호출로 예상치/단위테스트만 계산. 실생산은 후속 v0.6에서 연결.
- 합금 수율 함수는 기본 `low:0.14, medium:0.33, high:0.52`와 별도의 기술 단계/효율 파라미터를 지원. 예상치와 확률 표본을 혼동하지 말 것.
- 고품질 광석의 전략자원 부산물은 데이터 인터페이스/문서만 예약. 새 희귀 자원을 기본 ore 제련 출력에 임의 생성하지 않는다.

## 9. 탐사·지식: '진실값'과 '알려진 값' 분리

- 모든 ore 실제 매장지는 **게임 시작 전 생성**되며, 탐사를 수행할 때 갑자기 매장량이 생겨서는 안 된다. 지질 원본에 `initialReserveU`, `depositId`, `depositKind`, `groupId`, 숨겨진 기본 품질 확률이 존재한다.
- 일반 플레이어 화면은 처음부터 모든 진실값을 보면 안 된다. 개발자 모드에서는 전량·숨김 여부·품질 등급 확률·발견 난도 표시 가능.
- 문명별 지식은 해당 문명의 **발견한 매장지 목록, 총매장량 탐지율/확인율, 현재 기술 티어와 품질 확률 추정의 신뢰도/범위**를 별도 저장한다. 한 매장지의 `actualTotalU` 외에 수십 개의 중복 매장량 필드를 진실 데이터로 저장할 필요 없음. **진실 매장량×인지 퍼센트**로 해당 문명의 확인량을 계산해도 된다.
- `surveyProgress=100%`는 **그 기술 티어에서의 조사 완료**이지 '자원 100% 발견'이 아님. 센서 기술 향상 시 기존 누적 탐사 진행률을 파괴하지 않고 새로운 확인 티어/재탐사를 지원할 구조.
- 지구는 시작 문명의 기존 지식이 높게, 달·화성은 일부 알려져 있고, 기타 미개척 천체의 숨겨진 매장지는 비공개로 시작하도록 공용 정책을 준비. **정확한 시작 인지 퍼센트는 미확정**이므로 도구에서 바꿀 수 있는 임시 데이터로 선언한다.
- 초기 지식에 기록된 `discoveredDepositIds`는 반드시 실제 같은 셀/천체의 depositId를 참조해야 한다. 기존 v1 지식과 매장지 재편성 중 ID가 바뀐다면 안전한 이관을 구현하거나 참조 손상을 거부한다.
- 개발자 데이터/숨겨진 매장량/기본 품질 실제 확률이 일반 모드 DOM·툴팁·색상 지도에 노출되지 않아야 한다. 일반 모드에서는 아는 만큼만 보인다.

## 10. 수소: 공통 연료 자원 등록 + 공급원 유형 구분

- `hydrogen`을 1 U=10톤의 **기초 연료 재고 자원**으로 정의. 일반 추진계통/펄스/하이퍼펄스/후기 드라이브의 실제 소비량·연료탱크는 이번 구현에서 미정. 수소는 광석 제련으로 생성하지 않는다.
- 수소 공급원은 **두 가지 유형으로 분리**한다.
  1. `finite-source`: 얼음·물 등에서 추출하는 유한 공급원. 실제 원천 물질·변환 과정/손실률은 향후 정제 산업과 연결. 초기에 수소의 무제한 매장량으로 간주하지 않는다.
  2. `atmospheric-collector`: 목성·토성·천왕성·해왕성 등의 대기층에서 채집. 대기 전체를 음수·무한대 같은 `initialReserveU`에 넣는 게 아니라, **채집 가능한 위치/잠재 채집량·유지비·시설 요구** 같은 별도 원천 정의를 사용. 실제 채집 생산은 후속 단계.
- 태양계 공식 19개 천체 중 적절한 대기/빙설 천체에 수소 생산 **잠재 공급원**을 설정. 가스 거대행성은 고체 광석 광산으로 위장시키지 않는다. 실제 수소 재고를 시작 시점에 임의로 무한 생성하지 않는다.
- `hydrogen`과 고품질 ore 산출 확률은 완전히 별도 시스템. `alloy`·`credits`는 자연 매장 안 됨.
- **아스트로지늄은 기획 문서에만 예약**: '매우 희귀한 우주 매장지의 특수 드라이브 연료, 일반 행성 표면 광석에서 자동 산출되지 않음'. 출시용 임시 자원으로도 Sol 표면에 임의 배치하지 않음.

## 11. 데이터 모델·버전·저장 — 기존 v1 파일을 깨뜨리지 말 것

현재 v0.5C의 v1 deposit 필드는 `depositId/resourceId/initialReserveU/extractionDifficulty/discoveryTier/notes`이고, `planet-surface-template` v1의 `geology.cells`와 `startingScenario.cells`가 존재한다. 새로운 타입/품질/광맥 그룹/수소 채집원 필드를 이 v1 validator에 무심코 추가하면 오류가 난다.

### 필수 저장 계약

- **서로 다른 세 층:** `(A) 지질 원본(총량·실제 매장지·원래 품질 확률)`, `(B) 2100 초기 시나리오(POP/시설/문명 지식)`, `(C) 미래 런타임(잔여매장량·굴착 상태·테라포밍·피해·재고)`. 이번에는 (A)(B)와 (C)를 위한 인터페이스만. 런타임 상태로 원본 `initialReserveU`를 덮지 않는다.
- **권장:** 기존 v1 템플릿에서 v2로 명시적으로 스키마 진화하고 구형 v1을 검증된 마이그레이션으로 읽는다. 원본 파일과 로컬 초안의 백업을 먼저 제공하고, `schemaVersion`, `migrationVersion`, `generatorVersion`을 혼동하지 않는다. `grid.generatorVersion/frequency/orientationId/gridFingerprint`는 **기존 값 불변**.
- 대안으로 기존 v1 템플릿 + 독립적인 버전드 자원 레이어(JSON sidecar)를 선택해도 된다. **단, 어느 방식이든 ore 매장량의 진실값은 한 곳만 authoritative**해야 한다. 레거시 v1 ore와 새 자원 레이어를 동시에 합산하는 방식은 **절대 금지**. 채택한 단일 방식을 문서화하고 테스트로 증명할 것.
- 새 `depositKind=surface|vein|deep`, 셀별 고유 `depositId`, 공유 `groupId/veinId`, 동일 형태 내 **확률 벡터** `gradeProbabilities`, `extractionDifficulty`, `processingDifficulty`, `discoveryTier`, 미래 성분/희귀 부산물 확장 자리 제공.
- 행성 전체 설정(고정 총량, 형태별 목표, 확정/잠정 평균 확률, 시드, 품질 편차 강도)과 **생성 결과**를 분리해 저장. `gradeProbabilities`의 합 1, 숫자 범위, 참조 무결성, 모든 U 합계, 광맥 연결성, 자원 정의를 검증한다.
- 새 모델을 읽을 때 `null=미설정`, `0=실제 0`, `[] = 확인된 빈 목록` 의미 유지. 독자적인 새 JSON 구조라면 모호하지 않은 의미를 README와 검증에서 고정.
- 기존 `localStorage['space-project:surface:v1:...']`, 정적 manifest와 개발자 JSON 내보내기/가져오기, Undo, 손상/구버전 보호, 사용자가 수동으로 편집한 데이터 **보존**. 마이그레이션 실패 시 기존 JSON 원본을 유지하고 오류 이유/복구 안내; 조용히 초기화하지 않는다.
- 미리보기 → 합계/품질 검증 → 명시적 적용 → 백업 → 저장의 트랜잭션 흐름을 유지. 저장 실패 시 메모리만 적용한 사실을 알리고 JSON export 가능하게 한다.
- 태양계 공식 프리셋 파일들은 `dist/data/planet-surfaces/`(또는 명시적인 리소스 레이어 폴더)에 실제로 커밋한다. `dist/data/planet-surfaces/index.json`을 19개 대상으로 업데이트한다. **현재 index가 `{schemaVersion:1,templates:{}}`인 상태에서 끝내지 말 것.** 미래 시스템에서는 같은 로더/생성기를 사용하여 즉석 생성 또는 별도 snapshot 로딩이 가능하게 한다.

### 직관적 구조 예시(정확한 스키마 확정은 구현자가 검증과 함께 선택)

## 12. 개발자 UI / 일반 UI 요구

- 기존 숨김 진입 **SPACE 로고 5초 안 7회** 또는 기존 `?dev=1` 호환을 유지. 모바일 주소창 입력을 요구하지 않는다.
- 표면 지도 → 개발자 자동 설정 패널에서 **광석 총량(고정/시드 자동), 분포 유형별 예산, 행성·유형별 기준 품질 확률, 시드, 편차 강도, 원본 채굴/가공 난도, 초기 지식**을 볼 수 있게 한다. 행성별 잠정·확정값 라벨 필수.
- 지도 레이어: 광석 총량, 표면형, 광맥형(연속선 강조), 심층형, 고품질 예상 확률, 채굴 난도, 미발견/발견 상태. 공통 표면 섹터와 행정 섹터를 혼동하지 않는다.
- 개별 섹터 선택 시 그 섹터의 **표면·광맥·심층의 별도 매장지 목록**과 기본 품질 확률, 유효 품질 확률(기술 가정), 총량·확인량·미발견 여부, 같은 `groupId`의 광맥 전체 범위를 개발자에게 표시할 수 있어야 한다.
- **다른 시드 미리보기**는 실제 저장값을 변형하지 않는다. 미리보기에서 현재/예정 총량·유형별 분배·평균 품질·광맥 개수·변경 셀 개수 비교. 적용할 때 기존 사용자 편집과 기존 저장본을 백업하고 확인을 받는다.
- `fill-unset`의 의미와 명시적 `overwrite` 차이를 유지하되, 공식 지구 배분 교체는 반드시 사용자 의도에 따른 별도 전체 재구성 작업으로 처리(자동 실행/조용한 덮어쓰기 금지).
- 일반 게임 모드에서는 **탐사로 확인한 정보만** 표시. 개발자용 진실 확률·숨겨진 매장량·미발견 희귀자원 목록, 다운로드/편집 기능 노출 금지.
- 확률 입력은 0~100%·합계 100%를 검증하고, 사용자가 어떤 층의 확률을 편집하는지 (`행성 매장형 평균` vs `개별 매장지 확률` vs `기술 후 유효 확률`) 명확히 구분한다. 행성 평균을 깨뜨리는 수동 예외는 *예외값 보정/대안 시나리오*로 다루며 검증과 보고를 우회하지 않는다.
- 844×390/667×375 같은 작은 가로 화면에서 패널 내부 스크롤, 버튼 접근, 키보드 입력, 닫기/취소, 전체화면 동작 유지. 렌더 루프에서 모든 매장지를 다시 생성하지 않는다.

## 13. 테스트: 기능 완성이 아니라 데이터 계약을 실제로 증명

### 단위/불변식

1. 지구 786억, 금성 1142억, 화성 489억, 달 1000억 U **정확한 총량**.
2. 각 천체 매장 형태 총량도 3절 표의 정확한 U와 같고, 매장 형태 합이 전체 총량과 같음. 어느 `depositId`도 두 번 집계하지 않음.
3. 지구/금성의 3개 유형별 `[저,중,고]` 매장량 가중평균이 4절 확정 확률을 허용오차 범위에서 충족함. 각 개별 확률 합계 100%, 음수·NaN·Infinity 없음.
4. **동일 유형 내 서로 다른 셀들이 실제로 품질 확률이 다름**(불가능한 극단/단일 매장지 예외 제외). 그러나 평균은 확정값 유지. 가중평균 계산을 셀 개수로 잘못 나눌 경우 테스트 실패.
5. 달에 `surface` 외의 `vein/deep` ore가 0개, 달 전역형 저품질 기본평균 **80%**. 화성은 표면 저/중 중심, 해당 지구 유형보다 고품질 증가(수치는 임시 라벨).
6. 같은 시드 재생성 → 매장량/품질/ID/JSON 해시 일치; 다른 시드 랜덤 천체 → **총량까지 변화하는 사례 존재** + 위치/확률 차이. Sol 네 고정 천체는 여러 시드에도 전체/유형별 확정 예산 유지.
7. 광맥 groupId의 셀 연결성, 다중 섹터/단일 섹터 규모, 같은 그룹 소속 부분들의 총량 합, 경도 seam/극 지역, 구면 이웃 인접성.
8. 저·중·고 등급 채굴 배치 합계가 정확히 입력 U. 동일 배치 seed/serial 재현. 다른 배치 serial에서는 실제 확률적 편차가 발생. 과도한 루프/배치 성능 문제 방지.
9. 중품질 광석 100 U → 합금 **33 U**, 저품질→**14 U**, 고품질→**52 U**. 기술 보정이 지질 총량/원래 품질 확률을 변경하지 않는지 검사.
10. 지구 기존 JSON의 92개 ID/그리드 fingerprint/인구 **8,893,000,000명**/도시화/지형/기반시설 보존; ore **783억에서 786억으로만** 변경. 구형 v1 가져오기·마이그레이션·백업·새 파일 내보내기/재가져오기.
11. 자연에 합금/크레딧 매장 불가능, 가스행성 대기층에 ore 매장 불가능, 수소 공급원은 유한/채집 잠재량 구분, 아스트로지늄 무단 생성 없음.
12. 발견하지 못한 매장지는 일반 모드에서 보이지 않으며, 문명별 확인율을 올려도 초기 총량은 바뀌지 않는다. 고급 탐사 시 기존 티어 지식 보존.
13. 공식 19개 천체 manifest 파일 경로, 각 JSON schema/grid fingerprint/자원 검증, 지구/달/화성 식민지 시작 인구 일관성, 새 브라우저 기본 로드·로컬 초안 우선/보호.
14. `null`과 `0`의 구분, `fill-unset` 원본 보존, `overwrite` 확인/백업, 저장 실패·기존 지식 참조 오류·유효하지 않은 확률/예산의 원자적 거부.

## 15. 최종 설계 원칙(한 번 더)

> **광석의 매장량은 하나. 매장 형태는 분리. 품질은 채굴 때마다 확률로 판정. 행성·형태별 품질값은 매장량 가중 평균이고, 개별 섹터마다 미묘한 차이가 있다. 기술은 최종 품질/제련 효율을 개선하지만 지질학적 진실을 바꾸지 않는다.**
>
> **고정된 태양계의 역사와 수치 + 시드에 따라 다양하게 생성되는 미래의 외계 행성 + 탐사로 조금씩 밝혀지는 정보**를 하나의 공용 시스템으로 연결하라.

### 수치 빠른 재확인

- **지구** `78,600,000,000 U`, `25/65/10%`, 표면 `60/38/2`, 광맥 `45/50/5`, 심층 `23/44/33`.
- **금성** `114,200,000,000 U`, `38/12/50%`, 표면 `33/42/25`, 광맥 `8/22/70`, 심층 `1/17/82`.
- **화성** `48,900,000,000 U`, `70/20/10%`, 표면 저·중 중심/고품질 지구보다 약간 위, 광맥·심층 고품질 지구보다 위. **정확한 품질 확률 잠정**.
- **달** `100,000,000,000 U`, `100/0/0%`, 전역 저품질 **80% 확정**, 중/고 잔여 20% 잠정, 가공 고난도.
- **제련 수율** 저 `0.14`, 중 `0.33`, 고 `0.52` alloy U per ore U.
- **수소** 공용 연료 자원/유한 얼음 또는 대기 채집원 구분. **아스트로지늄** 명칭과 방향만 예정.
- **시드 변화**: Sol 네 천체의 확정 총량/형태/평균은 고정; 시드로 섹터별 배치/품질 편차는 변화. 랜덤 천체는 **총량·품질 평균 자체도 시드별 변화**.
