# SCU-2 FOLLOW-UP-1 구현

작성일: 2026-11-02 (Asia/Seoul). 기준 PR #12 `f2aa8a824020042d201c552d55f8f4a82ab2a6a6`.

## 시각 계약

산업 정산의 정수 `settledTick`을 유일한 권위로 사용한다. 직렬화 가능한 `packaging.clockMs = settledTick × 3,600,000`은 `originDays` 이후 경과 시각이다. 실제 시간, 프레임 시간, 마지막 SCU 처리 시각을 현재 게임 시각으로 추정하지 않는다. 산업 생성/명시적 가져오기/상태 교체에는 외부 WeakMap 시계 공급자를 다시 연결한다. 독립 SCU 라이브러리 사용자는 `advancePackagingClock()`으로 가상 시각을 명시적으로 진행해야 한다. 산업에 연결된 장부를 산업 정산보다 먼저 진행할 수 없다.

예약 시 현재 시각으로 유휴 설비를 정렬하고 `startedMs`를 기록한다. 처리 구간은 `max(lastMs, startedMs)` 이후이며 유휴 구간을 작업량으로 바꾸지 않는다. 설정 변경은 이전 설정으로 현재까지 정산한 뒤 적용한다. OFF/0 처리능력 구간은 새 작업량을 벌지 않고 이미 얻은 분수 SCU만 유지한다. 취소한 미완성 작업은 기존 실물과 예약을 반환하고 분수 작업량을 버린다. 재예약은 다시 현재 시각에서 시작한다. 완료 후 남은 시간은 차기 작업에 무료 이월하지 않는다. 과거/미래 예약 시각, 역행 및 산업 시계보다 앞선 큐 호출은 원자적으로 거부한다.

산업 루프는 매 시각 루트 스칼라만 갱신한다. 활성 SCU 작업이 없거나 설비가 OFF/처리능력 미연결이면 큐 처리를 위해 매시간 전체 장부를 복제하지 않는다. 자동 계획은 기존 예측·순편익·보호 재고 정책을 유지한다.

## 원광 현지 실포장

`industry-packaging.js`의 기존 견적/커밋/개봉 진입점에서 `resourceId:'ore'`를 현지 산업 어댑터로 연결했다. 기본 비용은 계속 null이므로 일반 실행은 `pending-cost-input`이다. 명시적으로 가격과 전력을 공급한 테스트 규격으로 실제 채굴 재고를 봉인/개봉한다. 별도 배송 객체나 기본값 0을 만들지 않았다.

호출 예(실제 상태/카탈로그 및 실행 가능한 승인 규격이 필요):

```js
const request = {bodyId:'earth', ownerId:'human', resourceId:'ore',
  amountQ:8000, lotKey:oreLotKey(actualFreeLot)};
const quote = quoteIndustryContainerPack(state, catalog, request);
commitIndustryContainerPack(state, catalog, request, quote);
unpackIndustryContainer(state, catalog, {bodyId:'earth', ownerId:'human',
  resourceId:'ore', groupKey:actualGroupKey, count:1});
```

`lotKey`는 천체·소유자·광맥 key/id·등급·가공 난도의 정규화된 튜플이다. 또는 명시적 `lotPolicy:'single-source-first'`로 요청 수량을 충족하는 단일 로트를 결정적으로 선택한다. 기본값으로 여러 로트를 섞지 않는다. 그룹의 `lotManifest`는 **컨테이너 1개당** 같은 7개 로트 필드와 `amountQ=fillQ`를 보유한다. 그룹 총량은 `count × fillQ`다. 그룹 키에도 전체 로트 식별을 포함해 서로 다른 광맥/품질/난도가 합쳐지지 않는다.

견적은 상태를 바꾸지 않는다. 커밋은 원본 상태 객체·전체 직렬화 서명·시각·주체·재고·현재 규격/해금·비용을 재검증하고 상태 사본에서 산업 자유 로트, 품질 재고, 소재, C/Wh, 컨테이너 및 보관 원장을 함께 검증한 뒤 교체한다. 견적은 동결/상태 종속/1회용이며 JSON으로 위조하거나 다른 상태에 적용할 수 없다.

`inv.ore`는 **제련 가능한 자유 원광**이다. 봉인하면 자유 로트와 해당 등급에서만 차감하고 `freeQ.ore`나 generic 잔여 버퍼를 만들지 않는다. 제련은 기존 로직 그대로 자유 로트만 소비한다. 정수 컨테이너를 열면 그 컨테이너 전체 원광을 같은 로트로 돌려준다. `industryOreInventory()`는 자유/봉인/전체 품질 합계를 제공한다. 기존 재고 행에 자유 품질 및 봉인 총량을 표시한다. 기본 비용이 미정인 점을 유지하므로 전용 실행 UI를 새로 만들지 않았다.

## 이중 장부 검증

- 로트별 `packedByLotQ − unpackedByLotQ = 실제 봉인 manifest 합계`.
- 자유 품질별 `inv.ore = 실제 inventoryLots 합계`.
- 천체별 `자유 원광 + 봉인 원광 + 정상 제련 소비 = 실제 채굴량`.
- 광맥별 현재 자유+봉인 소유량은 실제 추출량 이하여야 한다. 모든 참조는 현재 지질 카탈로그와 소유자/난도가 일치해야 한다.
- 기존 SCU 수량·묶인 소재·회수 정수/분수·손실·제작/개봉 수·C/Wh 보존식도 모두 검사한다. 원광의 공급/외부 소비/배송 장부 우회, 미등급 자유/잔여 원광, 원광 자동 재포장은 거부한다.

기존 v1 비교 좌표에 봉인량을 되돌리는 projection은 **위 전체 검증을 먼저 통과한 후** 과거 생산 공식과 750.125일 궤적을 비교하는 데만 사용한다. 자유 재고를 봉인량만큼 중복 추가하면 전체 보존 검증에서 실패한다.

## 지원 경계

지원: 정부 human 소유, 현지 단일 로트, 같은 내용의 집계 그룹, 불완전 적재, 그룹 중 정수 개수의 컨테이너 전체 개봉, 현재 저장의 정확한 왕복, 실제 구버전 검증/이관.

명시 거부: 혼합/중복 로트 선택, 컨테이너 내용의 임의 부분 개봉, 미등급 원광 소비 버퍼, 원광을 포장 구조재로 사용, 원광 자동 현대화/재포장, 민간 원광 공급자, 다른 천체/소유자로 인도/이동, 가짜 배송 영수증을 통한 원광 순간이동. 원광 세대 변경은 기존 컨테이너를 현지 개봉한 뒤 새 규격으로 명시 포장한다. 해금만으로 옛 그룹/소재/회수율이 바뀌지 않는다.

ECON-SIM-4, 포장 C·전력 재보정, 실제 운송/화물선, 발전모듈 추가는 구현하지 않았다.
