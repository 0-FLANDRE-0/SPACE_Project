## 실제 동작

시작 함대는 지구 고궤도 경계의 서로 다른 세 위치에 생성된다. ‘지구 궤도 정거장’은 위치 이름이며 정거장 기능은 없다.

| 함선 | 수 | 함급 | 드라이브 | 순항 | 충전 | 선회 | 표시 길이 |
|---|---:|---|---|---:|---:|---:|---:|
| 건설지원함 | 1 | 중소형 | 펄스 | 1 gAU/h | 1시간 | 0.3°/게임초 | √(170/60) ≈ 1.6833 월드 |
| 탐사함 | 2 | 소형 | 실험형 하이퍼펄스 | 640 gAU/h | 2시간 | 2.5°/게임초 | 1 월드 |

반응로는 모두 개량 핵분열이다. 길이 170m/60m는 임시 형상 기준이며 물리 거리 환산에 사용하지 않는다. 하이퍼펄스의 `maxHullClass`는 소형이고 더 큰 함급·알 수 없는 함급은 거부한다. 충전에는 질량 계수 함수가 적용되며 현재 계수는 1이다. 연료·수소·산업 재고를 차감하지 않는다.

탐사함의 좁은 기수, 상부 경사, A자 능선과 후부 엔진을 재현했다. 건설지원함은 전방 작업 모듈, 종재 4개와 양면 X 트러스, 큰 후부 기관 모듈로 구성했다. 전체 형상(기관부 포함)의 실제 경계 상자를 기준으로 표시 길이를 정규화한다. +Z가 함수이며 선회는 pitch를 포함하는 3D 벡터의 최단 회전이다.

카메라 거리로 메시 크기를 바꾸지 않는다. 원근 투영한 명목 길이/화면 높이가 3.6% 미만이면 아이콘, 4.4% 이상이면 3D이며 중간 구간에서는 직전 표시를 유지한다. 아이콘은 원, 플라스크 또는 교차 망치·몽키스패너, 함수 방향 틱, 이름이다. 선택 시 메시의 모서리 외곽선 또는 아이콘·이름을 강조한다.

## 조작

- **공통:** 함대 목록 또는 3D/아이콘으로 한 척을 선택한다. ‘함선 확대’는 명시적으로 누를 때만 카메라를 이동한다. 빈 지도나 X로 선택 해제한다.
- **모바일:** 하단 원형 ➜ → ‘이동 지점 선택’ → 지도 점을 터치한다. 뒤로가기는 목표 선택만 취소한다. 선회·충전 게이지와 X 이동 취소를 제공한다. 이동 중 ‘목적지 변경’으로 현재 위치에서 새 명령을 낼 수 있다.
- **PC:** 선택 후 천체·지점을 우클릭한다. 우클릭 드래그는 기존 화면 이동으로 유지한다. `C`는 목표 선택 또는 진행 중 이동을 취소한다.
- **도착 옵션:** 함선 정보의 ‘도착 시 일시정지’는 기본 꺼짐이다. 켜면 해당 프레임의 남은 시간을 진행하지 않고 모든 함선·게임 날짜·정부 산업을 최초 도착 시각에 맞춰 멈춘다.
- **목표 선택 중:** 정보 패널을 잠시 숨겨 지도 점을 가리지 않게 한다. 명령 또는 뒤로가기 후 복원한다. 카메라를 강제로 확대/이동하지 않는다.

아이콘은 선택 함선 우선으로 배치하고 서로 및 천체 클릭 중심을 피한다. 원래 위치와 벌어지면 가는 연결선을 표시한다. 화면 경계에서 완전한 라벨 겹침 해소까지 보장하는 레이아웃은 아니며 M1b/후속 HUD에서 확장할 수 있다. 44px 터치 영역과 지점의 화면 거리/실제 메시 판정을 사용한다. 목표 점의 큰 투명 DOM 영역으로 다른 점을 가리는 대신 지도에서 가까운 점을 판정한다.

## 좌표·항법

기존 `game-space.js`, `model.js`, 천문·행성 데이터는 바꾸지 않았다. **1 gAU = 140/53 월드 단위**가 유지된다. 지구의 궤도 장반경은 100 gAU, 표시 지름은 15 월드이다. 함선 시뮬레이션 좌표·속도는 gAU/게임초이며 렌더링 경계에서만 환산한다.

천체의 행성권은 `bodyRadiusGameAU × 1.6`이다. 예를 들어 지구 반경은 약 2.8393 gAU, 행성권은 약 4.5429 gAU이며 카메라와 무관하다. 저 1.05·중 1.3 배율은 데이터 자리만 있고 궤도 껍질·표면 꼭짓점 이동은 없다.

외부 이동은 **선회 → 충전 → 직선 순항**이다. 각 단계의 시작·종료 절대 게임 시각을 미리 계산한다. 큰 프레임에서도 단계 완료·도착 이벤트를 시간순으로 처리한다. 같은 목표를 새로 지정하면 현재 좌표와 선회 중 자세에서 다시 계획한다. 선회·충전 취소에는 비용이 없고 순항 취소는 현 위치에서 멈춘다. 행성권 안의 정지는 해당 천체의 평행 이동을 따르고 밖에서는 항성계 좌표를 유지한다.

현재 행성권 안 목적지는 **충전 없는 등속 추진 0.04 gAU/분**이다. 안전한 구면 경로를 15° 이하 현으로 나누고 필요한 선회·추진을 처리한다. 현재 천체가 외부 목표를 가리면 고궤도 경계의 후보들에 대해 추진 경로와 LOS를 검사하고 예상 도착이 빠른 후보를 택한 뒤 드라이브를 사용한다. LOS에는 현재 중심이 아닌 **예측 도착 목표**를 사용한다.

행성/위성은 도착 시각의 공전 위치를 예측한다. 최종 접근 구간의 실제 출발 좌표에서 천체 쪽을 바라보는 고궤도 경계 점을 도착점으로 삼으며 도착 후 공전을 추종한다. 선회·충전 중의 출발 천체 이동도 반영한다. 아군 함선은 명령 시 좌표를 복사해 고정한다. 개별 소행성과 소행성대 목표는 자체 공전 예측 위치에 도달하며 도착 후 소행성을 추적하지 않는다. 항성은 클릭해도 이동을 거부한다.

도착 해법은 고정점 반복 **최대 48회, 잔차 허용 0.005 게임초**이다. 공전 속도가 펄스보다 빠른 위성처럼 고정점이 수축하지 않으면 구간 확장(최대 40회)과 이분법(최대 96회)으로 연속 도착 잔차를 푼다. 범위/수렴 실패는 유효하지 않은 경로를 실행하는 대신 안내하고 기존 명령을 보존한다.

경로 장애물은 천체 표시 반지름에 `min(0.4 gAU, 천체 반지름 × 0.2)`를 더한다. 고정 0.4 gAU만 사용하면 작은 위성의 고궤도까지 금지 영역이 되므로 상대 여유를 함께 제한했다. 구간 시각별 천체 위치, 공전 속도의 보수적 상한, 적응적 구간 분할로 충돌 여부를 검사한다. 불확실한 극소 구간은 안전하다고 간주하지 않는다. 우회점에서도 **다시 선회·충전**하므로 ETA에 모든 대기가 포함된다. 경로선·우회점·UTC 도착 시각·현재 배속 기준 현실 대기를 표시한다.

320 gAU 고정 거리 픽스처의 순항은 펄스 **320시간**, 하이퍼펄스 **30분**이다. 실제 태양계 주문의 전체 ETA에는 경계, 선회, 충전, 공전 예측, 우회가 포함되므로 이 숫자와 다를 수 있다.

## 이동 지점 및 배속

성계 전역 반경을 60개 구간으로 나누고 구간별 임의 반경·방위·경사를 갖는 **개별 소행성 60개**, 190–230 gAU의 **소행성대 지점 30개**를 고정 시드로 생성한다. 공전면은 현재 항성계 기준 평면을 따른다. 기존 입자 소행성대·공식 프리셋·자원 정보는 그대로 두고 이동 지점만 별도 추가했다. 자원, 탐사, 소행성 충돌은 구현하지 않았다.

210 gAU 고정 육각 격자의 모든 꼭짓점을 생성하고 공유 꼭짓점은 좌표 키로 중복 제거한다. 목표는 행성·위성, 소행성, 띠 지점, 격자 꼭짓점, 다른 아군 함선이다. 내부로 막힌 좌표는 안전 경로 검증에서 거부한다.

기본 1× = 현실 1초당 게임 10초와 기존 10개 배속을 유지하고 **360/2160/4320/8640×**를 추가했다. 메뉴에는 **1시간/6시간/12시간/1일 per 초**로 표시한다. `speedCap`은 0.1–8640 범위로 확장하고 요청 배속 복원 규칙은 유지했다. 백그라운드·60초 이상 브라우저 중단 제외 정책과 UTC 표시는 기존 그대로이다.

## 저장과 보존

함선은 **현재 탭 메모리 전용**이다. 산업 시험 JSON은 산업·원장·로트·포장 상태의 기존 v4 계약을 가지므로 함선을 함께 넣으려면 별도 상위 캠페인 스키마와 원자적 시계/항법 이관이 필요하다. 이번에는 그 계약을 변경하지 않았다. 새로고침, 산업 개발 시나리오 초기화, 명시적 산업 JSON 적용, 시험 항성계 전환 시 새 함대를 만든다. 함선을 산업 JSON에 내보내거나 자동 복원하지 않는다.

보존 매니페스트는 기준의 **946개 파일 SHA256**, 정확한 기존 파일 변경 허용 목록, `DECISIONS.md`의 원문 접두사, 새 파일 경로 범위를 검사한다. 공식 지질·92개 섹터 인구·광맥·매장량·품질·생산/비용 공식·SCU·저장 이관·ECON1–4.1 코드와 산출물은 그대로다. 기존 전체 트리 보존 테스트의 허용 목록에는 이번에 승인된 지도/UI/배속 통합 파일만 추가했다. 기존 시간 테스트의 최대 상한은 8640으로 갱신했으며 기존 foreground clock/날짜 구현의 바이트 보존 검사는 계속 수행한다.

## 고배속 성능

다른 브라우저 검사를 종료한 뒤 Chromium/SwiftShader **소프트웨어 GPU**에서 각 화면을 순서대로 측정했다. 각 조건에서 10프레임 워밍업 후 60프레임의 RAF 간격을 기록했다. 기준은 `677536c` 임시 복사본에 고배속 프리셋/상한만 열어 동일한 1일/초로 실행했다. 공식 파일은 변경하지 않았다. M1a 대기는 시작3척, M1a 이동은 지원함→해왕성/탐사함→토성·화성을 발주하고 지원함을 선택한 상태다.

| 화면 | 기준 중앙값 ms | M1a 대기 중앙값 ms | M1a 이동 중앙값 / p95 ms | 이동 중 함대 CPU p95 ms |
|---|---:|---:|---:|---:|
| 1440×900 | 150.0 | 150.0 | 183.3 / 233.3 | 0.20 |
| 844×390 | 150.0 | 150.1 | 166.6 / 200.0 | 0.20 |
| 667×375 | 149.9 | 150.0 | 183.3 / 266.7 | 0.30 |
| 390×844 | 133.3 | 150.0 | 150.0 / 200.0 | 0.20 |

기준 자체가 약 6.7–7.5FPS이고 M1a 이동도 약 5.5–6.7FPS여서 **이 환경에서 부드러운 30/60FPS를 달성했다고 보고하지 않는다**. 함대 CPU p95는 위 표와 같으며, 이벤트·GC 등을 포함한 최대치는 원문 JSON에 기록했다. 화면 프레임 시간은 소프트웨어 래스터화·브라우저 스케줄링을 포함하고, CPU 메서드 시간과 같은 지표가 아니다. 정부 산업 CPU p95도 원문에 기록했다. 각 측정의 CPU 통계는 워밍업 포함70호출이다. 실제 모바일 GPU 성능은 후속 실기기 검증이 필요하다.

[원문 수치](performance-isolated.json) · [기준/대기 로그](logs/performance-isolated.log) · [이동 로그](logs/performance-active.log) · [측정 코드](measure-performance.mjs). 재측정은 5173 현재 빌드와 5176 기준 임시 서버를 켜고 `PLAYWRIGHT_MODULE`/`CHROMIUM_EXECUTABLE`을 지정해 측정 코드를 실행한다. `M1A_PROFILE=M1a-active`는 이동 조건만 재측정한다.

## 임시값과 한계·후속 연결

| 임시 항목 | 이번 값/정책 |
|---|---|
| 실제 길이·질량 계수 | 60m / 170m, 충전 질량 계수 1 |
| 초기 정거장 방향 | 데이터의 세 방향 벡터를 정규화해 지구 고궤도에 배치 |
| 추진·가감속 | 0.04 gAU/분, 등속, 현 경로의 구간마다 선회 |
| 궤도 배율 | 저1.05·중1.3 데이터만, 고1.6만 사용 |
| 장애물 여유 | min(0.4 gAU, 표시 반지름 20%) |
| 출발 LOS 후보 | 목표 방향 1개 + 균등 구면 32개, 고궤도 경계 |
| 구면 경로 | 최대 15° 현 분할, 평행 이동하는 비회전 천체 좌표계 |
| 자동 우회 | 점마다 선회/충전, 최대 8단·탐색 노드 160; 전역 최단 경로 보장 없음 |
| 연속 충돌 검사 | 보수적 속도 상한·최대 깊이24, 0.001초 미만 불확실 구간은 차단 |
| 목표 수렴 | 0.005초/48회 + 필요시 구간 해법 |
| 소행성 | 60+30개, 시드77191에 성계 ID 혼합, 전역40 gAU~관리 외곽 / 띠190–230, 경사 폭0.65/0.12rad |
| 우회 후보 | 반지름1.8/3/6배 × 수직면8방향 |
| 아이콘 | 3.6/4.4% 히스테리시스, 선택 우선 겹침 회피와 연결선 |

항법은 **함선 중심점 + 천체 여유 반경** 모델이다. 선체 전체의 swept volume이나 다른 함선과의 충돌은 구현하지 않는다. 특히 표시 함선이 작은 위성보다 클 수 있어 근접 시 외형 여유·정박 자세는 M1b에서 추가 조정할 부분이다. 경로 탐색 한도 또는 최종 접근이 막히면 기존 명령을 유지하며 다른 지점을 안내한다. 실기기 GPU 성능·모든 브라우저 호환성은 이번 Chromium 소프트웨어 환경만으로 보장하지 않는다.

M1b는 `highOrbitRadius`/저·중·고 배율, `localPath`와 출발 후보 공급부를 궤도 껍질·표면 꼭짓점으로 확장할 수 있다. 명시적 선택 확대 외에 행성권 줌 자동 추종을 추가하지 않았다. 추후 저장은 산업 JSON과 별도의 상위 캠페인 시계·함대 스키마를 설계해야 한다. M2 탐사, M3 경제 값 연결, 연구, 물류 배송, 화물, 건조, 연료, 전투, 호위·추적, 하이퍼펄스 사고는 모두 미구현이다.
