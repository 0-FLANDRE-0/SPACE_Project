## 0. 목표 / 구현 경계

**목표:** 플레이어가 행성 표면 섹터를 선택하고 섹터 정보 탭의 **육각형 정부 건설구획**을 눌러 국영 광업단지 또는 국영 제련단지를 건설하며, 게임 시간 경과에 따라 **광석 채굴 → 행성 내 정부 광석 재고 → 제련 → 합금 생산**을 실제로 경험하게 한다. 광산은 조건을 갖춘 섹터에서 **수소를 동반 회수하는 부산물**을 생산할 수 있다.

이번에 구현할 것:
1. 행성 **표면 섹터**별 정부 건설 슬롯(최대 1~4 / 현재 개방 / 사용 중 분리), 슬롯 UI, 건설·진행·완공 상태.
2. **국영 광업단지**, **국영 제련단지** 두 시설만 신설. 시설 규모(레벨), 장비 세대, 주요 개량모듈을 저장할 확장 가능 모델.
3. 정부 크레딧·행성별 정부 광석(저/중/고)·합금·수소 재고; 건설 자원 예약/차감; 배속 독립적 생산·잔량 정산.
4. 기존 섹터 매장지의 **채굴 난도, 가공 난도, 매장 형태, 환경, 문명별 인지**를 재사용.
5. 수소가 있으면 **제련 속도가 최대 +15%** 증가, 없어도 제련 가능. 광업단지의 **수소 동반회수 최대 100U/월**(적합한 원천이 있을 때).
6. 섹터 정보 탭 및 시설 상세·생산·건설 UI. PC와 모바일 가로/세로 기본 조작.
7. 새로운 런타임 저장·검증·회귀 테스트·문서. 기존 PR 기능 훼손 금지.

**이번 범위에서 제외:** 민간 경제/민간 생산, 거래·가격·물가·통화 발행, 행성 간 물류, 전력·노동·운영비의 실제 차감, 탐사 진행 타이머, 연구 시스템 효과 자동 연동, 함선 건조, 별도 수소 채집 전용 건물, 가스 행성 대기 채집 실운영, 오프라인 진행, 전투, 대규모 건설/운영 AI. 미래 연결을 위한 데이터 계약만 예약한다. **6h/12h/24h/초 신규 배속 UI도 이 패치에 임의로 추가하지 않는다.** 다만 큰 배속에 견디도록 정산 코어를 작성한다.

## 1. 변경 불가/근거로 삼을 기존 계약

- repo `AGENTS.md`, `SPACE_GAME_MASTER_HANDOFF_KO.md`에서 `[확정]`이 최우선. ZIP 백업의 `03`, `05`, `06`, `07`, `08`, `13`, `15`, `16` 참고.
- 지질 스냅샷 `dist/data/planet-surfaces/sol-*-v2.json` / `geology.cells[tileId].deposits[]`와 **2100년 startingScenario, 셀 ID/격자·환경·원본 지도**는 수정 금지. 지구·금성·화성·달 확정 자원 예산/품질 목표도 불변.
- 현재 `dist/src/planetary-surface-model.js`에는 표면 셀 `terrain.terrainType`, `environment.terrainObstacle`, `temperatureK`, `radiationLevel`, `startingScenario.cells[].infrastructureLevel`, 그리고 시설의 **초기 메타데이터**가 있다. 이것은 **런타임 시설 인스턴스가 아님**.
- 매장지별 `extractionDifficulty`(채굴 난도), `processingDifficulty`(가공 난도), `accessDepth`(상대 깊이), `initialReserveU`(원래 물량), `depositKind`(surface/vein/deep), `discoveryTier`, `groupId`가 있다. 섹터 전체에 난도 하나만 있다고 가정하면 안 된다.
- 원천 매장량의 진실값은 **각 매장지의 `initialReserveU` 한 곳**. 다중 셀 광맥 group의 물량을 셀마다 중복 복제 금지.
- `dist/src/resource-knowledge.js`의 문명별 인지/확인 정보와 실제 원천을 엄격히 분리. 미발견/미확인 매장량이 플레이어에게 새어 나오면 안 된다.
- `dist/src/ore-quality.js`: `sampleGradeBatch()`의 결정적 배치 등급 판정과 `INITIAL_ALLOY_YIELDS = {low:.14, medium:.33, high:.52}`를 재사용. 같은 배치의 저장/로드/RNG 재시도로 품질을 새로 뽑으면 안 된다.
- `dist/src/body-resource-generator.js`의 `hydrogenSources`는 **수소 잠재 원천**이며 현재 실제 재고/생산이 아니다. `finite-source`와 `atmospheric-collector`를 구분하고 지질 광석으로 위장 금지.
- `dist/src/time-control.js`에서 `1×=현실1초당 게임10초`, 현재 배속 0.1~100×. `dist/src/model.js` 시계, `dist/src/main.js` 진행 루프를 존중한다. 기존 시계/UI와 개발자 편집기 파괴 금지.
- **정부 슬롯은 섹터당 1~4개 대규모 정부 시설의 추상적 관리 슬롯**이지, 표면을 실제로 4개 육각형으로 추가 세분하는 지형 시스템이 아님. 섹터 표면은 실제로 오각형도 있으니 원래 격자 유지.

## 2. 상태 구분: 확정·합의 vs 잠정·미정

| 항목 | 적용 내용 | 상태 |
|---|---|---|
| 정부 시설 슬롯 | 섹터당 최대 1~4, 현재 개방/사용/최대 구분, 민간 슬롯 비점유 | **방향 합의** |
| 국영 광업/제련 | 각 1슬롯; 증설은 내부 규모 확장이므로 추가 슬롯 없음 | **합의** |
| 건설비 / 기간 | 광업 14,500C + 합금 1,200U / 6개월; 제련 24,500C + 합금 3,150U + 수소 120U / 8개월 | **현재 잠정 기준값** |
| 광업 최대 처리능력 | 설비 기본 5,000U/월(채굴 난도·가동률 반영 전) | **잠정** |
| 제련 최대 처리능력 | 수소 최대 사용 시 5,000U/월; 미사용 시 `5,000/1.15 ≒ 4,347.826U/월` | **잠정 수치 +15% 보너스는 최근 합의** |
| 수소 부산물 | 광업단지 1개가 적합한 원천이 있을 때 정상 가동 기준 **최대 100U/월**, 광석 채굴과 연동 | **수치 합의, 발생 가능 조건은 구현 제안** |
| 제련 수소 | 최대 사용량 85U/월, 사용 시 처리 속도 +15%; 미사용도 가동 | **현재 합의** |
| 제련 수율 | 저/중/고 14%/33%/52%; 수소가 수율은 높이지 않음 | **확정** |
| 생산량 | 화면에서는 U/월, 실제 재고는 게임 시간 경과에 따라 정산 | **합의** |
| 시설 가동 램프업 | 완공 직후 저가동 → 수개월 후 정상, 난도에 따라 기간 달라짐 | **방향 합의**, 곡선·개월 미정 |
| 채굴 효율 곡선 | 난도 0~100에서 연속·단조로 변화, 79→80 불연속 금지 | **방향 합의**, 수치 미정 |
| 지질·환경 건설 보정 | `terrainType`, `terrainObstacle`, `temperatureK`, `radiationLevel` 사용. 채굴 난도와 분리 | **방향 합의**, 정확한 공식 미정 |
| 시설 확대/개량 | 레벨·장비 세대 별개, 개량 비용은 규모에 따라 증가하되 규모의 경제 적용 | **방향 합의**, 공식 잠정 |
| 학습 경험 | 생산/건설 주체별 경험 + 일부 사회적 확산, 기술 연구 효과와 분리 | **방향 합의**, 할인 수치 미정 |
| 정부 재고 | 행성별/소유권별 재고; 현 단계에서 행성 내 시설 간 무물류 접근 | **현재 1차 범위의 합의** |
| 운영비·전력·노동 | 속성 필드 `null` (미정), 현재 가동 제한으로 적용하지 않음 | **데이터 자리만 예약** |
| 최소 매장량/슬롯 산출·해금 수치 | 실제 수치는 아직 사용자 미확정 | **구성 파일의 잠정값으로만 시범 구현** |

**`null`은 아직 설계되지 않음, `0`은 실제 비용/소비량이 0이라는 뜻이다.** 확정 여부를 UI·데이터/문서에서 오인시키지 말 것.

## 3. 데이터 계층 — 원본/런타임/인지 분리

정적 `planet-surface-template`의 지질과 시작 시나리오는 그대로 유지하고, 별도 버전 있는 **campaign industry runtime**에 기록한다.

- `worldTime.days` 또는 현재 `simulation.days`와 동일한 **경과 게임시간**(중복 시계 금지).
- `governmentTreasuries[civilizationId]`와 `planetInventory[bodyId][ownerId]`: `ore.low`, `ore.medium`, `ore.high`, `alloy`, `hydrogen`, 크레딧은 물질 재고와 분리.
- `oreRemaining[depositId]`: `initialReserveU`에서 채굴분을 감산한 실제 잔량. 초기화 누락 시 원본에서 유도. 원본 수정 금지.
- `hydrogenRemaining[sourceId]`: 유한 `finite-source` 원천의 실제 잔량. 대기 채집원은 별도 룰 전까지 이번 시설에서 소비하지 않음.
- `governmentSlots[bodyId][tileId]`: `maxSlots (1..4)`, `unlockedSlots`, `slotFacilityIds`(고유·고정 순서); 사용 슬롯과 잠금 이유. 슬롯 번호가 아닌 **시설 ID**로 실제 시설 참조.
- `facilityInstances[id]`: 종류(`government_mining_complex`/`government_smelting_complex`), 소유 문명/정부, system/body/tile/slot, level, equipmentGenerationId, installedModules(단지 단위의 큰 개량만), `status`, construction progress/time, active deposit IDs/source IDs, rampup progress, experienced production amount, production batch serials, current utilization, `monthlyOperatingCostC:null`, `powerDemandMW:null`, `laborDemandPersons:null`, optional reserved construction resources.
- `productionExperience`: 주체+설계 계열(+환경 전문성)별 누적량을 미래 용도로 보존, 아직 크레딧/합금/시간 자동 할인 적용하지 않음.
- `inventoryLots`: 생산된 저/중/고 광석 배치의 **원천 매장지 ID 및 `processingDifficulty`**를 보존할 수 있어야 함. UI에는 품질별 합계로 보여주되, 나중에 가공 난도를 적용할 때 광석 출처 정보를 잃지 말 것.
- `productionHistory`/`eventLog`: 최근 게임 월의 실제 생산량, 소모량, 시설 가동/정지 이유를 요약 저장. 저장 성능을 위해 무한 로그 생성 금지.

**호환:** 기존 `startingScenario.cells[].facilities`는 시작 상태에 대한 메타 정보이지 런타임 생산 시설이 아님. 혼용/덮어쓰기 금지. 기존 localStorage 표면 초안/manifest/관리구역 저장키를 보존하고 신규 저장키·schemaVersion·명시적 로드/검증/백업 정책을 적용. 캠페인 저장이 없어도 새로고침 시 광물 고갈과 재고가 복제되거나 삭제되지 않아야 한다. `simulation.days`와 정산 기준시각을 함께 복원하거나 동등한 일관 저장 정책을 채택하되 기존 1× 기본 배속 리셋 정책은 훼손하지 않는다. 고장 난 저장은 **파괴/자동 덮어쓰기 없이** 경고·백업·격리.

## 4. 섹터 건설 슬롯과 건설 명령

- **표면 섹터를 클릭**하면 전용 섹터 정보 탭. 탭에서 작은 **육각형 건설구획** 최대 4개를 표시한다. 이는 **UI용 추상 슬롯**이며 기존 실제 오각형/육각형 지오메트리 분할이 아님.
- 최대 슬롯을 정하는 최종 면적·환경 공식은 미정이다. 1차 구현에선 `construction-slot-policy`처럼 외부 조정 가능한 **잠정·결정적** 정책을 작성할 것. 계산 시 이미 얻은 `tile.areaWeight`/실제 면적/지형·기반시설을 사용하고 행성 반지름을 중복 곱하지 말 것. 특수 지형을 임의의 0슬롯으로 확정하지 않는다. 각 슬롯은 `잠김`, `사용 가능`, `건설 중`, `가동 중`, `정지/고갈`을 표시한다.
- 사용 가능 슬롯 클릭 → **건설 메뉴**(국영 광업/국영 제련) → 조건·기간·비용·예상 생산·금지 이유 확인 → 명시적 건설 지시 → 비용 예약/차감 **1회** → 진행 → 완공 후 가동 준비.
- 정부 광업 건설 자격: 선택 섹터에서 문명에 **확인된·현재 접근 가능한** 자원 매장량이 잠정 최소치 이상이고, 지형/기술 조건을 통과해야 함. 실제 미발견 광맥의 존재/정확한 매장량을 UI나 불가 사유로 누설 금지. 최소치는 아직 미확정이므로 구성 가능/기록 가능하게 시범값만 배치.
- 정부 제련은 **같은 섹터에 광맥 없어도 건설 가능**. 같은 행성의 정부 광석 재고를 처리함.
- 초기 정부 C/합금/수소 재고 시나리오는 임의로 거액 지급해 해결하지 말 것. 시작 재고가 미정이면 별도 **개발용 fixture**와 정식 시작 시나리오를 구분해 검증한다. 수소 없이 제련이 가동할 수 있는 것과 **제련단지 건설에 수소 120U가 필요**한 것은 별개의 조건이다.
- 자원 부족 시 건설 불가/대기 사유 표시; 요청 반복·UI 중복으로 이중 차감 금지. 중도 취소/환불 정책 미합의이므로 임의 100% 환불·소모를 확정하지 말고, 명확히 정의하기 전까지 취소 기능을 별도 보류하거나 임시 정책으로 문서화.
- 6개월/8개월은 게임달의 최종 정의가 아직 없으므로 1차 정산 시 **1개월=30게임일**을 잠정 설정으로 둬도 되지만 상수 분리 및 UI에서 잠정 설명. 세계 UTC epoch를 2100년으로 무작정 재설정 금지.

## 5. 국영 광업단지 — 채굴·램프업·잔량

- 건설기본: **14,500 C + 합금 1,200 U / 6개월**, 정부 슬롯 1칸; 증설해도 1칸, 장비 세대·개량과 분리.
- 레벨 1 이상적 기준 **최대 5,000U/월**은 잠정 생산능력. 실제 생산은 선택한 **매장지별** `extractionDifficulty`, `accessDepth`, 가동준비율, 남은 매장량, 장비 기술을 반영.
- 난도 보정 `extractionEfficiency(d)`는 0~100 입력, 연속·단조 비증가, 양의 하한. 가동 준비기간 `rampDuration(d)`도 연속·단조 비감소. **난도 79↔80 단차 금지.** 예시 3~8개월 및 생산 25~100% 범위는 튜닝 제안일 뿐 고정값 아님. 개별 매장지 난도와 섹터 환경의 **중복 페널티 금지**.
- 시설 완공 직후 낮은 생산력에서 일정 게임 개월에 걸쳐 100% 가동 준비. **증설 시 기존 생산분은 계속 가동**, 늘어난 처리용량만 별도 램프업. 규모/장비 세대/부위별 신규 투자 상태가 식별되어야 함.
- 채굴 배치를 생성할 때 정확히 `oreRemaining` 감산 → `sampleGradeBatch(depositId, batchSerial, amountU, effectiveGradeProbabilities, seed)` 호출 → 저/중/고 광석 lot(정부 행성 재고)에 추가. **입력 quanta 합계와 품질 합계가 같아야 함**. 프레임 수·배속에 따라 batchSerial/RNG가 바뀌면 안 됨. 기존 원본 `initialReserveU` 변경 금지.
- 원광만 채굴하며 합금 직접 생성 금지. 매장량 0이면 해당 원천 생산 정지. 미확인 원천을 게임 엔진이 몰래 자동 선택 금지.

## 6. 광업단지 수소 부산물(동반 회수) — 새 UI 요청 반영

**플랑의 방향:** 수소는 광업단지에서 함께 회수되는 **부산물**로 보여주고, 적격 광업단지 하나의 정상 가동 기준 **최대 100U/월**. 별도 수소 채집 건물을 이번 패치에서 만들지 않는다.

**기존 지질과 충돌하지 않는 구현 규칙:**
1. **수소 원천이 있는 섹터만** 동반 회수 가능. 정적 `hydrogenSources`의 같은 `tileId`에 연결된 `finite-source` 중 실제 접근/이용 자격이 있는 원천을 사용. 광석 자체에서 수소를 무에서 생성하거나, 모든 광산에 무조건 +100U/월을 부여하지 않는다. 얼음·수화물·수분 원천을 채굴·처리하는 과정에서 동반 회수한다고 해석.
2. 실제 수소 출력을 광산의 **실제 가동 상태·채굴 활동량**에 종속. 광석 생산이 0이면 수소 부산물도 0. 최대 100U/월을 넘지 않으며 유한 수소 원천 잔량을 실제로 감소시킴.
3. 해당 섹터에 수소 원천이 없거나 접근 기술이 없다면 **광석은 채굴 가능하지만 수소 부산물은 0**. `atmospheric-collector`는 가스 행성/대기 채집 전용 후속 시스템에 예약; ore 없는 가스 대기층에 광산을 억지 배치하지 않는다.
4. 현재 `initialResourceKnowledge`는 ore 인지만 모델링하므로 **수소 원천의 공개/접근 정책은 별도 잠정 계약으로 명시**. 모든 잠재 수소 원천을 즉시 일반 UI에 노출하지 말 것. 건설 가능한 이유를 통해 미발견 수소 원천이 누설되지 않게 한다. 초기 수소를 실제로 확보하는 방법이 없는 캠페인은 개발 fixture로 해결하고 공개 플레이에는 준비가 되었을 때만 개방.
5. 섹터 정보에 `수소 부산물: 예상 0~최대 100 U/월 (조건부)` / `실제 생산` / `원천 확인 상태`를 분리. **`100U/월`은 보장량이 아닌 설비 상한.**
6. 다른 방식(모든 광산에서 기본 100U/월 생성)은 사용자가 별도 승인하기 전까지 **확정하지 않는다**.

## 7. 국영 제련단지 — 수소가 없더라도 작동

- 건설기본: **24,500 C + 합금 3,150 U + 수소 120 U / 8개월**, 정부 슬롯 1칸. 제련단지 자체에는 광석 매장지가 필요 없음.
- 광석을 같은 행성의 **정부 소유** 저/중/고 원광 lot에서 공급받아 합금으로 전환. 원광이 부족하면 실제 처리량이 줄고 재고 음수 금지.
- **수소를 쓰지 않는 기준 처리능력**(잠정) `5,000/1.15 ≒ 4,347.826 U/월`. **수소 보조 최대로 가동 시** `5,000 U/월`. 수소 최대 소비 **85U/월**, 실제 광석 처리와 가동률에 비례해 0~85U/월 소비. 수소가 없을 때도 제련 가동 가능. 부족 시 **연속적으로** 보너스가 감소한다(즉시 정지/1단계 절벽 금지).
- 수소 **+15%는 원광 처리속도 보너스**이지 광석 품질 확률/합금 수율 보너스가 아님. 저/중/고 광석 1U의 기본 합금 수율 **0.14/0.33/0.52** 그대로, 잔여물(`residueU`) 별도 보존. 수소 소비/처리량/잔여물의 질량 회계 검증.
- 광석의 `processingDifficulty`는 채굴 난도와 다르고, **제련 처리 능력·원료 구성에 대한 독립적인 잠정 보정**. 원광 lot의 출처 값을 잃지 않아야 함. 확정 수율에 가공 난도를 중복 감산하지 않는다.
- 수소 사용 설정: 기본 `자동(있으면 사용)`으로 시작하되, 플레이어가 **사용/미사용을 전환** 가능. 끌 때 수소 소비 0, 저속 제련은 계속.

## 8. UI/UX — 섹터 클릭에서 건설까지

### 8.1 진입 흐름

`행성/위성 선택 → 표면 지도 열기 → 섹터(실제 다각형) 탭/클릭 → 섹터 정보 탭 → 작은 육각형 정부 건설구획 1~4개 → 구획 선택 → 건설/시설 상세`

- 기존 표면 셀 선택·표면 생성/자원 개발자 UI·지도 카메라·기타 컨텍스트 패널의 **모드 우선순위 유지**. 개발자 도구가 일반 모드에 노출되면 불합격.
- 우측/하단 정보 탭은 탭 전환형: `개요` / `정부 건설구획` / `자원·산업` (같은 섹터의 연속 정보). 정보 과밀 방지, 모바일 스크롤 가능. 필요 시 상위 행성 재고는 별도 간단 요약.
- 슬롯을 클릭해도 지도상의 표면을 다시 세분하거나 추가 육각 지오메트리를 생성하지 않는다.

### 8.2 섹터 정보 탭에 표시할 항목

- 섹터 ID, 천체명, 지형 유형, 환경(알려진 수치/미확인 표기), 셀 실제 면적, 인구·기반시설(존재하는 값만), 건설 가능한 시설/차단 사유.
- **인지된 자원만**: 발견된 광석, 확인된 추정량, 등급 정확도·접근 조건. `initialReserveU`와 실제 숨은 지질값은 일반 UI에 노출 금지. 광맥 상세·확률·시드·groupId는 개발자 모드 전용.
- 정부 슬롯 `사용 중 / 현재 개방 / 최대` (예 `1/2/4`), 사용 불가 슬롯은 잠금 사유. 각 구획 상태는 **육각형 버튼**의 아이콘/상태 텍스트로 표시(색상만으로 구분하지 않음).
- 국영 광업·제련 시설 목록: 이름/종류·Lv·장비 세대·생산·재고·가동률·건설 잔여시간·증설/개량 가능 여부. 더 상세한 값은 시설을 클릭한 뒤 펼쳐 표시.
- 행성 공용 정부 원광(품질별)·합금·수소 재고와 최근 월 생산/소비량. 민간 재고를 무료 정부 재고로 합산 금지.

### 8.3 육각형 슬롯 상태 및 조작

- **빈 슬롯**: 큰 `+`, 터치 → 건설 메뉴. 현재 선택 섹터의 광업 가능 여부를 알아볼 수 있고, 불가 시 구체적 이유(슬롯 부족, 확인 매장량 부족, 예산/합금/수소 부족 등)를 표시.
- **건설 중**: 시설 아이콘, 건설명, 진행률/남은 게임 일수, 예약 자원. 완료 시 `완공 → 가동 준비`로 자연스럽게 전환.
- **가동 중**: 광업/제련 아이콘, 현재 U/월, 램프업, 생산 대상·수소 동반회수/보조 사용 상태, 레벨 및 세대 표시.
- **정지/고갈**: 어떤 재고/매장/조건이 부족한지 표시. 오류처럼 원본에 빈 데이터를 덧쓰기하지 않음.
- **잠긴 슬롯**: 자물쇠, 해금 이유 설명. 미발견 광맥 위치 누설을 일으키는 힌트 금지.
- **증설/개량**: 시설 상세 버튼에서 분리. 비용은 실제 개량 대상 규모에 비례하고 대규모 할인 적용 가능하지만, 최초 예시 `Lv1=5C, Lv5=23C`를 실제 비용으로 하드코딩하지 말 것. 건설비/장비 세대/추가 램프업은 구성 가능. 구형/신형 설비 혼합 시 구형 대상만 개량비 부과.
- PC 클릭·터치 탭·키보드 포커스 지원. 667×375 / 844×390 모바일 가로 및 390×844 세로에서 슬롯 선택·탭 닫기·리스트 스크롤이 가능해야 함. 터치 타깃 40~44px 권장. 탭이 카메라 이동/행정 편집으로 이벤트를 누출하면 안 됨.

## 9. 환경·건설 난도는 채굴 난도와 별개

- **건설 비용/시간 보정:** 주로 `terrainType` + `terrainObstacle` + `temperatureK` + `radiationLevel` + `infrastructureLevel`에서 산출하되 상호 상관된 환경을 중복 곱하지 않는다. 강한 극한 환경은 관련 기술이 없으면 건설 불가로 남겨둘 수 있으나 해금 연구는 이번 패치에 넣지 않는다.
- **가동/생산 보정:** 선택한 매장지의 `extractionDifficulty`와 `accessDepth`, 제련의 `processingDifficulty`를 활용한다. `terrainObstacle`을 채굴 난도와 동일하게 또 큰 페널티로 곱하지 않는다.
- '달은 표면 채굴 쉬움/가공 어려움', '금성 채굴 80+ 극한', '지구 바다의 해저 단괴 80+'가 실제로 구분되어야 함.
- **학습 곡선:** 생산 주체별 경험 + 일부 지식 확산. 현재 경험 데이터만 쌓고 할인 효과는 잠정 정책을 승인·시험하기 전에는 실제 적용하지 않는다. 기술 연구와 건설 경험 효과 분리. 향후 할인은 크레딧/시간/물질 각각 별도 하한 및 중복 적용 가드.

## 10. 정산·저장·게임 시간 일관성

- 단위 `1U=10톤`, 광석/합금/수소 U, C는 독립 장부. 광석 최소 정밀도 **0.001U** 기존 계약 유지; 반올림 잔량 누적으로 물질 생성·소멸 금지.
- 시설 건설시간 6·8개월은 게임 시간으로 경과. 프레임 속도에 의존하지 않는 **고정 게임 시간 틱 또는 동등 이벤트 기반** 처리. 월 생산량은 화면 표기이고 **월말에만 한번 생성하지 말고 게임 시간 동안 정산**.
- 생산 처리 순서가 일관되어야 함: 시설 건설/완공 판정 → 가동 상태·수송/전력(후속) → 광산 매장량 차감/품질 판정/수소 회수 → 행성 정부 재고 반영 → 제련의 원광·보조 수소 소비 → 합금·잔여물 추가. 동일 타임스텝에 광산이 생산한 것을 제련이 쓰는 정책도 한 번 정하면 항상 동일해야 함.
- 게임 배속 0.1×/1×/100×, 프레임 묶음 변화, 일시정지/재개, 브라우저 종료/명시적 저장·재로드 시 **동일 게임 시간에 실질적으로 동일한 결과**. 시간 누락/중복 정산 금지.
- 현재 프로토타입에서 숨김 탭 시간은 진행하지 않고, ≥60초 장기 브라우저 멈춤은 중단 처리. 이 정책과 현재 epoch 유지. 신규 6h/12h/24h 배속은 별도 후속 이슈로 취급.
- 생산 전에 필요량·현재 잔량·저장 수용성을 검증하며 음수 재고·원천 잔량 발생 금지. 저장 불가 시 내보내기/경고, 알 수 없는 schema나 훼손 원본 자동 덮어쓰기 금지.

- 버전/유효성 있는 시설·슬롯·재고·원천 잔량·경과 게임시간 스키마.
