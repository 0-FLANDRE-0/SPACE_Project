# v0.5E 산업 런타임 및 섹터 정보

기준: PR #6 `47c062b6d35bf75487a5b42c31893613ca5f9c3f`. 요청 초안과 사용자 승인/UI 보강을 함께 적용한다.

## 사용 흐름

일반 사용자는 천체 → 표면 지도 → 실제 섹터를 선택한다. 왼쪽에 일반 정보, 오른쪽에 정부 슬롯과 현재 게임월 실적·행성 정부 재고를 표시한다. 구획을 선택하면 왼쪽 내용만 건설 목록이나 시설 상세로 바뀐다. 선택된 구획을 다시 누르거나 뒤로가기로 일반 정보에 돌아가고, X로 패널을 닫는다. 지도에 추가 셀을 만들거나 카메라를 움직이지 않는다.

정식 시작 재정/재고는 미정이다. 크레딧은 null로 두어 자원 지급 없이 건설 차단 이유를 표시한다. 공개 플레이의 경제 시작 상태가 확정되었다는 뜻은 아니다.

산업 루프를 시험하려면 `?dev=1` 또는 로고 7회 탭으로 개발자 모드에 들어가 DEV → **산업 개발 시나리오 열기**를 누른다. 별도 시나리오가 지구에 100,000 C, 합금 10,000 U, 수소 500 U를 제공한다. 지구의 기존 유한 수소 원천 하나와 같은 섹터의 기존 광석을 런타임 조사 완료로 가정한다. 표면 프리셋·지질·2100 시나리오는 변경하지 않는다. 같은 버튼을 다시 눌러도 재지급하지 않는다.

이 섹터의 빈 구획에서 광업을 지시하고 다른 섹터의 빈 구획에서 제련을 지시할 수 있다. DEV의 +30일/+180일은 개발 검증 명령이며 신규 배속 UI가 아니다. 일반 0.1~100×와 기존 epoch를 유지한다. 건설 완료 후 램프업·채굴·조건부 수소 회수·원광 출처별 제련을 확인한다. 일반 캠페인 복귀 버튼은 별도 저장을 복원한다.

## 시간·수량·원천

- `simulation.days` 하나를 사용한다. 런타임의 `days`는 그 시계의 저장 체크포인트이며 별도로 흐르는 시계가 아니다. 시작 기준 `originDays`에서 고정 게임 1시간을 계산하고 완료된 시간만 정산한다. 최대 1시간 미만은 저장된 날짜에서 다음 정산으로 이어진다.
- 한 시간의 순서는 건설·투자 완공 → 시설 ID 순 광업 → 시설 ID 순 제련이다. 같은 시간에 나온 원광과 수소를 같은 행성의 제련이 사용할 수 있다. 다른 행성·소유자 재고는 참조하지 않는다.
- U 값은 장부에서 정수 quanta(0.001 U)로 저장한다. 처리능력의 소수는 시설별 이월값으로 보관한다. 광석 품질 합계는 입력 quanta와 같고 `sampleGradeBatch`의 키는 시드+시설 ID+원천 ID+영속 배치 일련번호다.
- 매장지 잔량과 누적 채굴의 합은 원본 `initialReserveU`와 같다. 광맥 group 물량을 복제하지 않는다. 확인된 개발 가능 물량까지만 채굴하고 조사되지 않은 원천으로 자동 전환하지 않는다.
- 원광 lot는 행성/소유자/원천/품질별로 합산하며 원천 ID와 `processingDifficulty`를 보존한다. 제련 소비 순서는 원천 키, 저→중→고 순서인 잠정 정책이다.
- 제련 수율 14/33/52%는 고정이다. 1 quanta 미만 합금 계산의 나머지를 이월하고 입력=합금+잔여물 장부를 유지한다. 가공 난도는 처리 속도에만 적용한다.
- 수소 부산물은 확인된 같은 섹터 유한 원천에서만 회수한다. 실제 광석 채굴량에 비례하고 단지당 최대 100 U/월이다. 원천/인지/채굴이 없으면 0이며 대기 채집원은 사용하지 않는다. 정식 수소 인지 정책은 미정으로 두고 개발 시나리오에서만 명시적으로 확인 상태를 설정한다.
- 제련 수소 자동/미사용을 전환한다. 현재 보유 수소에 따라 연속적으로 처리속도 보너스가 감소한다. 수소가 0이어도 기본 처리능력으로 가동하며 수율을 바꾸지 않는다. 수소 소비는 실제 처리량에 비례한다.
- 최근 12게임월 시설별 실적, 최근 이벤트 80개만 보관한다. 경험은 생산 주체/설계 계열 및 완공 작업량별로 누적하고 건설 경험의 10%를 사회적 확산 지표로 별도 기록한다. 이 비율도 잠정이며 어떤 할인/연구 효과도 적용하지 않는다.
- 재고의 시범 수치 상한은 자원 종류별 10¹² U, 원광 출처 기록은 20,000개다. 광업은 원천 차감 전에 수용 가능 여부를 검사하고, 제련도 합금·잔여물 수용 한도 안에서 처리한다. 수소 재고가 가득 차면 유한 수소 원천을 추가 소비하지 않는다. 저장 시설이나 경제적 보관 비용을 구현했다는 뜻은 아니다.

## 저장 계약

새 키는 `space-project:industry:v1:{systemId}`이고 개발 캠페인은 `:fixture` 접미사를 사용한다. 기존 표면/관리구역 키는 그대로 둔다. 스키마 버전은 1이며 `kind=campaign-industry-runtime`이다. 이 초기 스키마는 출시 전 변경이며 구버전 자동 이행을 하지 않는다.

현재 태양계 표면 19개를 먼저 읽어 카탈로그로 고정한다. 저장에 각 표면 템플릿 서명을 기록하고 다시 로드할 때 확인한다. 개발자 편집으로 지질/시나리오가 바뀐 기존 산업 저장을 무조건 새 원천에 연결하지 않는다. 서명이 달라지면 원본을 보존·격리하고 경고한다. 서명은 변경 감지용이며 인증용 암호 해시가 아니다.

10초 주기, 명령 후, 시스템/캠페인 전환과 pagehide에 시계·잔량·배치·재고를 함께 저장한다. 배속은 기존처럼 새 접속 시 1×다. 숨김 탭 및 60초 이상 브라우저 중단에 오프라인 생산을 적용하지 않는다. 저장 실패 시 메모리 상태를 유지하고 경고·JSON 내보내기를 제공한다. 캠페인 복원은 파일 검증→확인 체크→기존 raw 저장의 `:backup` 백업→시계와 산업의 동시 복원 순서다. 손상/알 수 없는 버전은 자동 덮어쓰지 않는다.

원본 지질·환경·격자·셀 ID·2100 시나리오·원본 지구 자료 및 19개 프리셋은 변경하지 않는다. 기존 시나리오 `facilities` 메타데이터를 런타임 단지로 자동 운영하지 않는다.

## 잠정값과 남은 정책

| 항목 | 이번 구현의 잠정값 |
|---|---|
| 게임월/정산 | 30일 / 1시간, 명령은 마지막 완료 시간 틱 기준 |
| 광업 최소 확인 물량 | 1,000 U |
| 기본 접근 | 발견 단계 ≤1, 상대 깊이 ≤25; 개발 시나리오만 단계 ≤5/깊이 ≤100 |
| 슬롯 최대 | 실제 면적 `4πr²×areaWeight`에서 1~4; radius를 중복 적용하지 않음 |
| 개방 슬롯 | 기반시설 2단계마다 +1, 최대 이내. 추가 해금 명령/비용은 미정 |
| 환경 보정 | 지형/장애/온도/방사선 중 최대 부담 하나와 기반시설 완화; 고온 >600 K 및 대기층 차단 |
| 채굴 난도 | 0→100에서 효율 100→25%, 준비기간 3→8개월의 연속 곡선, 깊이 별도 완만 보정 |
| 제련 가공 난도 | 0→100에서 처리효율 100→50%, 고정 수율 유지 |
| 완공/추가 용량 | 10%에서 램프업. 증설 전 용량은 계속 가동 |
| 장비 | gen1→gen2 시 최대 +10% 용량을 추가 램프업, 구형 설비에만 비용 부과 |
| 투자 규모 | 최대 Lv5, 규모^0.9에 증설 0.65/개량 0.35 비율과 환경 보정 |

시작 재정/정식 수소 조사·접근·소유권 미지정 구역의 최종 권한, 슬롯 해금, 매장지 수동 전환, 취소/환불·교체·철거는 후속 결정 사항이다. 소유권이 설정된 타 세력 구역은 차단한다. 소유권 null 구역의 시범 건설은 확인 자원과 정부 예산 조건에 따른다. 운영비·전력·인력은 null이며 제한·차감을 적용하지 않는다. 수요와 취소·교체·철거 버튼에 미정 상태를 표시한다. 민간·물류·전투·연구·새 배속·오프라인 진행은 추가하지 않는다.
