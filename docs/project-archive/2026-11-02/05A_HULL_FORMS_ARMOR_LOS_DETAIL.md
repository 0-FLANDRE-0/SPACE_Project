## 1. 세 계층을 절대로 합치지 말 것

| 계층 | 정하는 것 | 정하지 않는 것 | 상태 |
|---|---|---|---|
| **함급(크기 분류)** | 물리적 규모 범주. 현재 명칭은 마이크로·초소형·소형·중소형·중형·중대형·대형·초대형·타이탄 | 고정 임무, 무장, 단일 선체 외형 | [사용자 방향] |
| **선체 형식(hull form)** | 한 함급 안에서 선택할 **특정 고정 형상**, 선체 표면·방향성과 **면별 장갑 최대 두께** 등 그 형식 고유의 설계 한계 | 실제로 몇 mm 장갑을 붙였는지, 어떤 무장·기관을 탑재했는지 | [최근 사용자 결정] |
| **개별 함선 설계(build/loadout)** | 선택한 선체 형식 내에서 장갑 재질·부위별 실제 두께·발전·추진·센서·무장·화물/특수모듈의 배치 | 다른 형식의 외형/상한을 무상으로 복사한 결과 | [사용자 방향] |

- 같은 **중대형 함급**에도 서로 다른 선체 형식이 존재할 수 있다. 중대형의 모든 함선이 같은 외형이라는 해석은 **폐기**.
- 어떤 선체 형식이 중장갑을 허용해도, 해당 형식으로 만든 모든 함선이 자동으로 최고 장갑을 갖는 것은 아니다. 최대치는 **상한**이지 **기본 장착값**이 아님.
- 전투함·순양함·정찰함·산업지원함·전자전함·차단함 같은 **임무/함종 표기는 설계 결과의 역할**이다. 함급별로 전투 역할이 강제되지 않는다.
- 특정 선체 형식의 이름·수량·치수·모듈 슬롯 구조는 아직 [미정]. 9개 함급에 형식 9개만 존재한다거나 함급마다 임무별 형식이 반드시 하나씩 있다는 식의 숫자 추가는 금지.

## 3. 선체 형식이 갖는 설계 제한 — 구체화와 미정 분리

### 3-1. 사용자 결정으로 취급할 내용

- 선택된 **형식의 기본 외형**이 실제 기하학적·전술적 차이를 만든다.
- **면별 최대 장갑 두께**는 선체 형식에 따라 달라진다. 모든 면에 동일 상한 하나를 일괄 지정한다고 추정하면 안 된다.
- 플레이어는 허용 상한 안에서 **실제 장갑 재질과 두께**를 지정하며, 장착 모듈 구성에 따라 함선의 최종 질량·건설소재·비용·전투 능력이 바뀐다.
- 함선의 실재 외형은 공격의 **진입 방향, 피격 지점, 노출 장비, 입사각/LOS 경로, 도탄·관통 가능성**에 영향을 줘야 한다.

### 3-2. 구현을 위한 데이터 분리 제안 — 아직 확정 스키마 아님

- **형식 고유 데이터:** 형상/좌표 기준, 표면과 방향·법선, 장갑 배치 구역 식별자, 구역별 허용 두께 상한, 실제 설치 가능한 위치/장비 제한을 표현할 수 있는 근거 데이터.
- **개별 설계 데이터:** 형식 ID 참조, 각 장갑 구역의 선택 재질·실제 두께, 설치된 장비·위치·방향, 전력·냉각·추진·탄약·화물, 설계 버전.
- **운용 중 상태:** 각 부위의 현재 손상/장갑 상태, 실제 모듈 고장과 온도·전력·기동·연료, 전투 이력.

세 계층을 하나의 '함급 스탯'으로 뭉치면, 같은 함급 안에서 다른 선체 형식을 고른 의미가 사라진다.

**미정:** 선체 표면을 전/후/좌/우/상/하 여섯 면으로 고정할지, 더 세밀한 다각형·부위별 구역을 둘지 / 하드포인트 형식 / 장갑의 연속 두께값·계단값 / 허용 두께를 결정하는 구조 강도와 기술. 여기서 여섯 면 체계를 공식 규칙으로 확정하지 않는다.

### 3-3. 최신 사용자 정정: 고정 선체 형식 안에서도 내부 공간 배분은 변경 가능

- **[사용자 확정]** 선체 형식의 외부 윤곽은 고정이지만 플레이어가 **함선 설계 단계에서 내부 공간(화물칸 등)을 늘리거나 다른 용도로 배분**할 수 있다. 따라서 고정 선체 형식이 곧 단 하나의 내부 구성/화물 용적까지 고정한다는 뜻은 아니다.
- **[설계 해석·제안]** 내부의 유한 총 공간·설치 부피/장착 위치를 검증하고 화물 공간을 넓히면 다른 장비/격벽/연료실 등에 활용할 공간이 줄어드는 식으로 구현 가능하다. 그러나 **물리적 외피 바깥으로 공짜 부피를 창출**하거나 형식별 최대 장갑 두께를 무제한 완화해서는 안 된다.
- **[미정]** 선체별 실제 용적, 탄약·화물 공간 SCU 용량, 발사기/포탑/엔진의 하드포인트 점유율, 무게중심/가속에 따른 화물 제한.
- 근거: [10 Claude 대화 보충 §9.6](10_CLAUDE_DISCUSSION_SUPPLEMENT.md); 실제 설계기 구현은 아직 없음.

## 4. LOS 두 의미를 구별할 것 — 특히 중요한 용어 충돌

과거 자료에서 'LOS'는 문맥에 따라 서로 다른 질문을 가리킬 수 있다.

1. **시선/가시성(Line of Sight):** 공격 지점에서 목표 선체의 **어떤 실제 표면·모듈이 보이는가?** 다른 표면·구조물에 가려진 부위를 바로 공격할 수 있는가?
2. **장갑의 시선 방향 관통 경로(LOS armor path / line-of-sight thickness):** 이미 **맞은** 장갑에서 공격 진행 방향이 장갑 표면에 대해 얼마나 비스듬하여, 내부까지 진행하는 경로가 얼마나 되는가?

두 개를 동일한 'LOS 보너스 +N%'로 처리하지 말 것. 위 1번은 **타격 가능 부위와 명중 위치**에, 2번은 **해당 부위 관통 과정**에 쓰이는 서로 다른 효과다. 용어 해석 자체를 게임 내부 명명으로 통일하는 방식은 [미정].

## 5. 실제 형상이 전투에 적용되는 단계

이하 단계는 **[기존 합의 방향을 구현 흐름으로 해석한 제안]**. 수식과 사건 분할은 미승인이다.

1. **방향/자세 확인:** 공격자-표적의 상대 위치·시선 방향과 표적의 실제 3D 자세를 확인한다. 속도벡터와 함선이 바라보는 방향은 같을 필요가 없다.
2. **관측/추적:** 센서가 제공하는 위치·형상/식별 신뢰도, ECM/ECCM 및 FCS 조건을 분리한다.
3. **발사·명중 사건:** 거리, 상대 기동, 무기 분산, 추적 상태, 목표의 투영 실루엣과 사격 가능 방향에 근거해 **확률적으로 판정**한다. 모든 탄자를 매 프레임 완전 물리 적분해야 한다는 뜻은 아님.
4. **실제 피격 표면:** 명중한 경우 시선에 노출된 형상/실루엣과 조준 오차를 바탕으로 실제 맞은 표면·모듈 위치를 선택한다. 숨겨진 후면 모듈이 정면 공격에서 아무 근거 없이 직접 명중되지 않도록 한다.
5. **국소 관통·도탄:** 해당 표면의 실제 장갑 재질·두께·법선, 탄착 방향, 무기/탄종·에너지, 이전 국소 손상 등을 이용한다. 경사에 따른 경로 증가와 도탄 성향은 **같은 입사기하의 효과이므로 근거 없이 이중 가산하지 말 것**.
6. **국소 손상:** 관통·비관통·파편/외부 노출 등 실제 결과에 따라 맞은 부위와 연결된 장갑·센서·포탑·추진·FCS·발전·냉각·내부 모듈 상태를 변화시킨다.
7. **전투 상태:** 함선 전체 HP 하나만으로 폭발을 결정하지 않고 기동·교전·도약 불능, 후퇴, 수리, 나포 가능 상태로 연결한다.

**입사각이 크면 무조건 도탄한다거나, 경사 장갑에는 별도 고정 회피율이 붙는다는 식의 단순 보너스는 [미채택].** 무기 성격에 따라 경사/도탄의 효과는 다를 수 있고 정확한 확률·관통식은 [미정].

## 6. 선체 형식 두 가지를 고르는 상황 — 수치 없는 예시

**[설명용 가상 예시, 실제 공식 형식명/스탯 아님]**

같은 중대형 함급에 A/B 두 선체 형식이 있다고 가정한다.

| 비교 | A 형식(상대적으로 평평한 넓은 측면) | B 형식(상대적으로 경사진 측면) |
|---|---|---|
| 형상 | 넓은 평면 측면 | 경사면/다른 돌출 구조 |
| 장갑 선택 | A의 해당 면 최대 두께 안에서 재질·두께 선택 | B의 **다른** 해당 면 상한 안에서 선택 |
| 정면/측면에서 노출 | 공격 방향에 따른 실제 투영면 변화 | 방향에 따른 다른 노출 실루엣·모듈 가림 |
| 탄착 시 | A의 실제 법선·장갑 상태에 따라 처리 | B의 다른 입사각/LOS 경로·도탄 조건에 따라 처리 |
| 운용상의 대가 | 모듈 공간·질량·사격각 등은 실제 설계 후 판정 | '경사'만으로 무조건 상위 형식이 되지 않음 |

B는 어떤 방향에서 유리할 수 있지만, 반대로 내부 모듈 배치·피격면·사격각·선회·무게중심 제약 등에서 다른 선택을 강요할 수 있다. 이런 **장단점의 존재는 해석 제안**이고, 구체적으로 어떤 형식이 어떤 보너스를 갖는지는 결정하지 않았다.

## 7. 함선 실제 질량·건조비와 선체 형식을 연결

- 장갑을 더 붙이면 해당 구역의 실제 장갑 질량과 필요한 소재·공정/건조비가 증가하는 것이 자연스럽다. 면적·부피·밀도·제작손실 등을 사용할 수 있으나 **구체 계산식/재료 밀도/보정계수는 미정**.
- 고정 골조와 실제 설치된 추진기·발전기·무장·탄약·연료·화물·보강재 등의 질량을 구분해야 한다.
- **건조 합금 U = 완성 함체의 톤 수**로 단정할 수 없다. 제작 투입과 최종 질량은 서로 다른 장부이며, C와 자원 U의 실제 거래도 별개.
- 과거 HAC **1,580,000C + 합금 58,000U**는 [잠정 건조 목표]. 최근 HAC **약 280~300m 초반**은 [초기 길이 구상]. 두 숫자는 **아직 선택·완성된 HAC 선체 설계에서 계산된 결과가 아님**.
- 형식/장갑/모듈에 따라 실제 비용과 가속·선회·전술 장갑면이 달라지도록 하는 것이 목표지만, 비용·기동의 구체적 수학 모델은 [미정].

## 8. 구현할 때의 보존·회귀 판정 예시 — 아직 테스트 수행 전

- 같은 함급에 서로 다른 선체 형식 두 개를 등록할 수 있고, 각자 고유 외형·장갑 구역 상한을 유지한다.
- 각 형식의 구역별 상한 초과 입력은 거부되며, 상한까지 자동 장착/충전하는 오류가 없다.
- 같은 선체라도 장갑 재질·두께·모듈 배치를 바꾸면 후속 설계 검증 단계에서 질량/소요자원과 전투 특성이 실제 상태에 따라 변한다.
- 자세를 회전시켰을 때 실제 **노출 표면·투영면적·장갑 입사각·외부 모듈 피격 가능성**이 따라 변한다.
- 동일한 입사각 효과를 'LOS 두께'와 별도의 '도탄 +20%'로 중복 계산하지 않는다.
- 관측 가능성과 명중 확률, 명중 위치, 피격 후 관통 및 국소 피해를 서로 구분한다.
- 같은 공격·조건·고정 시드에서 사건 순서/프레임 분할을 달리해도 의도치 않은 난수 결과 변화가 없어야 한다.
- 함급 역할 강제, 무제한 장갑 추가, 연구 완료 즉시 기존 함선 자동 개조, 원격 소재 순간 사용은 금지한다.

이 항목들은 **향후 구현 지시서의 수용 기준 후보**다. 실제 테스트/게임 구현이 완료됐다고 보고하지 않는다.

## 9. 여전히 결정되지 않은 문제

1. 함급 분류의 정량 기준(전체 부피/길이/질량/형식 등), 각 함급에 존재하는 형식 목록과 실제 치수.
2. 선체 형식별 3D 원본 geometry·표면 세분화·장갑 구역 명명, 면별 최대 두께의 실제 값과 기술별 해금 규칙.
3. 모듈·포탑·엔진·센서의 실제 장착 위치, 공간/사격각 제약과 파괴 경로.
4. 장갑 재질·밀도·다층 구성·경사·LOS 유효두께·도탄/관통의 무기별 실제 공식.
5. 장갑/구조/모듈/연료 총질량, 실제 추진력·회전 관성·가속·열·전력·건조비의 결합 방식.
6. 고정밀 기하 연산과 확률 사건 판정의 경계 및 성능 목표.
7. 나포·완파/전투불능 임계값과 정비·개수·수리·손상된 형식의 복구 정책.
8. 2D 윤곽에 두께를 주는 아트 방향은 예전 제안/검토 사항이지 3D 선체 형식의 유일한 생성 방식으로 확정된 것이 아님.
