# 08. 이번 채팅의 논의 순서·변경사항 (2026-11-01~11-02)

> **형식:** 원문 대화 전체의 문자 그대로 인용/녹취록이 아니라, 이 채팅에서 접근 가능한 발언의 **주제별·시간순 요약**. 별도 인계서에 있던 역사적 Claude 제안과 이번 사용자의 명시적 정정을 구분함.

## 1. HAC 건조량과 SCU 물류 문제 발견

- 먼저 과거 인계서의 중기 중강습순양함 **HAC 약1,580,000C + 합금58,000U**라는 건조량 후보가 재확인됐음. 이는 실제 함선 디자인으로 계산된 확정 건조비가 아니라 과거 경제적 목표임.
- 합금1U=10톤, 장거리 운송에서 합금1U=4SCU, 32SCU 표준상자 제작에 합금0.450U를 사용하므로 **전량 장거리 포장**을 가정하면 7,250개 상자, 내용물232,000SCU, 상자 재료3,262.5U가 필요함.
- 용기 개봉 후 회수2,936.25U, 손실326.25U, 내용물+상자 합금 질량612,625톤. 하지만 이를 **완성 HAC 질량**이라고 부르면 안 된다는 점을 분명히 했음.
- 사용자 발언의 함의: 실제 운송·자재 비용이 국가적 중대 사업으로 느껴져야 함. 단, 지금 배송 엔진이 구현됐다는 뜻이 아님.

## 2. HAC 길이와 함급 명칭 보정

- 과거 Claude가 HAC 약230m를 대표 이미지를 써 왔지만 사용자는 **초기 HAC 길이 약280~300m 초반**을 더 자연스럽게 구상한다고 말함. **최종 CAD/전장 확정은 아님.**
- 초기 백업에는 함급 9단계만 있고 정확한 길이·질량 경계는 미정. Claude가 과거 제안한 겹치는 길이 범위 표는 공식 분류표가 아니라 잠정 참고안이었음.
- 사용자는 후속 대화에서 **Claude의 명칭 쪽이 더 맞다**고 명시적으로 선택: **마이크로/초소형/소형/중소형/중형/중대형/대형/초대형/타이탄**. 오래된 '초미소형/극소형/준중형/준대형' 표기보다 우선함.
- 9단계 분류 = 강제 임무/무장/순양함·전함 티어가 아님.

## 3. 선체 '형식'이 무엇인지 최신 결정

- 사용자는 함선 설계 기능에서 **장갑 두께와 모듈 배치에 따라 최종 질량/소모 자원이 달라져야 한다**고 확인. 따라서 지금까지의 HAC U/C는 설계 이후 다시 계산해야 하는 잠정치임.
- 이어 **같은 함급 안에서도 선체 형식이 존재**하고 형식에 따라 외형·최대 장갑 두께 등이 다르며, 형태에 따라 전투가 달라진다고 직접 정정.
- 예시로 **LOS에 따른 경사·도탄**, 실제 표면 방향과 피격 위치를 제시. 선체가 고정 보너스가 아니라 실제 기하 데이터를 제공해야 함.
- 이 발언이 이후 함선 설계 기획에서 가장 최근의 우선 의사결정. 실제 충돌/장갑 관통 공식까지 정해진 건 아님.

## 4. 사용자 제공 두 개의 함선 원본 읽기

1. `11_함선_선체_설계_생산_개수.md`: 9개 규모 분류, 역할 자유설계, 장갑/선회/전력/장거리 드라이브, 지역별 손상, 생산·수리·개수 및 초기 함선 구상.
2. `SPACE_Project_함선설계_전투_상세인계서_2026-11-01.md`: HAC/타이탄 등 과거 잠정 비용, 전략 전투 AI, 3D 관성, 센서/FCS/전자전, 확률 기반 명중 후 실제 기하 관통, 다층 미사일 방어, 나포 및 경제 연동.

사용자에게 최신 명칭 선호를 확인했고, 각 문서의 **구현/잠정/제안/미정**이 섞이지 않도록 읽어 반영했음.

## 6. '광석4SCU는 그냥 적용하면 된다' 정정과 ECON-SIM-4 범위

- 사용자는 광석도 합금과 같이 **4SCU/U로 적용**하면 된다고 지적. 문제는 계수 자체가 아니라 로트를 잃지 않는 상태 어댑터라는 점을 바로잡음.
- 사용자는 ECON-SIM-4가 무엇인지 정확하게 파악했는지 질문. 핵심은 **포장 C만 정하는 소규모 조정이 아니라**, R3의 **종합 합격0**, 수소500kg/U·새 양론·수전해 전력, 포장/냉각 C·전력, 정부/민간/식민지/전시/복구까지 재검증하는 것.
- 특히 수소 **0.4C/U와 1.2C/U는 비교 후보**, 기존 3차 '물9U→H1U+산소8U'를 최신 물리 보존식으로 사용할 수 없다는 점이 기록됨.

## 7. SCU-2 FOLLOW-UP-1 지시서 작성 → PR #13 검토

- 사용자가 먼저 보완 패치 지시서 작성 요청. 범위를 **시계 버그 재현·수정 + 광석 품질 로트 현지 봉인/개봉 + 전액/원자성/저장/산업 회귀**로 정하고, 실제 배송·ECON4·발전소는 제외.
- 사용자가 작업 완료를 통보했고 GitHub [PR #13](https://github.com/0-FLANDRE-0/SPACE_Project/pull/13)을 확인.
- **수정 전** 500일 유휴+8SCU/h+32SCU 예약→1시간 후32SCU 완료. **수정 후** 1시간 후8SCU/진행 중, 4시간째 완료.
- 원광 low/medium/high의 출처·난도 로트를 현지 단일 로트로 봉인/개봉, 포장재0.450U/90% 회수, 봉인 중 제련 소비 차단, 엄격한 v4/book v3 저장 연동.
- **제출 로그** 78개 모듈 검사, **404/404 PASS**, 브라우저7개 PASS. 이번 대화에서는 코드/로그를 별도로 검토하고 **후속 작업으로 넘어갈 수 있을 정도로 요구를 충족**했다고 판단했으나 직접 전체 테스트를 새로 실행한 것은 아님.

## 8. 다음 개발 순서 논의

- 사용자는 **실제 물류를 잠시 미룰지**, 초기 식민지 **소형 발전모듈이 필요한지**, 광업·제련 전력량 탐색은 했는지 질문함.
- 경제3차 원본을 조회해 채굴0.07/0.11MWh/t·전처리0.03/0.04MWh/t·금속구성별 합금2.025/3.575/5.9MWh/t 등은 이미 탐색됐음을 확인. 게임 본체에는 아직 미연결.
- R3 달·화성 수요0.8GW/0.2GW(4kW/인 가정)와 대형5/2.5/1.5GW 모듈 과잉 문제를 확인. 소형 핵분열·태양광 후보 설계를 우선 제안했으나 **50/100/250MW 등의 수치는 미승인 예시**.
- 권장 순서 **소형 식민지 전력 후보 → ECON-SIM-4 → 사용자 승인된 전력·경제/포장비 채택 → 실게임 전력·산업 연동 → 실제 물류 → 함선·전투**. 이는 개발자의 권장 순서이고 사용자 확정 전체 일정은 아님.
