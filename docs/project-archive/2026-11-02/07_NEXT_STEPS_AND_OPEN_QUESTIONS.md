## P1. 초기 식민지용 소형 발전모듈 [우선 설계/수치 후보]

**이유:** R3 기존 발전 정격 5GW/2.5GW/태양광1.5GW 피크는 달0.8GW/화성0.2GW의 초기 평균 수요에 비해 과대할 수 있고, 콜드스타트·초기 재료/장기 유지보수의 부담이 큼.

- 기존 대형 발전소 정격/원래 핵융합 정상2.5U·기동 계약은 **몰래 변경 금지**.
- 소형 **핵분열/태양광 우선 후보**의 출력, C·합금·설비 기반 공유, 공기, 수명/교체, 가동률, 태양광 야간/축전, 핵연료/시동, 전력 저하, 폐열·유지보수를 산출할 설계표 마련.
- **50/100/250MW**는 대화 중 제안된 탐색용 크기 예이지 확정값 아님. 소형 핵융합 포함 여부도 이후 선택.
- 달/화성 최소 생명유지 우선 수요와 산업 추가 전력, 유한 재료를 동시 고려. '정격만 줄이면 자재 비용도 자동 감소' 같은 임의 비례식은 금지.

**제안 산출물:** 대형/소형 모듈 비교안, 근거와 비용 범위, 월/20년 민감도 입력, 미정/사용자 승인 필요 목록. **이 단계에서 실제 게임 발전 UI 구현을 필수로 삼지 않음.**

## P2. ECON-SIM-4 [재보정·오프라인 검증]

**목적:** 새 SCU·수소 kg/U·실물 포장 비용·소형 전원 후보를 포함했을 때 경제가 평시뿐 아니라 전시·식민지·유상 복구 경로에서 모순 없이 동작하는지 검증.

**검증이 반드시 포함할 것:**

1. U/C/SCU/Q 분리와 물량/질량/용적·C·전력의 보존, 물/수소/산소의 kg 양론.
2. 광업 부산물과 수전해 수소의 실물 출처, 전력 소비, 액화·보관·냉각·포장/개봉 소재 손실 및 비용의 **중복 청구 방지**.
3. 7종 컨테이너의 전체 비용 후보(자재 묶임/90% 회수/직접 C·전력/취급비), 실제 공간과 SCU 용량/운임 가정 분리.
4. R3의 기존 채굴·전처리·금속 제조 전력 후보와 소형 발전·대형 발전·축전·유지보수의 기술적/재정적 효과 대조.
5. 정부·민간·가계 회계와 국고/재량예산/기업 수익성, 물가/CPI·합금/수소 시장, 내부 거래와 통화발행 구분.
6. 평시 E0~E2 / 충격 E3~E8와 전체 16경로×5시드 최종 교차 검증(비교 기본), 수소 단절·정부 재고 징발·식민지 가뭄/밤·기동 실패·유상 복구.
7. 3차와의 동일 기준 비교, 조건부/제안 안정성 기준 별도 표시, 실패 원인/신뢰성/민감도/재현성/성능 보고.

**결과가0개 합격이면 0으로 기록.** 통과 목표 때문에 미정 변수를 무상0으로 바꾸거나 신규 전력/합금/수소를 무한히 만들지 않음. 사용자 승인 전 후보를 실제 게임 `industry-policy.js` 등의 공식값으로 적용 금지.

**선행 불필요:** 실제 화물선·배차·항로 AI의 전체 구현. 4차에서는 보급량·외형 SCU·위치별 U 소유권·비용과 시차를 **별도 모델 가정**으로 시험 가능.

## P3. 검증 뒤 실제 행성 전력·경제 본체 연동

- 정부/민간 발전설비의 기반/모듈 건설·가동/정지·고장·전력 구입/판매·실물 유지보수와 행성 통합 계통 만들기.
- 게임의 `powerDemandMW`, `monthlyOperatingCostC`, `laborDemandPersons` 같은 현재 `null` 필드와 실제 산업 생산/감산을 연결.
- 정전이 나면 생명유지·산업·수전해·우선 공급 정책을 반영, 전력/에너지 저장과 실제 공급 부족을 분리.
- 실험용 비용·재료·기술값은 승인된 것만 입력하고 지구 기존 산업 부하 **이중 계상 금지**.
- 사용자 승인된 저장 스키마/버전 이관을 추가하면서 새로고침 개발 초기화/수동 백업 정책은 보존.

**완료 기준:** 게임 내 발전 시설과 실제 광업/제련의 전력 수지가 같은 상태계에 연결, 돈·자원·에너지·시간이 보존되며 전력 부족 시 생산 감소가 실재함. ECON 오프라인 결과를 그대로 실게임 성공이라고 부르지 않음.

## P4. 실제 지역/행성/성간 물류 [후속]

- 출발 재고 차감 → shipment 인계/운송중 소유·점유 → 정산 도착 → 목적지 실제 재고 지급. 두 천체 재고가 순간 공유되지 않게.
- 동일 섹터/인접 연결망/2링 이상/행성 간 포장 면제 규칙과 **최종 배송 계약** 적용. 인접 다중 홉으로 무상화 금지.
- SCU 외형, 실제 자원·포장 질량, 수송 수단 용량, 취급 가능한 최대 컨테이너 크기, 경로·시간·운임·연료/위험물 및 합법 수소 수취 시설.
- PR #13 현지 전용 원광 로트의 **원격 인도**는 새로운 출발·inTransit·도착 어댑터/소유권 검증이 필요. 기존 차단을 그냥 지워서 구현했다고 말하지 않음.
- 처음부터 개별 빈 상자·수천 트럭·각 화물의 상세 3D 객체를 강요하지 말고 집계 배송·정확한 물량 장부를 우선.

## P5. 연구 → 함선 설계·조선·항행·전투 [장기]

- 연구 19분야 초안/상한·이론/심화/실현, 부품·규격 해금과 실제 C/U/시간/시설 요구 연동.
- 사용자가 선택한 9함급 이름, **같은 함급 안의 고정 선체 형식 여러 개**, 면별 최대 장갑 두께·형상/LOS 효과, 실제 장갑·모듈 설계로 질량/건조비 산출.
- **함선 설계기의 선행 계약:** [05A 상세](05A_HULL_FORMS_ARMOR_LOS_DETAIL.md)대로 함급→형식→개별 설계를 분리하고, 형식별 고정 3D 기하/면별 장갑 상한 및 국소 장갑·모듈 배치의 데이터/검증 모델부터 설계한다. 시선에 보이는 표면과 경사 장갑의 관통경로를 구별하고, 비가시 부위 피격·상한 초과 장갑·고정 도탄 보너스 등의 경계 테스트를 준비한다. **구체 공식·두께/형식 수치·작업 시점은 미정**.
- 소수 귀중한 함선의 조선소 공정/보급/정비/개수와 3D 관성 이동, AI 보조, 상태 기반 확률 탐지·피격 및 실제 국소 관통/모듈 손상.
- 완전 격침/전투불능/나포·회수의 장기 경제 효과까지 확장.

**순서 유연성:** 연구 기초 데이터·선체 형식 기하·배송 계약·시뮬레이터는 일부 병렬화 가능. 단 공용 단위와 실물/현금 보존 계약을 우회해서는 안 됨.
